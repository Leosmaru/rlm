## Статус

Обсуждение идёт; **сборка промта из слотов заработала** (2026-08-24, см. `changelog.md` / `architecture.md`): мультиплей-комплитер теперь кормит `API`, `assembleMessages` разбирает слоты (активный персонаж = полная карточка + фантомы остальных; активен рассказчик = все карточки полные; Душа/Состояние активного in-chat, Мир — только у рассказчика). Раньше собраны: нода `Мультиплей-комплитер`, пересобранный пресет. **Группа ИГРАБЕЛЬНА + доводка** (2026-08-24): вход в игру (фантомы→сцена), ранжиратор (судья/механика со счётчиками), роли-ограничители, `{{char}}`=активный, и **двухканальная память D** — у каждого персонажа своя изолированная память (namespace по активному слоту), у рассказчика общий мир. Плюс: **своя `Душа` на каждый слот** (доки урезаны по роли, вьюер по клику на ник) и **отдельная нода `Рассказчик`** с секциями Промт/Стиль/Тон/Мир (пресеты+RU/EN, дефолт SoW). Пресет — **v12** (разработка группы на паузе — базовый цикл готов). Ключевое финала (2026-08-25): **отдельная нода `Групповой чат`** (`node-groupchat`) — обычный `Чат` НЕ группа никогда (изоляция сингла); **кнопка «⏭ След. ход»** (форс хода ИИ); **фантом = нода `Систем промт`** («Фантом · Имя») на холсте, вписывается генерацией, нейтральный (не про игрока); **аватары по говорящему**; **имя перед репликой в истории** (модель не путает, кто есть кто); **пустой ответ не засоряет историю**; **«Новый чат» в группе** бережёт фантомы+рассказчика (чистит историю/Души/чат-лорбук); **переключатель «завязка как есть / дописать»** + перевод завязки RU→EN; **кнопка «🌐 RU» в Консоли** (перевод запроса Яндексом). **Роли (решение пользователя):** плашка «Основной промт» = иммерсивный RP-систем-промт (НЕ «ассистент»); **Рассказчик — роль** (двигать сюжет/дополнять обстановку, ходит реже), его секции только на его ход; **персонажи играют от 3-го лица как в сингле** (зажим снят). Косметика: нарратор — прозой без имени/аватара, активный — золотым. Осталось (открытые темы): Критик/Состояние/NPC/температура/нода «Цель». Полная сводка — в «Чек-поинт → СВОДКА СОСТОЯНИЯ». Референсы: **ST** (`group-chats.js`), **SoW / Soul Stage** (`soul_stage_engine.py`).

**Курс (решение пользователя):** оркестровку берём **по образцу SoW Soul Stage** (судья-роутер + нарратор + цепочка ответов), но с нашими фиксами (см. «грабли»). Двухканальная память (пункт D) **реализована** (2026-08-24): личная память по персонажам изолирована namespace по активному слоту. По ходу могут всплывать ещё «моменты», где отходим от SoW.

## Чек-поинт реализации (ПРОДОЛЖАТЬ ОТСЮДА — 2026-08-24)

**СВОДКА СОСТОЯНИЯ (обновл. 2026-08-25, пресет v12, всё проверено вживую на 8100). Базовый цикл группы ГОТОВ — разработка на паузе.** Что уже стоит:
1. **Мультиплей-комплитер** + **слоты** (тип плашки, коннекторы внутри) + **in-chat копии** + авто-разводка + **сборка промта из слотов** (`assembleMessages`: активный персонаж=полная карточка, остальные=Фантом, рассказчик=свои секции; кормит API через `completerForApi`).
2. **Пресет «Групповой чат»** — версионированный пере-посев (`GROUP_PRESET_V`, сейчас **v12**); отдельная нода `Групповой чат` (`node-groupchat`); карточки разведены в слоты; плашка «Основной промт» = RP-систем-промт (`GROUP_MAIN_PROMPT`).
3. **Вход в игру** (`#rlm-entry`): экран старта перед чатом → этапы **фантомы по персонажу** (`genPhantom`) → **стартовая сцена SoW** (`genOpeningScene`).
4. **Ранжиратор** (движок хода, 🔧 Инструменты→«Ранжиратор»): судья (LLM)/механика, счётчики ходов, N-предел, RU/EN; цикл `groupPlay` в `chatSend`.
5. **Роли**: `{{char}}`/аватар=активный слот; **персонаж играет 3-м лицом как в сингле** (зажим снят — можно описывать свои действия и сцену; нельзя только за игрока/полные ходы за других); **Рассказчик — роль** (двигать сюжет/обстановку, реже); имя говорящего над репликой + в истории для модели (`chatTurns`).
6. **Двухканальная память (D)**: **СВОЯ `Душа` на каждый слот**, папка `chatId:slotId` (`memChatId`), доки урезаны по роли (перс=Дневник+Психика, рассказчик=Статус+Мир+Темы), подхват имени слота; **вьюер**: клик по нику партии / 🔧 → Душа этого слота. Изоляция лорбуков проверена.
7. **Нода `Рассказчик`** (тип `narrator`): карточка нарратора с секциями **Промт/Стиль/Тон/Мир** (пресеты стиля/тона+ручной+RU/EN, дефолт-промт SoW), 4 выхода → слот-рассказчик.
8. **Фантом = нода на холсте** (пресет v9): у каждого персонажа своя нода `Систем промт` («Фантом · Имя», `slotPhantom`/`phantomSlot`/`phantomSyncNames`) → поле «phantom» слота. Пустая; текст **вписывается генерацией на старте** (`genPhantom`→`slotPhantom`), дальше **редактируется руками**. При подключении нода берёт имя персонажа (так система находит нужную ноду). `slotPhantomText`: текст ноды в приоритете, `_phantoms` — фолбэк (старые чаты).
9. **Косметика сообщений группы** (`mesHtml` в `chat.html`): рассказчик (`_narr`) — **прозой, без имени и аватара, без курсива** (`.mes-narr`, во всю ширину); активный говорящий («на передаче» по партии) — **имя+аватар золотым** (`.mes-active-speaker`), остальные нейтральны.
10. **Кнопка «⏭ След. ход»** (`group-next`→`groupNextTurn`): форсит один ход ИИ без реплики игрока (судья вернул «игрок» → фолбэк на механику); видна в группе с начатой игрой. Решает жалобу «нет реакции / как инициировать».
11. **Фантом — НЕЙТРАЛЬНЫЙ, не про игрока** (`genPhantom`; у каждого свой фантом): впечатление от третьего лица, одинаковое для любого зрителя, без упоминания `{{user}}`/«ты» и без взаимодействия с кем-то конкретным.
12. **«Новый чат» в группе бережёт фантомы/рассказчика** (`clearThisChat`): чистит только историю + Души + чат-лорбук; `_groupStarted`/`_phantoms` целы, игра остаётся начатой.
13. **Макросы `{{slot_1}}`…`{{slot_N}}`** = имя персонажа слота (1-индекс; дополняет `{{char}}`=активный); **номер слота виден в UI всегда** (бейдж «#N»).
14. **Отдельная нода `Групповой чат`** (`node-groupchat`) — обычный `Чат` НЕ группа никогда (изоляция сингла). Аватары в группе — у каждой реплики свой (по говорящему). Кнопка **«🌐 RU»** в Консоли (перевод запроса через Яндекс). Перевод завязки RU→EN на экране старта.
15. **Базовый систем-промт группы = Рассказчик (v11).** Убрана плашка «Основной промт» у комплитера (тащила «Ты — ассистент» → персонажи вылетали из роли). Промт Рассказчика идёт ролью `system` всегда; `NARRATOR_DEFAULT_PROMPT` = общий ролеплей-каркас + правила наррации. Также: пустой ответ модели не засоряет историю; имя говорящего перед репликой в истории (план C реально в промте); переключатель «завязка как есть / дописать»; «Новый чат» в группе бережёт фантомы/рассказчика.
14. **ОТДЕЛЬНАЯ НОДА `Групповой чат`** (тип `groupchat`, `node-chat`+`node-groupchat`, `buildGroupChatNode`) = копия `Чата` с групп-накрутками; сингл-`Чат` не тронут. Пресет **v10** сеет её. (Решение пользователя: «сделай копию, не ломая сингл-чат».)
15. **ФИКС пустых ответов:** групповой ограничитель роли = роль `user` (не system) — иначе массив кончается на assistant+system → модель пустая. Пустой ответ в группе убираем (не «(пустой ответ)»), ход пропускаем.
16. **ФИКС «кто есть кто»:** `chatTurns` в группе ставит **имя перед репликой** («Кайра: …», план C) — модель различает говорящих/понимает сцену.
17. **Завязка КАК ЕСТЬ** (переключатель в окне старта, дефолт «дописать»): выкл → введённая завязка = первое сообщение без переписывания рассказчиком (точность).
18. **АВТО-ходы** («▶ Авто/⏸ Пауза»): `groupAutoPlay` крутит ходы, пока ранжиратор не отдаст ход игроку / пауза (можно влезть самому).

**Следующее (по приоритету):** **открытые темы** (Критик в группе, Состояние в группе, NPC/визитёры, температура наррации, нода «Цель») → мелочи (вижн-синк slot-портов, N в UI ноды чата). Детали — в «НЕ СДЕЛАНО» ниже.

**НЕ СДЕЛАНО (бэклог, порядок):**
1. ~~**Стиль сообщений группы** (косметика): нарратор прозой без «имени», подсветка активного говорящего.~~ **СДЕЛАНО** (`mesHtml` в `chat.html`): нарратор — проза без имени/аватара (без курсива, `.mes-narr`); активный говорящий — золотым (`.mes-active-speaker`). Выбор пользователя: без курсива; подсветка только у активного (не цвет-на-каждого).
2. **Мелочи ранжиратора/памяти:** предел N вынести в UI ноды чата (сейчас в панели ранжиратора); per-slot batch-счётчик записи памяти (сейчас общий на Душе).
3. **NPC / визитёры (на потом, с пользователем):** связать групповой ход с генератором NPC Режиссёра — спавн/деспавн лиц в сцене (реф SoW `WorldState`/`NPCCard`, тип события `visitor`, макс 2 активных). **Температура наррации — НЕ решено (обсудить):** в SoW тон крутит temperature (мрачное 0.6 / лёгкое 0.85), у нас **тон температуру НЕ трогает** (решение пользователя); где жить управлению температурой — у рассказчика или у ранжиратора — решим позже.
   - **Критик в группе — НЕ решено (тема в доки):** как Критик проверяет реплику в группе (чей контекст, Душа рассказчика как ground-truth, метагейм судье можно — см. черновик в разделе «Критик в группе» ниже), финальная механика не выбрана.
   - **Состояние (переменные) в группе — НЕ решено (тема в доки):** у каждого перса свой `Состояние`-узел или общий? как свапается коробкой (личный канал), где живёт «состояние мира» (у рассказчика). Пока не выбрано.
   - **Нода «Цель» — ИДЕЯ на потом (НЕ решено):** отдельная нода `Цель` (цель сцены/персонажа/игры — что двигает сюжет). Что именно она делает и как ложится на группу/Режиссёра/ранжиратор — обсудим позже. Пока просто заметка, чтобы не потерять.
4. Мелочь: вижн-синк проводов слота (`syncVisionToMaster` для slot-портов несовершенен — реатач по `.pm-item[data-id] .port.in` берёт ПЕРВЫЙ порт слота, поля теряются).
5. **(на потом)** Новый док `Души` **«Мнение об остальных»** у каждого перса (заводится в пресете): личное мнение персонажа о других участниках, **ДОПОЛНЯЕТ фантом**. То есть в блок «остальные» активного идёт **фантом** (публичное впечатление от рассказчика) **+ его мнение** (личное, эволюционирует по ходу игры). Помимо фантома персонаж сам формирует и дополняет мнение.

## Концепция (главное)

Групповой чат RLM разваливается на **два слоя** — ровно как принято у нас (база ST + опциональные слои):

1. **База (как ST):** несколько нод `Персонаж` → один `Чат` + выбор говорящего. Ничего сверху не подключил → обычный общий чат нескольких персонажей.
2. **Слой «Сцена/Режиссёр» (амбиция SoW Soul Stage):** гейм-мастер, рассказчик, NPC, общий стейт мира. Дорого, опционально, **на будущее** — сверху на базу.

Курс выбран в сторону **слоя** (SoW-оркестровка) как основы, но механический выбор говорящего остаётся дешёвым вторым режимом — чистый общий чат без судьи по-прежнему возможен.

**Ключевой принцип разделения (важно, чтобы не сломать архитектуру):**
- `Режиссёр` — это **лорбук** (инжектор текста «События» в промт). Он **НЕ рулит очередью** говорящих. Может лишь *косвенно* подтолкнуть — если событие упомянуло имя, механика подхватит этого персонажа.
- **Выбор говорящего — отдельный механизм** (нода `Ранжирование`, см. A). Это управление ходом, а не данные; вешать его на `Режиссёр` нельзя (правило «провод ≠ команда»).

## Коробка передач (ядро архитектуры) · обсуждаем

Идея пользователя: не строить отдельную «групповую» машинерию, а **крутить N одиночных игр**. У каждой карточки — её **полный сингл-плеер как сейчас**: свои состояния/переменные, инвентарь, своя `Душа`, свой лорбук. Группа = **коробка передач** поверх них.

- В любой момент **один** персонаж «на передаче» — подключён целиком: весь его соло-риг живой (карточка + состояния + инвентарь + `Душа`/RAG + лорбук).
- Остальные запакованы в **«фантом»** — сжатое представление, **богаче визитки** (не 2–3 строки, а «достаточно, чтобы активный знал, с кем имеет дело, и видел его»: аватар + описание).
- Меняется очередь → **переподключение**: риг отцепляется от прошлого активного, цепляется к новому; прошлый пакуется в фантом.

**Почему сильно:**
- Переиспользуем **весь существующий соло-конвейер** — отдельную групповую память/состояния/лорбук строить не нужно. Группа = слой оркестровки над N соло-играми.
- **Чище, чем ST и SoW:** ST свапает только карточку (не риг целиком), у SoW память течёт между сценами. Здесь каждая карта — герметичная соло-игра. Такого в референсах нет.
- **Предрешает D:** личная память/состояния/лорбук = у каждого свои, изолированы. Открытым остаётся только по-настоящему **общий факт мира** — ему нужен тонкий общий слой (нарратор/транскрипт).

**Честные оговорки (не блокеры):**
- **Цена переподключения:** каждый ход свап всего рига (лорбук, RAG) = как один соло-ход. С судьёй+нарратором терпимо, но за скоростью следим.
- **Общий мир:** факты, которыми владеют все (дверь открыта, предмет на столе), ничьи → нужен тонкий общий слой (хвост D).
- **«Фантом» — параметр:** богаче = больше токенов × размер партии.

**Вердикт:** реально и красиво, не «пиздец». Становится **ядром** плана; «визитка» из B — частный случай «фантома».

## Разбор по пунктам

### A. Кто говорит — очередь на ход · РЕШЕНО (направление)

Отдельная **нода `Ранжирование`** (рядом с `Чатом`, не инжектор). Строит очередь говорящих на ход. Два режима:

- **Механика** (без нейросети, дёшево): правила + кубик. Берём из ST — режимы «по списку / естественный / пул»; у естественного: бан на повтор последнего, **упоминание имени → в очередь** (язык-независимо, просто совпадение слова-имени), затем кубик по полю **«разговорчивость» 0…1** на каждой ноде `Персонаж`. Очередь считается сразу, вперёд.
- **Судья** (нейросеть, дорого): отдельный вызов LLM «кто отвечает следующим — имя?». Пересчёт после каждой реплики. Как у SoW, но без их костылей.

**Дефолт — судья** (LLM-роутер, по образцу SoW): группа сразу «живая». Механика остаётся вторым режимом ноды (дешёвая альтернатива, кто хочет без лишних вызовов).

**Остановка цепочки (как SoW):** после каждой реплики роутер решает, кто следующий; ход возвращается игроку, когда роутер вернул «игрок» **или** достигнут предел ответов за ход. У SoW предел жёстко = 3 — у нас это **параметр** (опция внутри ноды группового чата): максимум 3, **сейчас дефолт = 1** реплика бота за ход.

**РАНЖИРАТОР = переключатель коробки передач (решено, концепт).** Метафора замкнулась: `Чат` = двигатель (запускает ход), **слоты = передачи** (данные: чья карточка), **ранжиратор = рука, что дёргает рычаг** (решает, какую передачу воткнуть следующей). Живёт **В ЧАТЕ** (в двигателе), не в коробке — ровно принцип «управление в чате, ноды = данные».

**Где живёт — Вариант B (гибрид), выбран:** ранжиратор — механизм В ЧАТЕ, который после каждой реплики **решает** «кто следующий» + анти-луп (>N подряд) + «пора ли рассказчику»; **лёгкий промт для решения** (фантомы + короткая история = дёшево) собирает **комплитер в «ранжирование»-режиме**. Коробка передач переключается только на реальных говорящих (не мигает).
- *Отвергнут Вариант A* (ранжиратор = «лёгкий режим» рассказчика внутри коробки передач): переиспользовал бы машинерию, но мигал бы коробкой каждый ход и мешал управление со слоем данных.

**Бутстрап (закрыт):** первый переход хода — **КОНСТАНТА**: игрок написал → ранжиратор запускается сам (не нужно «кто его позовёт»). Дальше: ранжиратор выбирает говорящего → передача → ответ → ранжиратор снова / ход игроку. Рассказчик на своей полной передаче — только когда ранжиратор так решил (тогда все карточки полные).

**Ранжиратор — детали (решено):**
- **Доступен в вижне** (опционально, через меню 🔧 «Инструменты», как другие ноды-инструменты).
- **Промт «как определить очередь»** — открытый (редактируемый), с переводом **RU/EN** (как поля других нод).
- **Счётчики ходов:** у каждого персонажа — до **3 поинтов хода** до прихода рассказчика. Рассказчик (на 3-м или раньше) → поинты **сбрасываются на указанное число** (настройка). Ранжиратор **видит эти числа** и по ним пейсит/анти-лупит (когда звать рассказчика).

Это **движок хода** — крупный функциональный слой, отдельно от уже собранных слотов. Пока концепт; реализация — в бэклоге группы.

### B. Чья карточка попадает в промт говорящего · РЕШЕНО

Когда отвечает персонаж X — что он «читает»:
- **Swap** — только свою карточку; про других знает лишь имена + их реплики в чате.
- **Join** — склейка карточек всех. **Отвергнут**: даёт мета-знание (X мгновенно знает секреты всех, будто прочитал их дневники) — ломает отыгрыш.

**Выбрана «середина»:** Swap + **визитка**.
- Что видит X про других — **«фантом»**: сжатое публичное впечатление (аватар + несколько строк). **Генерит его сам Рассказчик на старте игры** (читает карточку + лорбук каждого, один запрос на персонажа) — см. «Старт игры». Инструктирован писать **только публичное** впечатление; секреты карточки/лорбука в фантом не тащит (защита от утечки переехала из «пишет автор» в инструкцию рассказчику).
- Когда отвечает X: его **полная** карточка (Swap) + блок **фантомов остальных**.
- Полные карточки других остаются скрыты → секреты недоступны.
- **Что в фантоме:** внешность + роль + ощущения (впечатление). **Манера речи — НЕ нужна.**
- **Фантом живёт в ноде на холсте** (СДЕЛАНО, пресет v9): у каждого персонажа своя нода `Систем промт` («Фантом · Имя») → поле «phantom» слота. Генерация на старте **вписывает текст в эту ноду**, дальше **правишь сам** (живой, не статичный). Авто-обновление рассказчиком по ходу — позже.
- По цене — почти как Swap.

*(В модели «коробка передач» визитка = частный случай **«фантома»** — см. раздел «Коробка передач».)*

### C. Разметка реплик в истории · РЕШЕНО

Как модель понимает, где чья реплика в общем чате:
1. **Имя перед каждой репликой** в истории (`Эмилия: …`, `Пак: …`) — иначе каша.
2. **Подсказка «чья очередь» в самом конце** (`[Пиши дальше только как Рем.]`) — иначе модель отвечает за всех.

Берём чистый вариант ST (аккуратнее текстовых костылей SoW). *(Технический нюанс ролей assistant/user для chat-completion — решим при реализации.)*

### D. Память в группе · РЕШАЕМ (двухканальная)

Раньше было отложено; сейчас складывается через «коробку передач». Особый **групповой комплитер** двигает риг и держит **два канала памяти:**

- **Личный** (свапается коробкой, у каждого свой, изолирован): **Психика + Дневник + Статус/Состояния** — состояния крепятся за перса. Не сваливается в общий котёл, чтобы персонажи не «файнили» чужими фактами. Живёт только у активного.
- **Общий** (постоянный): Душа **Рассказчика** — **без** Психики/Дневника/Статуса, зато **Мир + остальное**. Рассказчик её сам и ведёт → он **хранитель общего мира**.

Так закрывается и «общий факт мира» (дверь открыта, предмет на столе) — он живёт в Душе рассказчика. SoW-баг утечки памяти в соло **не повторяем** (у нас каналы изолированы).

**Решено (метагейм):** общий канал (Душа рассказчика) в промт **персонажей НЕ подмешивается** — иначе персонаж получил бы метагейм (всеведение мира и чужих секретов). Персонаж знает мир только через **историю чата** (публичные строки рассказчика + видимые действия других — то, что он и так видел) + свой личный канал + фантомы. Душа рассказчика идёт в промт **только когда говорит сам рассказчик**; там может лежать даже скрытое (тайны, «что за дверью») — безопасно, наружу уходит лишь его публичная речь в истории, не его записная книжка. Ключ: **публичная строка рассказчика ≠ его Душа.**

Осталось по мелочи: куда «Темы» (личное/общее).

### E. Нарратор · РЕШЕНО

Нарратор нужен, потому что в группе каждый персонаж иначе тянет **свой** нарратив (описывает мир по-своему, они противоречат) → каша из «камер». Решение — один голос на сцену.

Механизм — **чистый промт, без спец-сущности** (роль и персонаж под капотом одно и то же: карточка+промт в модель):
- Нарратор = **ПРОМТ, а не карточка** (сверено с SoW `GM_EXECUTOR_SYSTEM` — там нарратор именно системный промт). **СДЕЛАНО (2026-08-24, пресет v8):** рассказчик = **отдельная нода `Рассказчик`** (тип `narrator`, `buildNarratorNode`) — карточка нарратора с **4 секциями**, у каждой свой выход → в слот-рассказчик (4 входа: `system`/`nstyle`/`ntone`/`nworld`): **Промт** (дефолт `NARRATOR_DEFAULT_PROMPT` в духе SoW `GM_EXECUTOR`) · **Стиль письма** (пресеты `NARR_STYLE_PRESETS` + ручной ввод) · **Тон** (7 пресетов SoW `NARR_TONE_PRESETS` + ручной) · **Описание мира**. На каждой секции RU/EN. `sourceText`→`narrSectionText` (обёртки STYLE/TONE/WORLD). У слота-рассказчика карточные поля/лорбук/разъём скрыты (CSS). Мир/лор ведут ещё глобальная плашка «World Info» + его Душа («Мир»+Статус). **Тон НЕ крутит температуру** (решение пользователя).
- В группе к каждому **персонажу** добавляется правило-ограничитель: «отвечай только за себя (речь + действия), мир и других персонажей не описывай — это делает Рассказчик».
- Ограничители подставляются **только в группе**. В соло-чате персонаж повествует сам, как раньше.

**Когда вступает (как SoW):** пишет в **начале хода** (задаёт сцену) + короткие **«мостики»** между репликами персонажей по решению роутера.

**Рассказчик = СУДЬЯ (роутер).** Он не только повествует — в режиме «судья» он **решает, кто отвечает следующим**. Для этого **коробка передач переключается на него** (его передача = точка «наррация + выбор следующего»). Когда рассказчик на передаче — **все слоты дают полные карточки** (не фантомы), **чтобы он имел доступ** ко всем (всевидящий: описать сцену + выбрать следующего). Поток: игрок → передача рассказчику (описал+выбрал) → передача выбранному персонажу (ответил) → снова рассказчик (мостик+выбор) / ход игроку. В режиме «механика» очередь решают правила — рассказчик только повествует. *(Реализация: слот-рассказчик СОБРАН — флажок «Рассказчик», без Фантома, память=Мир, значок ✎, берёт передачу; впереди — сборка промта «активен рассказчик → все карточки полные» и движок роутинга «выбрал → передача переключилась».)*

## Холст (узлы)

- **Новый пресет «Групповой чат».**
- **Особый групповой комплитер** — формат НЕ меняем (устраивает пользователя), но это **отдельный** комплитер, который **двигает риг** (коробка передач). Заливка плашки «Персонаж» меняется: она становится **живым слотом активного персонажа**, куда каждый ход подставляется текущий говорящий. Механизм подмены — уже принятый **«клон на общих данных»** (нода `Персонаж` не двигается, данные клонируются в слот на ход).
- **Память — два канала** (см. D): личный свапается коробкой (Психика/Дневник/Статус активного); общий = Душа `Рассказчика` (Мир + остальное) — идёт **только в промт рассказчика**, персонажам НЕ подмешивается (иначе метагейм); мир персонажи знают из истории чата.
- Заливка слота и плашки «остальные» — по говорящему:

| Кто отвечает | Слот активного | Плашка «остальные» |
|---|---|---|
| Персонаж | своя полная карточка (+ весь соло-риг) | фантомы (аватар + описание) |
| Нарратор | промт-рассказчик | **все карточки целиком** (ему можно — всевидящий) |

- **Нода `Групповой чат`** — отдельная, вариант `Чата` со всеми функциями, но сложнее. Разрабатываем и дорабатываем **постепенно**.

## Слоты — подключение персонажей (мультиплей-комплитер)

**Слот = ТИП ПЛАШКИ.** В комплитере тип плашки: **текст / маркер / слот** (слот — третий тип). Слот-плашка живёт **в списке плашек** комплитера (двигается / вкл-выкл, как другие), но особая — сворачиваемая пачка перса. Вместо общих плашек персонажа — **N слот-плашек** (по одной на перса).

**Почему плашка, а не панель:** у плашки есть **порты** — а слоту нужны **коннекторы ВНУТРИ** (по входу на каждое поле перса). Иначе некуда втыкать. Свёрнут → один разъём; раскрыт → отдельный вход у каждого поля.

**Панель «коробка передач» = только переключатель/дисплей.** Показывает партию и кто «на передаче», даёт переключать активный слот. Она **отражает** слот-плашки, **не хранит** их (источник истины — сами слот-плашки в списке).

**In-chat копия при создании слота.** Раз у слот-плашки есть **Душа** и **Состояние** (а они впрыскиваются in-chat на глубину), при создании слота их разъёмы заводятся **сразу в двух местах**: в самой слот-плашке и как **копия в in-chat-зоне** комплитера. При смене передачи in-chat-копии неактивных слотов **гаснут серым** (горит только активный).

**Внутри слота (пачка перса):** Описание · Характер · Сценарий · Примеры · Лорбук персонажа · Систем-промт · **Душа** · **Состояние** · **«Фантом»**. Плашка «Фантом» берёт **имя перса** при подключении → по имени нода `Чат` находит слот (аватарки партии, подсветка активного) и потом правит фантом.

**Свёрнутый слот = одна точка.** Воткнул в неё **Основное описание** ноды `Персонаж` → остальные её поля (характер/сценарий/примеры/лорбук/систем/душа/состояние) цепляются **автоматом** (система нашла ноду по одному проводу). Один перс = один провод.

**Переключение передач:**
- активный слот → **полная карточка** в промт;
- неактивные → в промт падает **только их «Фантом»**;
- горит только **активный** слот (по коробке передач), остальные — серым.

**Душа и Состояние — в ДВУХ местах сразу:** (1) внутри слота (владелец = перс) и (2) в **in-chat-зоне** комплитера (место впрыска на глубину, рядом с ответом). Один разъём, показан дважды; при смене передачи in-chat-копии неактивных слотов **гаснут серым**.

**Общие плашки (вне слотов, один раз):** Основной промт · World Info · Лорбук чата · Описание персоны · Инструкции после истории. **Режиссёр (События) — тоже отдельный и ВСЕГДА работает** (не свапается, не гаснет, независим от коробки передач — сцена-уровень). *(Уточнение: Душа и Состояние ПЕРЕЕХАЛИ из общих в слоты — они привязаны к персу.)*

**СОБРАНО (первый заход, 2026-08-24):** слот-плашка (`makeSlotItem` в `app/renderer.js`) — тип плашки с коннекторами внутри (свёрнут = разъём `slot:<id>`, раскрыт = вход у каждого поля `slot:<id>:<field>`, `portKey`/`findPort`), панель = переключатель (`mpRenderSwitcher`), активный = `data-active`, сериализация, `chatPartyData` + панель партии в чате. Проверено вживую. **Авто-разводка собрана** (`slotAutoWire`): воткнул «Основное описание» → 6 полей карточки цепляются сами + слот раскрывается + берёт имя перса. **In-chat копия** Души/Состояния — отдельными плашками (`makeSlotIcItem`). **Сборка промта из слотов СОБРАНА** (`assembleMessages`, 2026-08-24): активный персонаж=полная карточка, неактивные=только Фантом, рассказчик=все карточки полные; Душа/Состояние активного in-chat; mprompt кормит API (`completerForApi`). **ВПЕРЕДИ:** движок хода (ранжиратор) + пересбор сида пресета «Групповой чат».

## Старт игры / подготовка

**Чат не открывается**, пока не выполнено: (а) персонажи добавлены в **мультиплей-комплитер**, (б) **назначена первая сцена**. Порядок: сначала пишется первая сцена, потом — после её назначения — запускается подготовка.

1. Подключаешь карточки (`Персонаж`) в мультиплей-комплитер + пишешь/назначаешь **первую сцену** → жмёшь **«Начать игру»**.
2. **Фаза подготовки:** **Рассказчик изучает всех** — проходит по каждому персонажу, **читает его карточку + лорбук**, **один запрос LLM на персонажа**, и пишет для него **небольшой фантом** (внешность + роль + ощущения; инструктирован не тащить секреты).
3. Эти фантомы дальше **вмешиваются в комплитер** — в блок «остальные» активного персонажа.

Стоимость: N запросов на старте (по одному на перса), разово. Сгенерированный текст **вписывается в фантом-ноду** этого персонажа (`slotPhantom`) — она и есть источник фантома в промте (`slotPhantomText`).

**Первая сцена — как в SoW** (склоняемся): стартовая наррация рассказчика + первое сообщение + стартовые локация / время / фон / эмбиент. **Это опция внутри ноды группового чата** (как и предел N).

**Решено:** автор **правит сгенерированный фантом** — это обычная нода `Систем промт` на холсте («Фантом · Имя»), редактируется как любой текст.

## Критик в группе

`Критик` (система-проверяльщик, см. `plan-critic.md`) в группе проверяет ответ с групповым контекстом:

- **Всегда получает:** историю чата **+ Душу рассказчика** (общий мир, ground truth).
- **Плюс контекст хода:**
  - ход персонажа → его «передача» (полный риг активного + личный канал) + **фантомы** остальных (как их видел активный);
  - ход рассказчика → сам рассказчик (его контекст).

**Почему Душу рассказчика критику можно, а персонажу нельзя:** критик — не игрок, а **судья**. Метагейм ему не вредит, а нужен: зная реальное состояние мира, он ловит противоречия (персонаж сказал то, что миру противоречит). Актёр играет вслепую (без Души рассказчика), критик проверяет зряче. Асимметрия «играть vs судить».

## Что у SoW НЕ берём (грабли — проверено в исходниках)

- **Русский хардкод.** Перехват обращения по имени завязан на английские маркеры (`hey/hi/listen/wait/okay/so/well/now`) — на русском не срабатывает. У нас выбор по имени должен быть язык-независимым (совпадение слова-имени).
- **Мёртвый лорбук сцены** — поле есть, в промпт не инжектится. Не повторять.
- **Утечка памяти сцены** — у сцены нет своего `chat_id`, события пишутся в одиночную память персонажа; разные сцены делят память. Память должна быть привязана к сцене.
- **Только имена о других** — SoW не даёт даже публичного минимума; наша «визитка» это чинит.
- **Хрупкость:** хардкод «3 ответа подряд» → у нас **параметр**; анти-луп только текстом промпта; тихое «замолкание» при обрезанном JSON → нужен явный фолбэк; монки-патч конфигов; потеря NPC при перезагрузке.

*(Стоимость судьи-роутера — 3–4 вызова на ход — принята осознанно: дефолт = судья по решению пользователя, механика оставлена как дешёвая опция.)*
