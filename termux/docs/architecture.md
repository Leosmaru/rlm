# RLM — Архитектура (как есть сейчас)

> **Устав документа**
> - **Зачем:** описать текущее устройство RLM: из чего собран, где что лежит, как не сломать.
> - **Что сюда пишем:** актуальную структуру, компоненты, паттерны, «грабли».
> - **Чего НЕ пишем:** историю правок (это в `changelog.md`), обоснование решений (это в `decisions.md`).
> - **Правило ведения:** обновляется **только там, где реально изменилось**. Всегда отражает «как есть сейчас».

## Что реально построено сейчас

RLM = **Electron-фронтенд (узловой холст)** + **свой сервер на моторе SillyTavern** (стартовал 2026-08-07, раздел «Бэкенд RLM» ниже). Раньше бэкенда не было — теперь есть его первый кусок: звонок к LLM-провайдеру для ноды `API`.

**`app/`** — Electron-приложение, ванильный JS без сборки:
- `main.js` — окно + IPC (закрыть/перезапуск), `disable-http-cache` (грузить свежие файлы), **файловое хранилище** (`store:get`/`store:set` через `sendSync` → `userData/rlm-store.json` — теперь ТОЛЬКО для `rlm.tts.dtype`, PC-only; всё остальное живёт в серверной базе) и подъём сервера RLM. **Перезапуск приложения** (`app:restart` = `app.relaunch()`+`exit`) зовётся кнопкой «Перезапуск» с ПК через мост `window.rlm.restart`. **С телефона** моста нет, поэтому сервер поднимается с **IPC-каналом** (`spawn(..., { stdio: ['ignore','ignore','ignore','ipc'] })`): телефон бьёт в `POST /api/rlm/app/restart` (за whitelist, `server/src/endpoints/rlm-app.js`) → сервер `process.send({rlm:'relaunch'})` → `serverProc.on('message')` в `main.js` делает тот же `app.relaunch()`. Клиент (`app/renderer.js` `appRestart`) показывает экран ожидания `#rlm-reconnect`, пингует `/rlm/manifest.json` и перезагружает страницу, когда сервер снова ответил. **Мобильный режим:** IPC `win:mobile` (`BrowserWindow.fromWebContents` → `setContentSize` под размер телефона + `center()`; десктопные границы запоминаются в `desktopBounds` и возвращаются при выходе). **Значок окна/таскбара:** `BrowserWindow.icon` = `app/icon.ico` (Windows) / `icon.png` (512) + `app.setAppUserModelId('com.rlm.roleplaymachine')` — иначе Windows группирует окно под `electron.exe` и держит дефолтный значок Electron. Иконки собраны из логотипа-чипа `стиль/Ярлык.png`.
- `renderer.js` — весь холст: панорама/зум, ПКМ-меню создания нод, ноды/розетки/провода, живой чат в ноде + разворот, журнал `Консоли`/`Сканеров`, генерация панели опций Moonlit, цветовые пресеты. **Меню нод — кастомные `describedDropdown`** (под каждой опцией её описание «что делает»; ведёт себя как `<select>` — `.value` + событие `change`, поэтому старый код не переписан); `selectToDropdown(root, cls, opts)` заменяет нативный селект. Тексты — `DD_OPTS`/`TRIGGER_DESC`/`PROVIDERS[].desc`. Применено ко всем меню (Систем промт, комплитер, Лорбук/Режиссёр, Эмбеддер, Душа, провайдер API); нативным остался только `lb-depends`.
- `index.html` / `styles.css` — тема **Steam** (цвета/градиенты в CSS-переменных, переключаются пресетами), шрифт **Ubuntu Mono**, тулбар, оверлей разворота чата `#immersive`. **CSP:** `default-src 'self'` + `img-src 'self' data: blob:` (иначе аватары/фон как `data:`-URL блокируются в Electron). **Мобильный режим** — кнопка `#btn-phone` в тулбаре: тумблер, вешает класс **`mobile-mode`** на `<html>` (основа мобильной вёрстки — та же, что пойдёт в мобильный билд Termux/браузер) и зовёт `window.rlm.setMobile` (ужимает окно); плавающая кнопка выхода `#mobile-exit` видна только в этом режиме. Мобильный режим **нигде не хранится** (это вид устройства, не «сессия»). Пока `mobile-mode` — заготовка (шапка компактнее/скроллится), полной адаптации холста/нод нет. **Браузерная/телефонная версия** (нет моста Electron → `browserBuild = !window.rlm`, класс `browser-build` на `<html>`): на «телефонном» экране (`pointer:coarse` или `≤820px`) мобильный режим включается **сам** при старте, а кнопка `#btn-phone` и `#mobile-exit` **спрятаны** (CSS `html.browser-build`) — на телефоне переключать нечего. **Оформление** (стиль/цвет/затенение/провода) — обычные ключи серверной базы (`rlm-style`/`rlm-preset`/`rlm-wire2`/`rlm-wire-op`/`rlm.shade`), **одна сессия** на все устройства (телефон видит тот же вид, что и ПК; см. «Хранилище»). `apply*` пишут в базу только по действию пользователя (флаг `save`), на старте применяются через `initUiFromDb()`. **PWA** («Добавить на главный экран», сделано ОДИН В ОДИН как SillyTavern): `app/manifest.json` (`display: standalone`, `start_url:/rlm/`; имя/MIME как у ST — `application/json`) + apple-мета в `<head>` (`apple-mobile-web-app-capable`, `mobile-web-app-capable`, `theme-color`, `apple-touch-icon`) + иконки `icon-192/512.png` + `apple-touch-icon.png` (**официальный логотип RLM** — чип; тот же логотип в `app/icon.*` для окна/таскбара Electron). Ссылка на манифест — с `crossorigin="use-credentials"` (как у ST). **Без service worker, без HTTPS, без тоннеля.** iOS (Safari «На экран Домой») — запуск без адресной строки даже по http. **★ Настоящее устанавливаемое приложение на Android (плашка «Установить», без адреса) Chrome даёт только в secure context = https ИЛИ `localhost`/`127.0.0.1`.** Телефон→ПК по сети (`http://192.168.1.59`) — не secure → только ярлык. Поэтому app-on-phone для RLM = **Термукс на телефоне** (сервер на самом телефоне → `localhost` → приложение как у ST) ИЛИ тоннель/https; **отложено до Термукса**. HTTPS-ветку (локальный CA + сертификат) пробовали и откатили. См. `changelog` и память [[rlm-pwa-keep-simple]].
- `app/moonlit/chat.html` — живой интерфейс ST+Moonlit (см. «Чат»).
- `webfonts/` — локальные шрифты: FontAwesome (для чата) + Ubuntu Mono (`.woff2`, латиница+кириллица) — офлайн, ради Termux.
- `preload.js` — мост `window.rlm`: `close`/`restart`, `setMobile(on,size)` (мобильный режим — ресайз окна), `api` (звонок серверу), `store` (get/set — файловое хранилище, осталось только под `rlm.tts.dtype`; основное состояние — в серверной базе через `api`).

**Ноды.** Создаются из ПКМ-меню:
- `API` (LLM-провайдеры) — **настоящая**: «Проверить связь», «Тест ответа», настройки сохраняются **в файл** (`rlm-store.json` через `window.rlm.store`; ключ — сразу при вводе/вставке, переживает перезапуск). Слева **два подписанных входа на границе ноды**: «Промт» и «Опции». Модель — **свой выпадающий список с поиском по буквам** (после «Проверить связь»), не нативный datalist. Зовёт свой сервер (см. «Бэкенд RLM»).
  - **Пресеты провайдеров** (`PROVIDERS`) — выбор из выпадашки заполняет Base URL/модель; у пресета есть `mode` (`chat`/`text`). Добавлена группа **RP-хостинги (Text Completion)**: ArliAI, Infermatic (`api.totalgpt.ai`), Featherless, Mancer — все `mode:'text'`; в «Локально» добавлен **KoboldCpp (Text)**.
  - **Переключатель режима** «Режим: Chat / Text» (`el.dataset.mode`, сегментированные кнопки). Выбор пресета **сам ставит** нужный режим (RP-хостинги → Text). Режим сохраняется и в конфиг ноды (`rlm.apiConfig`), и в сборку графа (`nodeValues`/`applyValues`). Рантайм (`chatSend` и «Тест ответа») подмешивает крутилки из подключённой ноды `Локал-сэмплеры` поверх `Опций`; **гейт** (`applyLocalCaps`) по режиму/провайдеру решает, какие доступны (Chat — нода `Локал` серая целиком, работает `Опции`; Text — все, кроме несовместимых с сервисом). Тело уходит по OpenAI-совместимому `/chat/completions` — этого достаточно для Aphrodite-хостингов; нативный путь koboldcpp (raw text + `sampler_order`) — см. «Дорожная карта».
- `Опции` — сэмплеры в порядке ST Chat Completion, «в ряд». Подаются в **вход «Опции»** ноды `API`; в запрос идут как OpenAI-параметры (маппинг поле→имя; «Контекст, ток.» не шлётся). **Seed** (`readOptionsParams`): **−1 = случайное зерно каждый запрос** (`Math.random`), **пусто = не слать** (провайдер сам), **число ≥ 0 = фикс**. Раньше −1 = не слать, но провайдеры/движки с фикс-дефолтом (GLM, локалки) отдавали дословно тот же ответ — потому −1 теперь честно рандомит.
- `Локал-сэмплеры` — «умные» сэмплеры локальных движков (koboldcpp/ooba/aphrodite), которых нет в облачном API. Две секции: **порядок сэмплеров** (`LOCAL_ORDER`: Top K/A/P, TFS, Typical, Температура) — строки **перетаскиваются** (`attachSortHandle(..., '.ls-item')`), позиция = `sampler_order`; и **умные крутилки** (`LOCAL_PARAMS`: Min P, DynaTemp, Smoothing, Mirostat, DRY, XTC, rep-pen, no-repeat-ngram) фиксированными полями. У каждой строки — **подсказка при наведении** (`title`). Один **выход** → вход «Опции» `API`. Значения **и порядок** сериализуются (`{order, values}`). Рантайм: `chatSend` читает крутилки (`readLocalParams`) и кладёт в `params` — сервер прокидывает их насквозь в `/chat/completions` (Aphrodite-хостинги их понимают). Выключенные/нейтральные значения и «спутники» без активного выключателя **не шлём** (`LOCAL_NEUTRAL`/`LOCAL_GATE`); имена мапятся под OpenAI/Aphrodite (`LOCAL_KEY_MAP`). **`sampler_order`** пока **не отправляется** — он для нативного протокола koboldcpp (см. «Дорожная карта»), живёт как настройка ноды.
- **Ключ API — по СЕРВИСАМ** (`rlm.apiKeys`: `{ OpenRouter: …, ArliAI: … }`). Выбор провайдера в списке
  подставляет его ключ (`apiKeyFor`), ввод — сохраняет под текущим (`saveApiKeyFor`). Ключ **не пишется
  в снимок графа** (раньше уезжал туда и оседал в пресетах); при восстановлении ключ сервиса главнее
  того, что лежит в старом снимке. `migrateApiKeys()` один раз переносит прежний единый ключ.
- **Лимиты у `Локал-сэмплеров` свои** — «Ответ, ток.» (уходит как `max_tokens`) и «Контекст, ток.»
  (`localCtxLimit`, в API не уходит — им режется промт). Для своей цепочки они главнее «Опций»:
  `contextLimitFor` спрашивает «Локал» первым. Нужны там, где ноды «Опции» в цепочке нет вовсе
  (сборка под RP-хостинг: комплитер → API(Text) → «Локал-сэмплеры»).
- **Инструкт-шаблоны** (текстовый режим) — промт собирается по разметке той модели, на которой она обучалась,
  как в ST. Шаблоны **не копируем**: 37 файлов лежат в форке (`server/default/content/presets/instruct/`),
  эндпоинт `POST /api/rlm/instruct/list` (`endpoints/rlm-instruct.js`) отдаёт их клиенту, тот кэширует на сессию
  (`instructTemplates`). Выбор — селект `.api-instruct` в ноде `API` (виден только в Text, живёт в снимке графа
  полем `instruct`); пусто = `instructGuess` по имени модели (сперва `activation_regex` шаблона, потом таблица
  `INSTRUCT_GUESS`, иначе ChatML). `buildInstructPrompt` клеит простыню по `system/input/output`-меткам,
  `instructStops` берёт из шаблона стоп-строки (`stop_sequence` + метки чужих реплик). Развилка — `sendTurn`:
  шаблон есть → `/api/rlm/complete` с `prompt`, нет → прежний `/api/rlm/generate` с `messages`. Подписи имён
  (`names_behavior: force`) **не дублируются**: если реплика уже пришла подписанной («Кайра: …» — так их даёт
  групповой и сетевой чат), имя второй раз не лепится.
- **Ручных стоп-слов НЕТ** — их место заняли шаблоны. Прежний список был грубой заменой: дефолт `

` рубил
  ответ на первом абзаце, и на двух разных моделях это выглядело как «модель отупела».
  **Правило:** настройка по умолчанию, которая режет или меняет ТЕКСТ модели, ставится только после проверки
  на живом ответе. Не «по аналогии с ST», не «логично же» — сначала реальный ход, потом дефолт.
- **Цепочки в таблице «Все токены»** опознаются по ноде **API** (`tokApiForNode`), а не по «Опциям»:
  сборка, где настройки идут от «Локал-сэмплеров», иначе падала в графу «Без Опций». В заголовке цепочки
  пишется, чем она настраивается и какой у неё контекст.
- **Гейт доступности** (`applyLocalCaps`) — крутилки, недоступные при текущем режиме/провайдере, гасятся (класс `ls-off`: приглушены, зачёркнуты, `disabled` → в запрос не идут). **Chat** → нода серая **целиком**: в этом режиме сэмплеры даёт нода `Опции` (полный облачный набор), а `Локал` — инструмент Text; порядок не перетаскивается (`ls-noorder`). **Text** → активны все, кроме неподдерживаемых провайдером (`PROVIDER_UNSUPPORTED`, напр. Mancer без Mirostat). Пересчёт — на смене режима/пресета и подключении провода; при отцеплении — снимается.
- **DynaTemp — поле-диапазон** «мин — макс» (два инпута через тире, `dynatemp_min`/`dynatemp_max`), а не один «размах»; остальные крутилки — одиночные поля (Mirostat tau/eta, DRY, XTC — это разные параметры, не диапазоны).
- `Промт комплитер` — промпт-менеджер ST: плашки, drag-перестановка, вкл/выкл, у каждой **левый вход** + опции в раскрытии (**тип текст/маркер** — переключаемый, роль только у «текста», **позиция Relative/In-chat**, глубина); один **выход** = собранный промт. Плашка «История чата» появляется, когда комплитер дотягивается до чата — **напрямую ИЛИ через `API`** (`комплитер → API → Чат`). «＋ добавить» свою плашку. **Две зоны плашек** (`relayoutPlates`): сверху `Relative` (место = порядок), снизу `In-chat` — сгруппированы по **глубине** (подзаголовки, разделитель `.pm-sep`/`.pm-subhead` — чисто визуальные, не видны drag/сборке/сохранению). Порядок внутри одной глубины — **как плашки стоят** (перетаскивание, сверху = раньше); числового «Порядка» нет (`assembleMessages` берёт DOM-порядок).
- `Мультиплей-комплитер` — вариант `Промт комплитера` для **группового чата** (тип `mprompt`, класс `node-mprompt`, `buildMpromptNode`). **Слот = ТИП ПЛАШКИ** (текст/маркер/**слот**, `makeSlotItem`): в списке комплитера, коннекторы ВНУТРИ — свёрнут = один разъём (ключ порта `slot:<id>`), раскрыт кареткой = вход у каждого поля карточки (Описание/Характер/Сценарий/Примеры/Лорбук/Систем/**Фантом**; ключи `slot:<id>:<field>`; `portKey`/`findPort` расширены). **Авто-разводка** (`slotAutoWire`, хук в `onPortDown`): воткнул выход `Персонаж` в разъём/«Описание» → 6 полей карточки цепляются сами. **Имя слота = имя карточки** + авто-переименование (`mpSyncSlotNames`, хук в `applyCard`). **In-chat КОПИЯ слота** (`makeSlotIcItem`, `.pm-item.pm-slot-ic`, та же `data-id`, `pos=chat`): Душа/Состояние — сюда (впрыск на глубину), раскрывается кареткой, имя синкается, гаснет у неактивного (`mpSyncIc`); `mpAddSlot` делает обе, удаление убирает обе. **Слот-РАССКАЗЧИК** (флажок «Рассказчик», `data-narr`/`.pm-slot-narr`): **питается от ноды `Рассказчик`** (см. ниже) — CSS скрывает карточные поля/Лорбук/разъём, у слота **4 входа**: Промт (`system`)/Стиль (`nstyle`)/Тон (`ntone`)/Мир (`nworld`); подписи/подсказка — в `slotSyncRow` по narr. Без Фантома, память=**Мир** (копия: Душа→«Мир», Состояние скрыто), значок ✎. `assembleMessages`: рассказчик на передаче → `system+nstyle+ntone+nworld`; у персонажа эти поля скрыты. Панель **«Коробка передач» = ПЕРЕКЛЮЧАТЕЛЬ** (`mpRenderSwitcher` — чипы из слот-плашек + «ход: X», клик = слот на передачу; `mpToggleSim` — симуляция); активный = `data-active` на плашке (источник истины — сами слоты). Провода свёрнутого слота/копии сходятся в плашку (`portCenter` редирект скрытых полей). Сериализация (kind/expanded/active/narr) — `nodeValues`/`applyValues`; вижн — `NODE_VISION_BUILD`/`TOOLS_MENU_SEL`/`syncVisionToMaster`. **Дефолт mprompt: 3 слота-перса + 1 слот-рассказчик** (порядок плашек: общие пред-историю → слоты → пост-история, чтобы карточки шли ДО «Истории чата»). **Сборка промта из слотов** (`assembleMessages`, роль всех полей слота — `system`): активный персонаж → его 6 полей карточки, неактивные персонажи → только «Фантом», рассказчик молчит (Мир скрыт от персонажей); активен рассказчик → ВСЕ карточки полные + своя; личный канал (Душа/Состояние из in-chat копии) впрыскивается на глубину ТОЛЬКО у активного (`SLOT_IC_DEPTH` = Душа @1, Состояние @0), у рассказчика личный канал = только «Мир». **Кормит `API`**: `completerForApi` = `.node-prompt` ИЛИ `.node-mprompt` (заменил жёсткие `sourceForApi(...'.node-prompt')`); `syncPromptHistory`/`directorNodeForChat` расширены на `.node-mprompt` (появляется «История чата», Режиссёр находит группу). Пресет **«Групповой чат»** (`buildGroupChatPreset`) — карточки РАЗВЕДЕНЫ в живые слоты (авто-разводка `slotAutoWire`: 3 перса + рассказчик), общие плашки (плашка **«Основной промт»** = иммерсивный RP-систем-промт `GROUP_MAIN_PROMPT`, НЕ «ассистент»; **Рассказчик — роль**, его секции идут только на его ход; ограничитель роли персонажа мягкий — 3-е лицо как в сингле, без запрета описывать мир), одна `Душа` → «Мир» рассказчика, **у каждого персонажа своя нода `Систем промт` (метка «Фантом · Имя») → поле «phantom» слота** (`slotPhantom`/`phantomSlot`/`phantomSyncNames`); пере-посев версионирован (`GROUP_PRESET_V`=11/`rlm.groupPresetV` — `ensureGroupChatPreset` пересобирает граф того же пресета при устаревшей версии). **Групповой вид чата** — панель партии `#rlm-party` в `chat.html` (`renderParty` + `chatPartyData` в `postRender`, у члена флаг `narr`): читает слот-плашки, в ноде и вижне; нет mprompt → скрыта.

Обычный `Чат` → `isGroupChat`=false ВСЕГДА → ноль группового (все групп-ветки под `isGroupChat` выключены). `nodeType` даёт `groupchat` ДО `chat`; `nodeValues`/`applyValues` — алиас chat; меню `new-groupchat`. - **Групповой чат — движок хода (Ранжиратор) + Вход в игру** (живут В ЧАТЕ, не ноды; всё под `isGroupChat`). **Вход в игру** (`#rlm-entry`/`renderGroupEntry` в `chat.html`): пока `node._groupStarted` false — вместо ленты экран старта (завязка + партия + **переключатель «Дописать сцену Рассказчиком»** + «Начать игру»); `postRender` шлёт `group:{started,scene,auto}`. По кнопке `groupStartGame(node, scene, {expand})`: этап 1 — **фантомы по одному персонажу** (`genPhantom` — публичное впечатление; текст **вписывается в фантом-ноду** слота `slotPhantom` + дублируется в `node._phantoms[slotId]` для back-compat; `slotPhantomText` берёт текст ноды в приоритете, `_phantoms` — фолбэк), этап 2 — **стартовая сцена**: `expand=true` → рассказчик дописывает по завязке (`genOpeningScene`); `expand=false` → **завязка КАК ЕСТЬ** первым сообщением (точность, без переписывания); прогресс — `group-prep`/`groupPrepUpdate`. **Ранжиратор** — конфиг на ноде `Чат` (`node._ranker` = mode судья/механика, maxTurns, points, prompt; сериализуется в `nodeValues`/`applyValues` типа chat вместе с `groupStarted`/`phantoms`/`groupScene`); открывается **🔧 Инструменты → «Ранжиратор»** (`openRankerPanel`, оверлей как меню инструментов). Один ход — общий `groupDoTurn(node,pick)` (передача → `generateReply` → подпись/счётчики; пустой/аборт → false). Цикл `groupPlay` (хук в `chatSend`, только для группы): ранжиратор выбрал (`rankerJudge` — лёгкий LLM-промт партия+фантомы+история; `rankerMech` — правила: имя/счётчик/кубик; нет API → фолбэк на механику) → `groupDoTurn` → снова, пока не «player» / предел N / пусто; анти-луп. **Важно (фикс пустых ответов):** групповой ограничитель роли идёт ролью **`user`** (не system), иначе массив кончается на assistant+system и модель отдаёт пустой ответ; пустой ответ в группе не пишем «(пустой ответ)», а убираем плейсхолдер (`_grpEmpty`). **История для модели (`chatTurns`) в группе — с ИМЕНЕМ перед репликой** («Кайра: …», план C), иначе реплики персонажей (роль assistant) без атрибуции путают модель; дубль-подпись «Имя:» из начала ответа срезается. Реплики несут `_speaker` (имя над сообщением, `mesHtml`); у рассказчика ставится `_narr` → **проза без имени и аватара, без курсива** (`.mes-narr`, во всю ширину), а активный говорящий («на передаче» по `lastParty`) → **имя+аватар золотым акцентом** (`.mes-active-speaker`), остальные нейтральны. Бутстрап = первый ход всегда запускает игрок. Счётчики ходов (`node._grpCounts`/`_grpSinceNarr`, ведёт `groupPlay`) видит и судья (в промте «turns taken»/«since narrator»), и механика (рассказчик при `sinceNarr≥points`); у промта судьи кнопки RU/EN (`attachFieldTranslate`). **Роли в группе:** `chatNames`/`chatAvatars` группо-зависимы (`{{char}}`+аватар = активный слот); `generateReply` для группы добавляет **ограничитель** (план E: персонаж «только за себя», рассказчик «только мир, не за игрока») + «пиши только как X». **Двухканальная память (D) — СВОЯ `Душа` на КАЖДЫЙ слот, доки урезаны по роли** (пресет v5): 3 персонажа + рассказчик, каждая Душа → in-chat поле своего слота (`slot:<id>:soul`) + свой Эмбеддер, хранит папку `chatId:slotId` (`memChatId`), подхватывает имя слота (`soulSyncNames` в `mpSyncSlotNames`/`markPortsWired`/правке имени карты: «Душа · Имя» / пустой → «Душа · Слот N» / «Мир · Рассказчик»). **Доки по роли** (`applySoulSlotDocs`, `SOUL_SLOT_CHAR_DOCS`=Diary+Psyche / `SOUL_SLOT_NARR_DOCS`=Status+World+Topics): урезаются при сборке пресета и ручном втыкании Души в слот (`onPortDown`), на восстановлении не трогаются. Хелперы `slotSoul(chat,slot)`/`soulSlot(soul)`/`activeSlotSoul(chat)`. Чтение/запись памяти — по АКТИВНОМУ слоту: `refreshSoulMemory`/`updateMemory`/`maybeUpdateMemory` (и Критик) берут `activeSlotSoul` + его папку; `characterBaseline(chatNode)` в группе — только активный; в промт идёт in-chat активного (канал не течёт); `clearThisChat` стирает per-slot папки. **Доступ в вижне:** клик по нику в панели партии (`renderParty`→`party-soul`→`slotSoul`) открывает Душу этого слота; **🔧 Инструменты** показывает каждую Душу (`soul` в `toolsMenuNodes`/`TOOLS_MENU_SEL`); `openLoreFs` для Души сам ставит папку слота (группа) / базовый chatId (одиночный) + метку `_recLabel` в заголовок; 🧠 в группе — Душа активного слота. **Кнопка «⏭ След. ход»** (`chat.html` → `group-next` → `groupNextTurn`): форсит ОДИН ход ИИ без реплики игрока (ранжиратор выбрал; судья вернул «игрок» → фолбэк на механику, чтобы ход случился); гейт `_grpBusy`; видна только в группе с начатой игрой. **Авто-ходы «▶ Авто/⏸ Пауза»** (`group-auto`→`groupAutoToggle`→`groupAutoPlay`): крутит `groupDoTurn`, ПОКА ранжиратор не вернёт «игрок» (тогда стоп) / пауза / пусто / аборт; НЕ форсит механику (уважает вердикт player). Состояние в кадр — `group-auto-state`, на рендере — `group.auto`. **«Новый чат» в группе** (`clearThisChat`, ветка `isGroupChat`): чистит ТОЛЬКО историю + Души (purge папок `chatId:slotId`) + лорбук чата; **не сбрасывает** `_groupStarted`/`_phantoms`/`_groupScene` (фантом-ноды и Рассказчик целы, игра остаётся начатой), сбрасывает лишь счётчики; `seedGreeting` в группе не зовётся. **Фантом — НЕЙТРАЛЬНЫЙ** (`genPhantom`; у каждого персонажа свой): впечатление от третьего лица, одинаковое для любого зрителя — явно без упоминания игрока/`{{user}}` и без описания взаимодействия с кем-то конкретным. **Макросы `{{slot_N}}`** (`substituteMacros`, регекс `[a-zA-Z0-9_]+` + резолв `slot[_-]?\d+` из `.node-mprompt`) = имя персонажа N-го слота (1-индекс по позиции); дополняет `{{char}}`=активный. Номер слота виден в UI всегда (бейдж `.slot-idx` «#N» в `slotSyncRow`). **Впереди** (см. `plan-group-chat.md`): NPC/визитёры; открытые темы Критик/Состояние в группе, температура наррации, нода «Цель»; awareness рассказчика о персонажах при опенинге.
- **Нода `Рассказчик`** (тип `narrator`, класс `node-narrator`, `buildNarratorNode`) — карточка нарратора для слота-рассказчика (как GM в SoW): **4 секции**, у каждой свой выход справа (`svc-out data-out=system/nstyle/ntone/nworld`): **Промт** (дефолт `NARRATOR_DEFAULT_PROMPT`) · **Стиль** (пресеты `NARR_STYLE_PRESETS` + ручной) · **Тон** (7 пресетов SoW `NARR_TONE_PRESETS` + ручной) · **Мир** (описание). RU/EN на каждой. `sourceText`→`narrSectionText` (обёртки STYLE/TONE/WORLD). Сериализация `{sections}` (`nodeValues`/`applyValues`); в 🔧 (`TOOLS_MENU_SEL`). В пресете группы 4 выхода разведены в 4 входа слота-рассказчика. Тон **НЕ** крутит температуру (в SoW крутит — у нас убрано; где управление температурой — открытый вопрос).
- `Персонаж` — источник карточки: имя в шапке, клик по **аватару** (крупный 60×78, скруглён) → загрузка PNG/JSON (V1/V2/V3), **выходы полей** → в плашки. Если в карточке есть встроенный лорбук (`character_book`) — при загрузке его записи ложатся в **существующую ноду «Лорбук персонажа»** (scope «персонаж»; ищется по плашке `charLore`, `charLorebookNode()`), новая нода **не плодится**; тянется провод `Персонаж.Лорбук → Лорбук персонажа` (данные копируются в ноду). Фолбэк (ноды «Лорбук персонажа» нет) — создаётся с этой подписью. **`Первое сообщение` (`first_mes`)** — отдельного порта/ножки на `Чате` **нет** (убрано). Приветствие засевается **автоматически**: если `Персонаж` подключён к графу хоть одним проводом (`nodeHasWire`), `seedGreeting` берёт его `first_mes` (выход `field:first_mes`) и ставит стартовой репликой пустого чата (роль `char`, `greeting:true`). Аналогично тому, как `chatNames`/`chatAvatars` берут имя/аватар по проводам. Парсер `readPngChara` **async** и читает `tEXt`/`iTXt`/`zTXt` (сжатые — `DecompressionStream`), при неудаче — видимое сообщение. Кнопка **«✕ карточка»** (`clearCharCard`) чистит ноду + лорбук персонажа + чат; `applyCard` при карточке БЕЗ лорбука тоже очищает лорбук персонажа.
- `Персона` (подпись ноды — **«Пользователь»**) — профиль пользователя (ST User Persona): **имя + аватар + описание**. Имя по умолчанию — латиницей **`User`** (чтобы `{{user}}` в англоязычном промте раскрывался как `User`); пустое имя → подпись «Пользователь». Один выход → плашка «Описание персоны» (`personaDescription`). Аналог карточки, но про `{{user}}` и проще (одно поле). Аватар — загрузка картинки (не карточки). В пресете подключена. **Библиотека персон — ОБЩАЯ на все чаты** (серверный ключ `rlm.personas` = `[{id,name,avatar,desc}]`, как персонажи): сверху ноды — **выпадашка выбора** сохранённой персоны (`.persona-dd`, наполняется при открытии), рядом **＋ добавить** / **✕ удалить** (`personaSelect`/`personaWriteActive`/`personaCommit`; список в `db` обновляется синхронно, POST на сервер — дебаунсом 400 мс, как у лога чата). Правки полей — **write-through в активную персону** (видно везде, где выбрана та же персona, и в вижне). Активная персона у ноды — `el._personaActiveId`, **её id пишется в снимок графа** (`nodeValues`/`applyValues` → у каждого чата своя активная из общей библиотеки). Старые снимки `{name,avatar,desc}` без `activeId` **мигрируют** в библиотеку (`personaEnsureAndSelect`: совпадение по имени+описанию или добавить как новую — ничего не теряем). **Вижн** — тот же клон `buildPersonaNode` на общих данных (выпадашка/＋/✕ там же; выбор персоны при закрытии переносится в мастер через `syncVisionToMaster`). *(Тип ноды/сериализация — по-прежнему `persona`; в снимке рядом с `activeId` для совместимости лежат и `name/avatar/desc`.)*
- `Систем промт` — своя инструкция + **системный промт персонажа** (по проводу в левый вход, от поля «Систем-промт» карточки). Селект **«Смешивание»** (**Только свой / Только входящий / Совместить** + порядок) — `sysPromptText`; «входящий» = что пришло по проводу в левый вход (карточка/`Душа`/любой источник, не только персонаж). Выход → плашка «Основной промт» (`main`) или прямо в `API` (простой режим). Это RLM-слой сверх ST (в ST `system_prompt` карточки просто перебивает main; чекбокс «перебивание» у `main` убран — спор решают режимы ноды). **Универсальна.** *(Раньше её цепляли и к докам `Души` — по ноде на каждый док, подпись «Промт: <док>»; теперь промты доков живут ВНУТРИ Души, эти ноды из пресета убраны.)* Подпись ноды (`label`) переживает сохранение. **Префилл** (поле «начать ответ модели с…» + **галочка вкл/выкл** `sys-prefill-on`, ST «Start Reply With») — уходит **последним сообщением роли `assistant`**, модель продолжает его (ломает отказы); идёт только при включённой галочке; берётся из ноды пайплайна (`prefillOf`: полный режим — подключённая к плашке `main`, простой — к входу «Промт» API).
- `Консоль` — **не нода, а узкая панель СПРАВА поверх холста** (`#console-fs`, `width:460px`, док под тулбаром — холст виден слева, не на всё окно): журнал всех вызовов `rlmApi` — промт (`messages` по ролям), модель, параметры, ответ/ошибка, `finish_reason`, токены. Ключ/Base URL **не показываются**. Терминальный вид. Открывается **кнопкой «>_» в тулбаре** (`#btn-console`, слева) на холсте **И кнопкой `>_ консоль` в шапке вижна** (`#im-console`, между «← ноды» и «опции ⚙» — панель `z-index:9999` выше `#immersive`, потому видна поверх чата): **в вижне чата раскрывается на весь экран** (класс `im-mode` по `immersiveNode` в `openConsole`: `top/left/right/bottom:0`, `width:100%`), вместо ✕ — кнопка **← назад** (`.con-back`); на холсте остаётся узкий док справа с ✕. Закрывается «← назад»/«✕»/Esc (в вижне Esc сперва гасит консоль, только потом выходит из погружения — capture-хэндлер). **Записи раскрыты сразу** (без свёртыша). - `Сканер` — **честный предпросмотр**: вход ← выход ноды (обычно комплитера) → по каждой активной плашке «имя + реальный контент» **той же** `plateContent`, что идёт в запрос (контекст лорбуков — `_msgs` чата); пустые плашки скрыты. Не-комплитер → просто текст источника. Обновляется при генерации/смене связей/кнопке. **Кнопка Сканера async: перед показом зовёт `refreshSoulMemory` + `refreshSemanticLore`** — поэтому в плашке «Память» виден реальный контент (RAG), а не пусто. Терминальный вид. Тупик (только вход).
- `Лорбук` — **мини-приложение** (слева список записей + фильтр, справа редактор; модель записей в JS `el._entries`; выбор — `el._sel` = id записи). *(**Грабли/инвариант:** id записей уникальны В ПРЕДЕЛАХ книги — иначе `find(x=>x.id===_sel)` в редакторе/клике «залипает» на первой с таким id. Счётчик `loreSeq` сбрасывается при перезагрузке, а сохранённые id живут → нормализация списка идёт через **`loreNormEntries`** (не `map(loreNormEntry)`): держит счётчик впереди восстановленных `eN` + дедупит дубли при загрузке. Зовётся во всех точках, где список становится `_entries`: `fillLorebook`/посев `buildLoreApp`/импорт/`applyValues`.)* Запись: имя, **тип триггера** — у Лорбука знаниевые `keyword`/`semantic`/`vectorized`/`always_on` (`LORE_KNOWLEDGE_TRIGGERS`; событийные `range`/`random`/`chain` — у `Режиссёра`). Два смысловых режима: `semantic` (SW) — по фразе-эталону (`semTrigger`+`semThreshold`); `vectorized` (ST) — по тексту самой записи (`vecThreshold`), «неточная» векторизация; оба на векторах, гейт на `Эмбеддер`. Дальше: инъекция (lore/event), ключи+вторичные+логика (И/НЕ)+целое слово/регистр, содержание. *(Позиции/порядка НА ЗАПИСИ нет — модель как у SW: позицию в промте решает ПЛАШКА, куда льётся лорбук; у записи только «инъекция» знание/событие. ST даёт 7 позиций на запись — осознанно не тянем, эту роль у нас играет разделение Лорбук/Режиссёр.)* *(Тайминги sticky/cooldown/delay — только в редакторе `Режиссёра` (флаг `cfg.timings`): для событий они осмысленны, для статичного знания нет. В движке пока не считаются.)* Внизу — **дальность сканирования** + Импорт/Экспорт JSON. **Глазок** в шапке (`.node-eye`, как у `Чата`) → полный экран (оверлей `#lore-fs` + топ-бар «← Назад»; клик по шапке в FS не сворачивает). **Полноэкранный вид — КЛОН на общих данных** (`openLoreFs`→`fsCloneFor`: клон делит `_entries` с мастером; снят `node-lore`/`node-director`, поэтому мимо движковых запросов и сериализации): сама нода из `#world` НЕ уходит (иначе автосейв в момент показа терял бы её провода). Вход (лорбук персонажа) + боковой вход ← `Эмбеддер`; выход → своя плашка по scope. **Область (scope)** выбирается дропдауном вверху ноды (`LORE_SCOPES`: world/char/chat) и **видна в имени** — «Лорбук · World Info / · Персонаж / · Чат» (`loreTitleOf`; `el.querySelector('.lb-scope-dd').value`). Нода **одна** (не три типа), в пресете три её экземпляра с разными областями → плашки «World Info» / «Лорбук персонажа» / «Лорбук чата»; `charLorebookNode()` ищет char-лорбук по области. `Режиссёр` области не имеет. Движок `loreText` (общий с `Режиссёром`): keyword-матчинг (вторичные+логика+целое слово+регистр) + always_on + вероятность + **дальность сканирования** (последние N сообщений массивом `node._msgs`) + **range** (номер сообщения в окне `[msgMin..msgMax]`, 0=до конца) + **random** (простой шанс/ход = «Вероятность,%») + **chain** (после предка `dependsOn` + пауза `chainDelay`, одноразово; память срабатываний `el._fired` хранит ПЕРВОЕ срабатывание = якорь цепочки) + **semantic**/**vectorized** (гейт на подключённый `Эмбеддер`; **работают на векторах**: `refreshSemanticLore` перед сборкой промта считает через `/api/rlm/soul/score` близость сцены к фразе-эталону (semantic) / тексту записи (vectorized), кладёт в `loreEl._semCache`, а `semanticScore()` читает кэш; порог `semThreshold`/`vecThreshold`). Редактор записи показывает блок полей под выбранный тип триггера. **Пин `ignoreBudget`** — галочка с описанием «Всегда в промт (мимо бюджета)» в редакторе (`.lb-ignorebudget`, `loreRenderEditor`/`loreBindEditor`): такая запись не срезается бюджетом. **Бюджет (`loreText`):** кандидаты сортируются `(a.mm===b.mm) ? b.order-a.order : (a.mm?1:-1)` — **ручные записи (не-`mm`) ВСЕГДА выше авто-глав `Хроники` (`mm`)**, внутри группы — по `order` (убыв.), лимит токенов, `ignoreBudget` всегда влезает. Keyword-матч вынесен в общий **`loreKeywordMatch(e,text)`** (основной+вторичные И/НЕ, целое слово, регистр) — используется и движком, и тестом активации в читалке 🕯.

- `Рандомайзер` — **честный кубик без второго запроса к модели** (`buildRandomNode`, класс `node-random`, 320px). Код держит очередь исходов `success|fail` (`randomFillQueue`, `RANDOM_QUEUE_LEN=24`, шанс успеха `.rnd-chance`); в промт уходит ТОЛЬКО ближайший (`randomNext` → `randomBlockText`, `{{roll}}`), поэтому модель не видит будущее и не может выбрать удобный момент. **Очередь сдвигается при ОТПРАВКЕ хода** (`randomTick()` сразу после `assembleMessages`, до вызова модели) — подсвеченный чип всегда «тот, что в работе». Вход ← ножка `Чат` **`out:random`** (`randomNodeForChat`), выход → плашка **«Рандомайзер»** (`pos:'chat' depth:0`). Значок кубика в панели чата (`chat.html` `.rlm-random-open` → `random-open`) открывает ноду вижном. **«Раскрыть вероятность»** под последним ответом (`randomHtml` в `chat.html` → `random-peek` → `roll-peeked`) — игрок смотрит, какой бросок уйдёт с его ходом; **ничего не тратит**. **Модуль для Критика живёт В ЭТОЙ ноде** (нода «Критик» не трогается): галочка `.rnd-crit-on` + своё окно промта `.rnd-crit-p`; `randomCriticBlock(chatNode)` дописывается в конец системного промта критика в `criticJudge` и `tgCriticJudge`, при выключенных бросках возвращает пусто.
- `Программный DRY` — **анти-повтор БЕЗ модели** (`buildDryNode`, класс `node-dry`, 330px; эмуляция сэмплера DRY/анти-клише на облачном API). Собирает **кодом** (ноль запросов к модели) список заезженных фраз и просит модель не повторять. Три функции тумблерами: **Анти-повторы** — авто-детект (`dryRepeatedPhrases`: n-граммы `minW..maxW` из последних N ответов роли assistant, ≥`thresh` раз, вложенные схлопнуты, топ `limit` по «частота×длина») **+ ручной банк** (`.dry-rep-bank`); **Штампы** — ручной банк (`.dry-cliches`); оба банка матчатся общим `dryBankMatches` (нормализованное вхождение подстрокой, ловится с одного раза), подаются разными секциями. **Оба банка ПУСТЫ по умолчанию** (`DRY_CLICHES_DEFAULT = ''`) — служебка к модели только на английском (инвариант [[rlm-prompts-english]]), содержимое наполняет пользователь. **Свежесть** — **редактируемый английский промт** (`.dry-fresh-prompt`, дефолт `DRY_FRESH_DEFAULT`). **У всех трёх текстовых полей** (промт + оба банка) — кнопки RU/EN (`attachFieldTranslate`) и чтение через `trSafeVal` в `dryReadParams` (RU-предпросмотр не утекает в промт); ролеплей на английском → и банки английские. У банков — кнопка «🗑 очистить» (`.dry-clear`). Плашка комплитера — тип **маркер** (перехват в `assembleMessages` по проводу к `.node-dry`, не по типу плашки). Готовый **English-блок** (`computeDryBlock`; дубль «повтор↔штамп» убран) впрыскивается **In-chat @0**. **Проводка иная, чем у Цели/Состояния:** нода **не** висит на `Чат` — историю берёт сам `assembleMessages` (`chatTurns`). В `assembleMessages`: у любой плашки, чей `.port.in` подключён к `.node-dry`, вместо `plateContent` считается `computeDryBlock(conversation, node)` на глубину плашки (мастер-тумблер `.dry-on` гейтит). Дефолтная плашка **«Программный DRY»** (`PROMPTS`, `pos:'chat' depth:0`) — только в свежих комплитерах; в старых плашку добавить вручную. Нода **заведена в `buildDefaultPreset`** (`wire(dry,'out',comp,'plate:dry')`); сохранённые графы не пере-сеиваются. **Выход веерный:** та же нода → плашка комплитера И/ИЛИ **разъём Критика** (см. ниже) И/ИЛИ оба — пользователь решает проводом. Сериализация тип `dry` (`on/window/thresh/min/max/limit/repOn/cliOn/freshOn/repBank/cliches/freshPrompt`); доступ из чата — 🔧 (`TOOLS_MENU_SEL.dry` + **`NODE_VISION_BUILD.dry`** = полноценный вижн-клон), глазок на холсте → `openLoreFs`. **DRY → Критик:** у Критика второй вход `svc-in[data-in="dry"]` («Анти-повтор»); `criticJudge` зовёт `criticDryData(critic, chatTurns(node))` и подмешивает блок в кейс (`CRIT_DRY_PREAMBLE`) — заворачивает ответ, если он повторяет заезженное (`criticDryData`, preamble `CRIT_DRY_PREAMBLE`). `tgCriticJudge` (Telegram) НЕ трогали. **«Свежесть» — писателю:** `computeDryData` отдаёт части (`{reps, clis, fresh, block}`) + `dryComposeBlock`; по `dryFeedsCompleter(dryNode)` свежесть идёт **модели** (есть провод в комплитер) либо **критику** (критик-only) — всегда в ОДИН промт, не двоится; повторы/штампы — обоим. **Уведомление** (`dryNotify` → `chatToast` + `opts.autohide`=7 c, тост вверху чата) — ОДИН раз за ход: модель-путь (`generateReply` из `chatNode._dryHit`, ставит `assembleMessages`) либо, при DRY-только-в-критик, `criticJudge` (гейт `!dryFeedsCompleter`). В `mprompt` (группа/сеть) не заведена.
- `Эмбеддер` — сервис смыслового поиска (текст→вектор), **модель на выбор** в UI (`multilingual-e5-small` дефолт / MiniLM / Jina), сериализуется. Боковой выход → `Лорбук` (semantic) / `Душа` (RAG). **Бэкенд настоящий:** векторы считает родной ONNX/WASM ST (`getTransformersVector`), модель задаётся в `server/config.yaml` (`extensions.models.embedding = Xenova/multilingual-e5-small`, многоязычная — знает русский); e5 требует префиксы `query:`/`passage:` (ставит обёртка в `rlm-soul.js`). RAG по памяти уже работает (`/api/rlm/soul/diary`,`/topics`); переключение модели прямо с ноды (и ре-векторизация) — позже. *(Пер-нодовый выбор модели пока не прокинут в пайплайн — движок берёт модель из конфига.)*
- `Транслитер` — управляет кнопками перевода (`buildTranslatorNode`, класс `node-translator`). Два режима-секции (preview/replace), у каждого провайдер (`TRANSLATOR_PROVIDERS`: google/yandex/bing/neuro). **Секция «Нейро-промт»** (видна при провайдере «Нейро»): поле инструкции `.tr-prompt` (дефолт `TR_DEFAULT_PROMPT` — **по-английски**, направление-агностичен) + префилл `.tr-prefill` с **галочкой** `.tr-prefill-on` (выключен → поле скрыто `hidden` и в запрос не идёт; «начать ответ модели с…», ломает отказы) — **чтобы расцензур/инструкция жили в ноде, без отдельного «Систем промта»**. Сериализуется `{preview:{provider}, replace:{provider}, prompt, prefill, prefillOn}`. **Боковой ВЫХОД** `.tr-neuro-out` (класс `svc-out`, ключ порта `out`; `portKey`/`findPort` понимают `.svc-out`) **на ПРАВОЙ стороне ноды** — **втыкается в «Промт» ноды `API·перевод`** (в пресете Транслитер слева, API справа → провод короткий, слева-направо); виден если **хоть один** режим = «Нейро». Смысл провода — **движок** (какой API переводит); промт берётся из поля ноды, а не течёт по проводу. **Кнопки перевода на полях** (`instrumentTranslateFields` по `TR_FIELD_SEL`: `Систем промт`/`Лорбук`/`Персона`, + записи `Души`) — `attachFieldTranslate`: **RU** `trTogglePreview` (предпросмотр EN→RU, обратимо, input НЕ шлём; ставит `field._trPreviewing`+`_trOrig`), **EN** `trDoReplace` (RU→EN, заменяет + input). **Инвариант:** предпросмотр НЕ должен сохраняться — все места, что читают такое поле в модель/снимок (`grab()` лорбука, «Принять» превью Хроники, сериализация `Систем промт`/`Персона`), берут значение через **`trSafeVal(el)`** (при активном предпросмотре → `_trOrig`, а не показанный перевод). Движок `trTranslate(text,to,mode)`: **сперва `substituteMacros`** (макросы `{{user}}`/`{{char}}`/… → имена ДО перевода, чтобы переводчик не видел голый шаблон), затем провайдер из режима (`trProvider`), кэш `_trCache`; google/yandex/bing → `/api/rlm/translate`; neuro → `trNeuroTranslate` (API находит по проводу `.tr-neuro-out → API.in:prompt`, через `/generate`): сообщения — `system` = поле `.tr-prompt` (или `TR_DEFAULT_PROMPT`), `user` = «Translate … to English/Russian:\n\n<текст>» (язык направления подставляет код), + `assistant`-префилл из `.tr-prefill` если галочка включена. Сэмплеры — из ноды `Опции · перевод`, а без неё — `TR_DEFAULT_PARAMS` `{temperature:0.3, max_tokens:4000}` (щедрый лимит: перевод ≈ по объёму исходника, а «размышления» отключены); **всегда шлёт `reasoning:{enabled:false}`** — иначе рассуждающие модели (glm/Qwen) вываливают «мысли» вместо перевода, а сервер при пустом `content` отдаёт их `reasoning`. В **чате** (`chat.html`) кнопки шлют `translate-mes`/`translate-input` родителю → он зовёт `trTranslate` и отвечает `mes-translated`/`input-translated`. **Вижн `Транслитера` доступен из чата через меню 🔧 «Инструменты»** (`NODE_VISION_BUILD.translator`/`TOOLS_MENU_SEL.translator`; клон на `applyValues`, порт `.tr-neuro-out` не пересобирается).
- `Озвучка` — **OmniVoice TTS, клон голоса, БЕЗ ComfyUI** (`buildTtsNode`, класс `node-tts`). **ПК/Electron-only** (тяжёлый python-сервис на GPU). Поля: образец голоса `_refAudio` (путь к WAV — `File.path`/`webUtils`), `ref_text` (опц.), язык, + числовые/булевы (`TTS_PARAMS`/`TTS_BOOLS`, имена реальные omnivoice: `num_step`/`guidance_scale`/`t_shift`/`speed`/`duration`/`position_temperature`/`class_temperature`/`layer_penalty_factor`/`audio_chunk_duration`/`threshold`/`seed`/`denoise`/`preprocess_prompt`/`postprocess_output`/`normalize_text`). Вход ← **нижняя ножка «Озвучка» ноды `Чат`** (`Чат.out:tts → Озвучка.вход`; `ttsNodeForChat` = `findPort(chat,'out:tts')`, фолбэк — единственная нода, в т.ч. для старых сборок с проводом на общем выходе). Сериализуется `{refAudio, refText, lang, nums, bools}`. Озвучка — **по кнопке 🔊** на сообщении (`chat.html` → `speakFromChat`): чистит разметку (`*`/кавычки) + `substituteMacros`, зовёт `window.rlm.tts.generate` → Electron лениво поднимает сервис `tts/service.py` (8123, модель грузится раз в фоне) → `out/out.wav` (**один файл, перезапись**) → рендерер играет base64-blob (`playB64Wav`; CSP `media-src blob:`). Реальный набор параметров сверен с пакетом (`OmniVoiceGenerationConfig` + прямые аргументы `generate()`); `seed` → `torch.manual_seed`. **В дефолт-пресете** — справа от `Чата`, провод `Чат.out:tts → Озвучка.вход` (образец голоса выбирает пользователь). **Сохраняется в снимок чата/пресет** (`nodeValues`/`applyValues` тип `tts`: `refAudio` (путь), `refText`, `lang`, `nums`, `bools`) — голос и настройки переживают перезагрузку. У каждой числовой/булевой настройки — **описание под полем** (`hint` в `TTS_PARAMS`/`TTS_BOOLS`: что делает, выше/ниже, что ставить). *(ffmpeg для mp3-образцов не стоит; старые сохранённые сборки ноды не содержат — добавить из меню или пересобрать дефолт.)*
- `Сетевая игра` — **«безэкранный чат» для партии** (`buildNetgameNode` поверх внутреннего `buildTelegramNode`, классы `node-telegram node-netgame`, 1060px). Отдельная нода `Telegram` (сингл) **удалена из меню 2026-08-28** — конструктор остался лишь основой; старые снимки с типом `telegram` открываются как `netgame`. **ПК/Electron-only** (CSP расширен на `api.telegram.org`), почтальон — прямой `fetch` к Bot API (`tgCall`/`getUpdates` long-polling 25с). Держит **`_convos`: chat_id → {chatId, msgs}** и играет роль чат-ноды (подставляет беседу в `el._msgs`/`el._chatId`, поэтому `assembleMessages`/`refreshSoulMemory`/`maybeUpdateChronicle`/`chatApi` работают как с `Чат`). Вход слева ← `API`; внизу ножки **`out:tts`**, **`out:chronicle`**, **`out`** (Критик). **Отправка (Bot API 10.x):** лестница `tgSendPretty` = `sendRichMessage` (rich-markdown: заголовки, таблицы, цитаты, спойлеры, потолок 32768) → Markdown v1 (`tgMdToLegacy`) → голый текст (`tgMdPlain`); при наличии медиа — `tgSendRichMedia` (multipart: `rich_message` + `media` с `attach://`, ссылки `tg://photo?id=`/`tg://video?id=`/`tg://audio?id=`), так картинка, озвучка и фоновый звук лежат **в одном сообщении** с текстом. **Разметку ставит код** (`tgNgAutoMarkup` — после перевода: имена жирным, реплики в цитаты, `tgFixTables` чинит таблицы; пустая строка перед таблицей обязательна, иначе Telegram склеивает её в абзац). **Кнопка «👤 Мой статус»** (`tgNgKeyboard` → `callback_query` в `tgHandleCallback`) присылает игроку **лично** (`tgSendWhisper`, ephemeral `receiver_user_id`, Bot API 10.2) его показатели и записи Души с переводом Яндексом (`tgYandexRu` → `/api/rlm/translate`); ведущий шепчет через ник → «🤫 Шепнуть». Ответ на эфемерку проверяется на `ephemeral_message_id`/`receiver_user` — иначе сообщение немедленно удаляется (Bot API молча глотает незнакомые параметры, секрет ушёл бы всем). **Замена хода** (перегенерация/фидбек/критик) всегда `deleteMessage` + новое сообщение; пустой ответ провайдера не отправляется. **UI ноды:** лента как чат Telegram (`tgFeed` → `.tg-bub`, `tgMdToHtml` рисует ту же разметку, что уйдёт в чат; значки 🔄/✏/⚖/🌐 у последнего ответа, теги контекста `_src` — включая невыполненные и выключенные плашки), панель участников с показателями (`tgNgSyncPartStates`), строка ввода с аватаром-переключателем (ведущий / игрок / шёпот), полоса нод сверху (`tgVisNodes`/`tgRenderVisBar` → `openNodeInChat` в контейнер `.tg-main`; лорбук/душа/режиссёр — через `fsCloneFor`), **админ-панель** (Атмосфера · Аудирование · Промт · Разделитель · «Пока бот думает»). Настройки — в `store` (`rlm.telegram`: `mode/aud/autoTr/voiceProb/critic/local/sep/sepOn/wait/waitOn`; токен — секрет, в граф не пишется).

Соединяются проводами: **выход (правая розетка) → вход (левая), 1 провод в гнездо**. Провода **сплошные**. **Стиль провода — переключаемый** (`wireStyle`, кнопка `#btn-wire` внизу слева, ключ серверной базы `rlm-wire2`; **дефолт `elbow`**, дефолт не пишется — только явный выбор): `elbow` — ортогональ с прямыми скруглёнными углами (`wirePathElbow`: ломаная по сторонам портов `portDir`, выступ `S`, скругление `roundedPolyPath`/`simplifyPolyline`; **от нижних ножек уходит ровно вниз, потом уголком**) или `curve` — плавная безье (`wirePathCurve`). `wirePath(a,b,wps)` — диспетчер. Рядом — **ползунок прозрачности** (`--wire-op`, ключ серверной базы `rlm-wire-op`). **Узловые точки (waypoints):** у соединения `waypoints[]` (магнит к сетке `snapGrid`); наведение на провод (толстая невидимая `.wire-hit`) даёт «призрак» (`nearestPointOnPath`/`getPointAtLength`), захват создаёт/двигает точку (`bindWireHit`/`bindWaypointDot`; **ПКМ или двойной клик — удалить**), провод идёт через них (`wps` → `roundedPolyPath`/`smoothPath`); сериализуются (`rec.wp`). `#wires` — большой SVG-бокс с `viewBox` 1:1 (хит-тест по проводам по всему холсту; координаты пути = мировые). Розетки бывают **на уровне ноды и построчные** (у плашек/полей) — `portCenter` считает реальную позицию через `getBoundingClientRect` (работает при любом зуме) и отдаёт **сторону подхода** (`side`: right/left/bottom) — ею пользуются оба строителя пути. При протяжке — **магнит**: если отпустил не точно на розетке, цепляется ближайшая подходящая в радиусе (`nearestPort`).

**Чат — живой интерфейс ST+Moonlit прямо в ноде.** Нода `Чат` содержит `iframe` `app/moonlit/chat.html` (настоящий ST+Moonlit), отрисованный в «десктопной» логической ширине (1000×680) и вписанный в ноду `transform: scale(0.64)` (`.chat-stage`) — точная мини-копия полного экрана, при зуме холста разница с полным экраном не видна. По «оку» (`enterImmersive`) камера ныряет к ноде и раскрывается полноэкранный разворот (`#immersive` со своим `#st-frame`), синхронизированный с **тем же диалогом** ноды (`renderChatLogs` шлёт `render` и в ноду, и в разворот).
- `chat.html` — **динамический** рендер из данных (`postMessage {type:'render', msgs, names, avatars}` → `renderMessages`, ST-разметка `.mes`), не статичный тест-диалог. Форматирование реплик (`**жирный**`, `*действие*`, `"речь"`→`<q>`). Стартует пустым.
- **Лента статуса процесса** (зона затенения над вводом, `#rlm-zone` в `chat.html`): единая индикация для всех долгих процессов. Строка `#rlm-proc` (текст этапа по центру + крестик-символ отмены) + полоса `#rlm-proc-bar`; над зоной — мягкое градиентное затенение (`#rlm-zone::before`, поверх фоновой картинки). Полосы рисуются из JS (`setInterval`): `load` — бегущая (подгрузка модели), `pulse` — дыхание (генерация текста/критик), `fill`/`grow` — заливка по доле (Душа по докам, генерация аудио по времени), `done`/`error`/`cancel` — финал, `idle` — гаснет и возвращает ряд кнопок. Приём `postMessage {type:'proc', state, text, frac, cancelable}`; крестик → `proc-cancel` → родитель зовёт `node._procCancel`. **Ошибки идут не в ленту, а в верхний тост `chatToast`.** Родитель шлёт через **`chatProc(node,state,text,opts)`** (в оба кадра — ноду и разворот); подключены `generateReply`/`speakFromChat`/`updateMemory`/`chronicleWrite`/`criticJudge`. Старая `#rlm-tts-bar` убрана; кнопка «Стоп озвучки» убрана (стоп — крестик ленты).
- **Ввод — в поле ST** (`#send_textarea`): iframe шлёт `{type:'send'}` наверх → `chatSend`. Над полем (ряд **слева**, `#rlm-actions justify-content:flex-start`) — кнопки **«Новый чат»** (`newChat`) и **«Перегенерировать»** (`regenerate`, генерация вынесена в общий `generateReply`). **`newChat` спрашивает** (в контексте чата): ОК → **`newChatCopy`** (новый `chatId` = КОПИЯ текущей сборки того же пресета, пустые история/лорбук чата/Душа, текущий чат сохранён целым), Отмена → **`clearThisChat`** (тот же `chatId`, но история + `fillLorebook(chat,[])` + `/api/rlm/soul/purge` — очистка на месте, со вторым подтверждением). Значок «Состояние» в левом ряду ввода — **сердечко** (`fa-heart`). Опции/режим/фон — через **postMessage** (contentDocument при `file://` ненадёжен). Панель опций — из `moonlit-settings.js`, отфильтрована до влияющих на чат, зависит от режима. **Moonlit-опции (`applyOpt`→`post`) уходят в `#st-frame` (вижн).** Плюс своя группа **«Затенение над вводом (RLM)»** (`buildOptions`): ползунки `--rlm-shade-d/-h/-blur` управляют скримом-затенением `#sheld::after` (тёмность/высота/размытие, blur-край); хелперы `rlmShade*` (хранение — ключ серверной базы `rlm.shade`) шлют `{type:'var'}` **во ВСЕ кадры** — `.node-chat .chat-frame` И `#st-frame`, и применяются при загрузке кадра ноды / открытии вижна (`enterImmersive`) — поэтому затенение одинаково в ноде и в вижне.

**Инвариант разворота:** `immersiveNode` обязан указывать на ЖИВУЮ ноду чата. Открытие другого чата пересобирает граф (`restoreGraph` уничтожает ноды), поэтому `enterImmersive` при уже открытом развороте **перенаправляется** на новую ноду (а не выходит по `if (immersiveNode) return`, как было), и общий обработчик команд из кадров подменяет ноду, если она не в DOM. Иначе вижн работал с мёртвой нодой: без проводов (чат отвечал «Подключи ноду API») и со своим `_msgs` (правки и удаления расходились с нодой). **Принцип «нода ↔ вижн» + направление «доступ из чата» (держать в уме).** (1) Нода = живая копия своего вижна (тот же контент мелко; эталон — `Чат` = уменьшенный `#immersive`). (2) Вижн открывается **ТОЛЬКО глазком** (не зумом). (3) **Глазок на самой ноде** (на холсте) → её вижн **полноэкранным оверлеем** (`openLoreFs`/`#immersive`; `openLoreFs`→`fsCloneFor` строит КЛОН на общих данных, сама нода из `#world` НЕ уходит — иначе автосейв в момент показа терял бы её провода). (4) **Открыто ИЗ чата** (значком) → вид ноды **ВНУТРИ контейнера чата**: из ноды чата → над `.chat-stage`, из вижна чата → над `#immersive`. **Нода на холсте НЕ трогается** — в чате строится **ВТОРОЙ ЖИВОЙ экземпляр тем же билдером** (`buildLorebookNode` — один код, правим один раз) на **ТЕХ ЖЕ данных** (`view._entries = master._entries`, общий по ссылке — оригинал и вид не расходятся; правки сразу в ноде и в сохранении). `openLoreInChat(master, chatNode, fromImmersive, selId)`: вид получает `.lore-fs-node`+снят `node-lore` (мимо `.node-lore` запросов; в `serializeGraph` не идёт — тот берёт `:scope > .node` у `#world`), оверлей `.chat-vision` с баром «← Назад»; `closeChatVision` выкидывает вид и обновляет ноду-оригинал (данные общие) + `persistCurrentGraph`. Общий массив держим **in-place** (удаление — `splice`, импорт — `length=0`+`push`), чтобы ссылка не отвязывалась. НЕ на весь экран. Уже так: **📖 «Лорбук чата»** (`.rlm-lore-open` → `lore-open`) и **клик по карточке главы** в Оглавлении (`openChapterInLore` — ещё и выделяет запись). Дальше — по надобности значки к видам других нод (`Режиссёр`/`Душа`) тем же приёмом. Механизм: иконка в `chat.html` → `postMessage` → общий listener `renderer.js` → `openLoreInChat` (или аналог для другой ноды).

«Как не сломать»: чат ST+Moonlit держим **в iframe** — иначе его CSS (широкие селекторы `#chat`, `body.*`) сломает узловой UI RLM.

**Рантайм (граф исполняется).** «Отправить» в `Чат` (`chatSend` = добавить реплику пользователя + `generateReply`; регенерация/«новый чат» тоже через него): найти подключённый `API` (`API.выход → Чат.вход`) → **`await refreshSoulMemory` + `await refreshSemanticLore`** (async-подготовка ДО синхронной сборки: RAG-память в плашку «Память» + близость сцены к semantic/vectorized-записям в кэш лорбука) → взять `messages` из подключённого к входу «Промт» комплитера — обычного `Промт комплитера` ИЛИ `Мультиплей-комплитера` (`completerForApi`); если там `Систем промт` — его текст системным сообщением → сэмплеры из подключённых `Опций` → звонок `rlmApi('/api/rlm/generate')` → ответ в чат. Каждый вызов `rlmApi` пишется в журнал `Консоли` (`consoleLog`/`consoleResolve`); перед звонком `renderScanners()` обновляет `Сканеры`. Сборка промта (`assembleMessages`): `Relative`-плашки по порядку ST, контент плашки — склейка текстов всех входящих проводов (`Персонаж`-поля, `Систем промт`, `Лорбук`); диалог — на месте плашки «История чата», иначе перед пост-историей. **`In-chat`-плашки** идут не в последовательность, а **вставляются в готовый массив на глубину N от конца** (индексы стабильные — вставка от конца к началу; в одной глубине — по «Порядку»). В `Мультиплей-комплитере` те же правила, но **слот-плашки разбираются по тому, кто «на передаче»** (активный персонаж = полная карточка / остальные = Фантом / рассказчик = все полные; Душа+Состояние активного — in-chat), см. `Мультиплей-комплитер` выше. **ST-макросы** (`{{char}}`/`{{user}}` + `{{time}}`/`{{date}}`/`{{newline}}`) разворачиваются `substituteMacros` в **финальных сообщениях перед отправкой** (регистронезависимо; значения имён — из подключённых `Персонаж`/`Персона` через `chatNames`; неизвестный макрос остаётся как есть). `Сканер` показывает уже развёрнутый текст. **Префилл** ноды `Систем промт` пайплайна (`prefillOf`) добавляется **последним сообщением роли `assistant`** (после макросов) — модель продолжает его, но **из готового ответа префилл вырезается** (он только запускает генерацию/ломает отказ; в чат/историю/критик/промты не липнет — так же в Telegram и Транслитере). **Рассуждение модели по умолчанию выключено** (`params.reasoning={enabled:false}`, если явно не задано) — думающие модели (GLM/Qwen) иначе отдают «мысли» вместо ответа и жрут лимит; управление — выпадашка **«Размышления»** ноды `Опции` (`opt-reason`: off/low/medium/high). **После успешного ответа** — `maybeUpdateMemory` (доки памяти) + `maybeUpdateChronicle` (глава Хроники) + **`maybeRunCritic`** (авто-проверка нодой `Критик`, если её режим `every`/`heuristic`; заворот → перекат). Ключевой инвариант — в `node-logic.md`: **промт и сэмплеры отдельны, склеиваются только в момент звонка (нода `API`)**. **Ещё инвариант: ВСЕ служебные промты к модели — на АНГЛИЙСКОМ** (каркас блока «Состояние», заголовки/подписи памяти `[CHARACTER MEMORY]`/`CHARACTER SHEET`, метки Критика/Хроники, имена доков `Diary/Status/World/Psyche/Topics`) — русский от кода в content модели не попадает; русский UI (подписи/описания/типы) в промт не идёт. Старые русские имена доков и файлы трекеров мигрируют (`SOUL_NAME_MIGRATE` на клиенте + `migrateTracker` на сервере).

**Хранилище — СЕРВЕР как единственный источник (модель SillyTavern).** Всё состояние (персонажи/пресеты/чаты/логи/графы/настройки/оформление/ключ API) живёт в серверной базе `server/data/rlm-store/` (файл на ключ, см. «Бэкенд»→`rlm-store.js`). Клиент (`renderer.js`) держит зеркало в памяти — **`db`**, грузит его с сервера при старте (`loadServerStore` — по ключам через `/api/rlm/store/keys`, тяжёлые `rlm.chatgraph.*` пропускает: они подтягиваются лениво `ensureChatGraph` при открытии чата, как ST грузит чат по клику). **`lsGet`** читает ТОЛЬКО из `db` (синхронно), **`lsSet`/`lsDel`** пишут в `db` + на сервер. **localStorage не используется для ДАННЫХ** — ни как хранилище, ни как зеркало/фолбэк (это и была прежняя «костыльность»: откат на localStorage показывал старое). Единственное исключение — `rlm.current` («где я сейчас»), это состояние устройства, а не данные. Обёртка `store` = `{get: lsGet, set: lsSet}` (ключ/настройки `API`, Telegram — обычные ключи базы). Оформление (тема/цвет/провода/затенение/**фон рабочего пространства**) — тоже обычные ключи базы (`rlm-style`/`rlm-preset`/`rlm-wire2`/`rlm-wire-op`/`rlm.shade`/`rlm-bg`/`rlm-bg-op`), **одна сессия на все устройства**; `apply*`-функции пишут в базу только по действию пользователя (флаг `save`), после загрузки базы применяются через `initUiFromDb()`. **Фон рабочего пространства** (кнопка «Фон» в шапке): слой `#workspace-bg` (`z-index:0`, над непрозрачным градиентом `body`, но под сеткой `#viewport` и нодами — сам `#viewport` прозрачен), арт из `app/loading/RLM1..5.png` (5-й — арт с ⚙-логотипом) + прозрачность (`applyWorkspaceBg`/`applyWorkspaceBgOpacity`). **Одна сессия:** любое устройство (ПК/телефон по LAN/Termux) видит одни и те же ДАННЫЕ, т.к. всё на сервере. **Но не позицию:** какой чат/пресет открыт (`rlm.current`) — состояние устройства (localStorage), телефон и ПК могут сидеть в разных чатах. **Старт под экраном загрузки:** пока грузится база, поверх всего — сплэш `#rlm-splash` (арт `app/loading/RLMn.png`, случайный из 5; полоска прогресса по реальной загрузке ключей; холст строится ПОД ним — без мелькания старого вида, гаснет по готовности). `boot` **ждёт сервер до ~60с и переподключается сам** (движок ST при холодном старте поднимается долго; гард `_booting`); **только если за минуту не ответил — экран `#server-down`** (без тихого показа старых данных, кнопка «Повторить»). *(Исключение: `rlm.tts.dtype` — PC-only железная настройка точности TTS — остаётся в файловом `window.rlm.store`; мобильный режим не хранится нигде — это вид устройства, в браузере авто по экрану.)*

**Сборка + система пресетов.** Граф сериализуется (`serializeGraph`): ноды (тип/позиция/свёрнутость/значения; у `api`/`options` теперь и `label`) + провода по **семантическим ключам портов** (`plate:<id>`, `field:<id>`, `doc:<id>`, `in:prompt|options|neuro|lastmes`, `out:chronicle`, `out`/`in`). **Самовосстановление провода API → Чат** (`ensureApiWired`, зовётся после `restoreGraph` рядом с `ensureObjectiveWired`): если у ноды «Чат» на входе НЕТ ни одного провода, а нода `API` в графе есть — соединяем автоматически (предпочитаем API, который ещё никуда не ведёт), перерисовываем и сохраняем. Занятый вход не трогаем — чужой конвейер (Telegram/мультиплей) остаётся как есть. Иначе снимок, доехавший без связей, давал в чате «нет ноды API». **Восстановление связей (`restoreGraph`) устойчиво к async-разметке нод:** если порт (плашка/док) ещё не построен к моменту восстановления, провод НЕ выкидывается молча, а дособирается повтором (`retryPendingConnections`, до 8 попыток). Плюс `persistCurrentGraph` **не затирает связный снимок графом БЕЗ проводов** (страховка от бага-гонки «25 нод, 0 связей»: раньше выкинутый на загрузке провод сохранялся автосейвом навсегда). **Пресет = сохранённая сборка:** `rlm.presets` (список `{id,name}`, верхний = **дефолт**), граф пресета — `rlm.preset.<id>`; у чата свой снимок — `rlm.chatgraph.<id>`; текущий контекст — `rlm.current` (`{mode:'preset'|'chat', presetId, charId, chatId}`). **Контекстное 💾** (`saveCurrent`): открыт пресет → пишет пресет (у безымянного спросит имя); открыт чат → снимок чата. **Инвариант: любой снимок сначала сливает открытый вижн в мастер** (`flushVisionsBeforeSnapshot` = `flushOpenVision` чат-вижна + `flushOpenGlazokVision` разворота-по-глазку `loreFsState`) — иначе правки, сделанные в развороте и НЕ закрытые (напр. голос/транскрипт ноды `Озвучка`), терялись при 💾; зовётся в `savePresetGraph`/`saveCurrent`/`savePresetAsNew`/`persistCurrentGraph`/`persistLayout`. `btn-save`→`saveCurrent`, `btn-open`→перечитать контекст, `btn-reset`→пересобрать дефолт-пресет. **Авто-персист** `persistCurrentGraph()` — тихо пересохраняет снимок графа **только в режиме чата** (пресет не трогаем) после программных/ручных правок лорбука: запись главы `Хроникой`, добавить/удалить запись, импорт JSON, завершение правки поля записи (`change`). Так главы и правки лорбука переживают перезапуск без 💾; **в режиме пресета** правки лорбука по-прежнему требуют 💾. *(Легаси: `ensurePresets` ещё умеет поднять старый `rlm.graph` в дефолтный пресет, если такой ключ есть в базе — на практике его там нет.)* **`buildDefaultPreset`** строит **ЧИСТЫЙ** дефолт (`Персонаж` без демо-имени, `Лорбук`/`Режиссёр` без демо-записей — `LOREBOOK_ENTRIES`/`DIRECTOR_EVENTS` пустые): пайплайн `Персонаж → Комплитер → API → Чат` (+ `Опции`), RLM-слои (три `Лорбук`а / `Душа` / `Режиссёр` / `Эмбеддер`, промты доков — ВНУТРИ ноды `Душа`, отдельных нод под них нет), **`Хроника`** (связи `Чат.out:chronicle → Хроника → Лорбук чата`), **+ блок перевода**: `Транслитер` (оба режима на «Нейро») + отдельные `API · перевод` + `Опции · перевод` → коннектор `in:neuro`. Ключ API — в серверной базе (`rlm.apiConfig`), не в графе. `Сканер` в пресет **не входит**; `Консоль` — вообще не нода (оверлей поверх холста, кнопка в тулбаре).

**Стартовое меню + пресеты (`#start-menu`, открывается на старте и по ☰; старый выпадающий `#char-menu` убран).** Слева — список **пресетов** (`startMenuRender`: верхний = дефолт ★, ▲ `makeDefaultPreset`, ✕ `deletePreset`, ＋ `newPreset` — имя при первом 💾, двойной клик `openPreset` грузит голый граф). Справа — **экраны** (`smView`: `grid`/`char`/`books`/`browse`), переключаются **верхними вкладками** `Персонажи · Лорбуки · 🌐 Каталог сайтов` (`.sm-tabs`, подсветка `updateTabs` по `smView`; «Каталог» и «Персонажи» переехали сюда из шапки сетки). Справа в ряду вкладок — **`#sm-restart` «⟳ Перезапуск»** (`window.rlm.restart`, как `#btn-restart` тулбара; скрыт вне Electron). **(1) Сетка карточек** (`startMenuRender`, `#sm-grid-view`): компактные плитки **аватар + имя под ним**, прокрутка + крупный скроллбар, размер аватаров кнопками **−/＋** в шапке (`smAvaBump`, `rlm.smAvaSize`); первая плитка ＋ грузит карточку во ВСЕ `.node-char`; **✕** (при наведении) — `deleteCharacter` (с чатами/логами/снимками/памятью). **(2) Меню персонажа** (`openCharMenu`/`renderCharMenu`, `#sm-char-view`) по клику на аватарку: слева аватар + список чатов (＋новый/открыть/✕удалить), справа — **все окна карточки** отдельными панелями, даже пустыми (`cardFieldsHtml`: поля `CARD_FIELDS` + авторское `creator_notes` заметным блоком сверху + встроенный лорбук `parseLorebook`). **(3) Каталог сайтов** (`openBrowse`, `#sm-browse-view`) — см. «Каталог карточек» ниже. **(4) Лорбуки** (`showBooks`/`renderBooksGrid`, `#sm-books-view`) — библиотека **ворлд-буков** (см. «Ворлд-буки» ниже). **Новый чат** `createNewChat` → дефолт-пресет + `applyCharacterToNodes` (карточка + аватар) + свежий `_chatId`. **Открытие** `activateChat` → `loadChatGraph` (снимок чата или дефолт-пресет) + карточка + сообщения. Хранение — **серверная база** `rlm-store` (см. «Хранилище»), ключи: `rlm.characters`, `rlm.chats.<charId>` (с полем `preset`), `rlm.chatlog.<chatId>`, `rlm.chatgraph.<chatId>`, `rlm.presets`, `rlm.preset.<id>`, `rlm.current`, **ворлд-буки** `rlm.worldbooks` / `rlm.worldbook.<id>` / `rlm.activeWorldbook`. **Очистка карточки в ноде** — `clearCharCard` (кнопка «✕ карточка»): чистит ноду + лорбук персонажа + чат; `applyCard` при карточке без лорбука тоже чистит лорбук персонажа. **Отложено:** «модель в файл чата» (новый чат без модели, ключ глобально). *(Серверный персистенс — СДЕЛАН: всё на сервере, одна сессия.)*

**Каталог карточек (внешние сайты).** Серверный модуль `server/src/endpoints/rlm-cards.js` (маршруты `/api/rlm/cards/search|tags|card|image|lorebook`, монтируются **ДО CSRF** в `server-main.js`, под whitelist) — прокси к сайтам карточек, т.к. холст на `file://` к ним напрямую не ходит (CORS+CSP), а картинки отдаём **data:-URL** (`img-src data:`; host-allowlist `IMG_HOSTS`). **Три источника** (`source`): `chub` (`api.chub.ai/search` + сборка TavernCardV2 как `downloadChubCharacter`), `tavern` (`character-tavern.com/api/search/cards` + PNG `ct-cards.storage…` со встроенной `chara`/`ccv3` + лорбук по `CT_id`), `risu` (**RisuRealm**: SvelteKit `__data.json` → распаковщик `devalue`; прямой PNG-v3 `…/api/v1/download/png-v3/<uuid>`). Нормализация в `{source,id,name,author,tagline,blurb,tags,downloads,likes,nsfw,hasLorebook,thumb}`. UI (`openBrowse`/`browseSearch`/`browseMore`/`browseOpenCard`/`browseDownload`): вкладки-источники, поиск, теги (**свёрнуты в одну кнопку** «Теги (N)», выбранные — чипами рядом, `browseRenderSelected`), сортировка Популярное/Новое (`smBrowseSort`; у risu «новое» = trending), 18+, **авто-перевод** (тумблер `smAutoTr` + провайдер `smAutoTrProv` google/yandex; store `rlm.cards.autotr`/`…prov`) — **описаний** (`browseAutoTranslate`, `.sm-res-desc`=`blurb/tagline`, последовательно, кэш `_smTrCache`, оригинал в `data-orig`) **и подписей тегов** (`browseTranslateTags` пачками по 40 через `\n`-join, кэш `_smTagTr`, применяет `browseApplyTagLabels`; значение `data-tag` для поиска остаётся англ.), «Показать ещё» (`smBrowsePage`), пометка «✓ скачано» (`browseDownloadedSet` по `srcId`/имени), **миниатюры через `/image` с серверным ресайзом** (`proxyImage(url, maxW=480)` через Jimp — webp/png/jpeg; chub-источник миниатюры — `max_res_url`, не мелкий `avatar_url`; деталь-обложка — в полном качестве). Деталь — `cardFieldsHtml` (общий с меню персонажа) + перевод **каждого блока** (Яндекс, `/api/rlm/translate`) + «↗ Страница на сайте» (`window.rlm.openUrl` → `shell.openExternal`) + «⬇ Скачать в библиотеку» (`registerCharacter`, проставляет `srcId`). Разбор карт из PNG — `cardFromPng` (tEXt/zTXt/iTXt, ключи `chara`/`ccv3`). **Подгруппа «Лорбуки»** (`smBrowseKind`, переключатель «Персонажи/Лорбуки»): у **chub** есть отдельные лорбуки (`chubSearch({kind:'lorebook'})` → `namespace=lorebooks`, items `kind:'lorebook'`, `id='lorebooks/author/slug'`); записи — `chubLorebook(fullPath)` (`node.definition.embedded_lorebook`) через маршрут `/lorebook`. В режиме «Лорбуки» источник форсится на chub (у Tavern/Risu отдельных лорбуков нет). Клик → `browseOpenLorebook` (просмотр записей), «⬇ Скачать в World Info» → `browseDownloadLorebook` создаёт **ворлд-бук** (не персонажа), пометка скачанного — `worldbookDownloadedSet` по `srcId`. *(janitorai НЕ поддержан: Cloudflare 403 и на поиск, и на экспортёр jannyai + определения скрыты by design.)*

**Ворлд-буки (World Info на постоянке).** Отдельная библиотека МИРА (не персонаж, не пресет; это про ноду `Лорбук мира`, а не лорбук персонажа): вкладка «Лорбуки» стартового меню (`renderBooksGrid`, `#sm-books-view`) — карточки как у персонажей (обложка+имя, ＋создать `newWorldbook`, ✎ `renameWorldbook`, 🖼 обложка, ✕ `deleteWorldbook`), одну можно сделать **активной галочкой** (`toggleActiveWorldbook`; можно ни одной). **Активный ворлд-бук → в ноду `Лорбук мира`** на любой чат: `applyActiveWorldbook` заполняет `loreNodeByScope('world')` при `createNewChat`/`activateChat`; не выбран — `Лорбук мира` из графа, как раньше. **Просмотр/правка «как вижн»** (`openWorldbook`): переиспользуем детач-ноду `buildLorebookNode()` в скрытом хосте + `openLoreFs`, автосейв записей в ворлд-бук (`closeLoreFs` сохраняет и выкидывает ноду; класс `.wb-node` прячет холстовую обвязку — порты/область/эмбеддер/глазок/кнопку выбора). В ноде `Лорбук мира` (и её вижне) — кнопка **«🌐 Ворлд-бук»** (`.lb-wb`, `loreWbSync` показывает только для scope=world) → пикер `openWbPicker` → `setActiveWorldbook`. Хранение — `rlm.worldbooks [{id,name,cover,srcId?}]` / `rlm.worldbook.<id> {entries}` / `rlm.activeWorldbook`. Записи можно **скачать из каталога** (chub, см. «Каталог»).

**Тулбар — имя контекста + сохранение.** Крошка `.tb-center` = имя текущего пресета/чата (`updateCrumb`), **клик по имени → инлайн-переименование** (`beginCrumbRename`; пресет → `rlm.presets`, чат → `rlm.chats.<charId>`). **В шапке вижна — то же имя чата по центру** (`#im-chat-name`, `updateImChatName`): клик → инлайн-переименование `beginImChatRename` (пишет через общий `renameChatRecord`, зовёт `updateCrumb` → имя синхронно и в крошке, и в вижне; тулбар в погружении скрыт, потому имя дублируется тут). `updateImChatName` зовётся из `updateCrumb` и `enterImmersive`. В режиме чата **дискета `#btn-save` скрыта** (всё сохраняется само); в пресете 💾 открывает меню **«Сохранить поверх» / «Сохранить как новый»** (`savePresetAsNew`). На мобиле (класс `mobile-mode` / `@media ≤720px`) крошка-имя видна (без «RLM /»), а «Стиль» уходит в меню **⋮ `#tb-more`**. **`window.prompt` в Electron не работает** → свой диалог **`rlmPrompt(title, initial, cb)`** (используется в создании/переименовании ворлд-бука и наименовании пресетов; `confirm`/`alert` в Electron работают, их не трогаем).

**«Новый чат» и лорбуки** (`resetCharScoped`, зовётся из `createNewChat`): `Лорбук чата` — пусто (память сцены с нуля), `Лорбук персонажа` — дефолт из карточки (`character_book`, перекрывает ручные правки; нет лора → пусто), **`Лорбук мира` НЕ трогается** — держится пресетом/активным ворлд-буком. **Нода `Озвучка` тоже НЕ сбрасывается** — новый чат берёт граф активного пресета (`loadPresetGraph`), поэтому настроенный в пресете голос/транскрипт перетекает в новый чат; `resetCharScoped`/`applyCharacterToNodes` её не трогают. Промты/сборка не меняются; свежий снимок пишется сразу (`persistCurrentGraph`).

**Темы оформления.** Цвет — CSS-переменные на `:root` (пресеты «Цвет»: синий/графит). **Стиль** — отдельная кнопка в шапке, переключает класс `theme-ref` на `<html>`: «Терминал» (наш) ↔ «Референс» (Langflow-подобный: пресет «Уголь · коралл» + структурный CSS — без угловых засечек, острые углы, обычный регистр, разноцветные иконки по типу ноды). Сетка холста при этом остаётся **линиями** (её задаёт `--grid`). Выбор стиля/цвета — в **серверной базе** (`rlm-style`, `rlm-preset`), одна сессия на все устройства.

**Лимиты токенов — единый реестр.** Числа `max_tokens` (и «сколько в контекст») больше не разбросаны по коду: реестр `TOK_REG` в `app/renderer.js` описывает каждую строку — ключ, нода-хозяин, подпись, дефолт и (если значение живёт в поле ноды) селектор поля. Правки зашитых лимитов лежат в базе под `rlm.tokenLimits`, сохранённые наборы — под `rlm.tokenPresets`; читается всё функцией `tokVal(key, def)`. UI — вкладка «🎚 токены» в Консоли: строки рисуются только для нод, присутствующих в сборке, полевые значения правятся прямо в ноде.

**Размер контекста — общий потолок промта.** Поле «Контекст, ток.» ноды `Опции` было мёртвым (`param:null`), теперь это настоящий лимит. `contextLimitFor(compEl)` берёт его у ноды `Опции` ТОГО конвейера, куда воткнут комплитер (комплитер → API → Опции; фолбэк — любая нода `Опции`), но сначала смотрит своё значение из таблицы (`ctx.limit`). Обрезание стоит в ОДНОЙ точке — `rlmApi('/api/rlm/generate')`: `trimToContext(messages, limit)` выкидывает **самые старые реплики истории** (сообщения БЕЗ метки `_src`), системные блоки и постановку задачи подсистемы не трогает. Подсистема может иметь свой контекст: вызов передаёт `body._ctxKey` (например `soul.think`), лимит ищется как `ctx.<ключ>` и перебивает общий; служебное поле снимается в `stripUiFields` и в модель не уходит. В таблице у каждой строки в токенах есть своё поле контекста (`.con-tok-ctx`, ключ `ctx.<k>`): пусто — placeholder показывает наследуемое число, вписанное — сплошная рамка. Колонки подписаны шапкой `подсистема · ответ · контекст`; строки не в токенах (шт./реплик) поля контекста не имеют.

**Счётчик токенов.** `approxTokens()` — оценка без токенизатора (кириллица ~2.6 симв./ток., латиница ~4), поэтому везде «≈». `promptTokenStats`/`paintPromptTokens` считают по плашкам комплитера (`plateContent`) + историю чата отдельно: бейдж `.pm-tok` на каждой плашке, итог `.pm-tok-total` в шапке ноды («≈всего / лимит», краснеет при превышении). Пересчёт — `schedulePromptTokens()` (debounce 400 мс) из `persistCurrentGraph` и после загрузки графа. В шапке Консоли — `renderConsoleTokens()`: «ушло ≈N» (реально отправленный промт, `compEl._lastSentTok`) «· сейчас ≈M / лимит».

**Доставка настроек на сервер.** `lsSet` → `storeSetFlush(key)` с очередью `_setPending`. Если отправка не отвечала (обрыв/зависший fetch), флаг `busy` оставался поднятым **навсегда** и ключ больше не сохранялся — правки жили только в открытой вкладке (поймано на `rlm.tokenLimits`). Теперь `busy` с меткой времени: через 20 с считается мёртвым, отправка повторяется.

## Бэкенд RLM (свой сервер на моторе ST)

RLM — **своё приложение на моторе SillyTavern** (решение Р-9): мотор ST лежит копией в `server/` проекта, и это **наш код** (правим напрямую), а не чужой ST рядом.

- **Запуск:** `server/` — копия ST 1.14.0 (исходники без `node_modules`/бэкапов; свои чистые `data/`; `soul-md` перенесён). Порт **8100** (эталонный ST пользователя на 8000 не трогаем; автозапуск браузера выключен). `main.js` Electron **сам поднимает сервер**, если не запущен, и гасит при выходе.
- **Наш маршрут** `server/src/endpoints/rlm.js` — звонок к провайдеру от лица ноды `API`:
  - `POST /api/rlm/models` `{base,key}` → проверка связи + список моделей (`GET {base}/models`).
  - `POST /api/rlm/generate` `{base,key,model,messages,params}` → генерация (`POST {base}/chat/completions`). Ответ: `{ok, text, content, reasoning, finish_reason, usage}` — **`content` (чистый ответ) и `reasoning` («мысли» reasoning-моделей) отдаются РАЗДЕЛЬНО**; `text=content||reasoning` (обратная совместимость: старые вызовы, где ответ реально лежит в `reasoning_content`). Вызывающий, кому нельзя мешать мысли в ответ (приглашение гостя), берёт `content`.
  - `POST /api/rlm/complete` `{base,key,model,prompt,params}` → text-completion (`POST {base}/completions`) — «ядерный режим» ноды `Критик` (не chat, а продолжение документа).
  - **Автоповтор без `reasoning`** (`postWithReasoningFallback`, общий для `/generate` и `/complete`): RLM почти везде просит `reasoning:{enabled:false}` (мысли едят лимит вывода), но часть эндпоинтов отвечает 400 «Reasoning is mandatory for this endpoint and cannot be disabled» — тогда тот же запрос уходит повторно **без поля `reasoning`**. Распознаётся строго по тексту ошибки (`reasoningForced`), прочие ошибки не повторяются. Мысли при этом приходят и отдаются отдельным полем, вызывающий берёт `content`.
  - `POST /api/rlm/translate` `{provider,text,to}` → перевод **без ключей** (как в ST): `google` (`google-translate-api-browser`), `yandex` (free), `bing`. Нейро-перевод идёт не сюда, а через `/generate`.
  - Путь **OpenAI-совместимый** (Bearer-ключ), с таймаутом. Врезан в `server-main.js` **до CSRF/логина** (под whitelist) — чтобы холст звал простым POST. Anthropic/Gemini прямые — адаптерами позже.
- **Маршруты памяти** `server/src/endpoints/rlm-soul.js` (`/api/rlm/soul/*`, тоже **до CSRF** — плагин `soul-md` за CSRF, холст до него не достучится):
  - `POST /chats` → папки памяти (для выбора во вьюере `Души`).
  - `POST /all {chat}` → все MD-доки + темы с текстом (листалка вьюера).
  - `POST /diary {chat,query,k}` → **RAG по дневнику** (эмбеддинг запроса vs записей, top-k, обрезка «хвостом» — стиль Soul of Waifu).
  - `POST /topics {chat,query,k}` → RAG по темам.
  - `POST /doc-save {chat,group,name,text}` → перезаписать файл записи (ручная правка из ноды `Душа`; тема — в подпапке `topics/`). `POST /doc-del {chat,group,name}` → удалить файл записи. `POST /purge {chat}` → стереть всю папку памяти чата.
  - Векторы — родной `getTransformersVector` (модель из конфига, e5-префиксы). Данные — папка плагина `plugins/soul-md/data/<чат>/`.
- **Раздача холста по сети** (`server-main.js`): `app.use('/rlm', express.static(<корень>/app))` — сервер отдаёт папку `app/` по HTTP на **том же origin** (8100), чтобы холст открывался с телефона в локальной сети: `http://<ip-ПК>:8100/rlm/`. Тот же origin выбран из-за CSP холста (`connect-src 'self'`): относительные `fetch('/api/rlm/*')` проходят без CORS. Смонтировано **до** `requireLoginMiddleware`, под общим whitelist.
- **Доступ по сети (whitelist из приложения)** `server/src/endpoints/rlm-net.js` (`/api/rlm/net/*`, **после** whitelist-middleware — менять список может только уже разрешённое устройство; loopback разрешён всегда): `POST /info` (адрес для телефона, IP клиента, список), `POST /add`/`POST /remove` `{entry}` (IP/подсеть, валидация `ip-matching`). `middleware/whitelist.js` даёт `getWhitelist`/`setWhitelist` — список **мутируется на месте** (применяется без перезапуска) и сохраняется в `server/whitelist.txt` (штатно перекрывает `whitelist` из `config.yaml`). UI — панель «Доступ по сети» в стартовом меню.
- **Первый запуск: установка движка** — окно создаётся ДО подъёма сервера (`app.whenReady`: `createWindow()`, затем `ensureServer()` без await). Нет `server/node_modules` → `installServerDeps()` гонит `npm install --omit=dev` и шлёт состояние в окно (`rlm:setup`, плюс `setup:state` по запросу — сообщение могло уйти до готовности страницы): пакеты считаются `readdir` каждые 0.5 с, мегабайты — обходом дерева раз в 2.5 с, туда же последняя строка npm. В `renderer.js` за это отвечает блок «ПЕРВЫЙ ЗАПУСК» (`setupWatch`/`setupRender`/`setupSound`): плашка `#rlm-setup` поверх заставки, фоном ролик через `updateClips([...])`, тема на повторе и голос один раз из `app/media/` (автоплей разрешён ключом `autoplay-policy` в main.js), ползунок громкости — внизу у номера сборки (`#rlm-splash-snd`). Пока `_setupActive`, цикл ожидания в `boot()` не считает попытки, поэтому экран «нет связи» не всплывает.
- **Обновление сборки с GitHub** `server/src/endpoints/rlm-update.js` (`/api/rlm/update/check|apply|progress`, **после** whitelist — перезаписывать файлы приложения может только доверенное устройство). Живёт на сервере, а не в Electron, потому что в Termux Electron'а нет вовсе. `check` сравнивает метку `BUILD.txt` в корне сборки с такой же в репозитории (raw, таймаут 6с; нет файла = рабочая папка → механизм выключен). `apply` берёт дерево GitHub с git-хэшами (`git/trees/main?recursive=1`), сверяет с локальными файлами (**вторым заходом по нормализованным переносам** — git на Windows разворачивает LF в CRLF, иначе полторы сотни нетронутых файлов считались бы изменившимися; переносы правятся по байтам, чтобы не портить `.bat` в кодировке DOS) и качает только разошедшиеся, по 6 потоков, с проверкой хэша скачанного и атомарной записью. `allowPath` держит границу: из `server/data/` берутся только стартовые пресеты, `rlm.presets.json` **сливается** (заводские id из репозитория + свои), память Душ и личные заметки не трогаются. Смена `server/package.json` тянет `npm install --omit=dev`. Показ — блок «Обновление сборки с GitHub» в `renderer.js` (`updateCheckStart` пускает проверку сразу после загрузки базы, `updateGate` перед `Splash.finish()` доводит полоску до 100% и задаёт вопрос). Перезапуск после обновления: ПК — существующий `appRestart`, Termux — `rlm-app.js` при `RLM_RELOOP=1` выходит с кодом 42, а `start-termux.sh` крутит сервер в цикле.
- **Серверная база = ЕДИНСТВЕННЫЙ источник (одна сессия на все устройства)** `server/src/endpoints/rlm-store.js` (`/api/rlm/store/get|set|setmany|del|keys`, **после** whitelist): KV-хранилище, каталог `<dataRoot>/rlm-store/`, **один файл на ключ** (`encodeURIComponent(key).json`) — частые правки (лог чата) переписывают только свой файл. `POST /keys` отдаёт список ключей (грузить базу по ключам, а не монолитом ~16 МБ, иначе телефон давится). Клиент (`renderer.js`): зеркало базы в памяти **`db`** — `loadServerStore` на старте тянет ключи через `/keys` (**тяжёлые `rlm.chatgraph.*` пропускает** — подтягиваются лениво `ensureChatGraph` при открытии чата, как ST грузит чат по клику). `lsGet` читает ТОЛЬКО из `db` (синхронно), `lsSet`/`lsDel` пишут в `db` + на сервер. **`lsSet` дедуплицирует:** зеркало `db` обновляется всегда, но одно и то же значение ключа на сервер повторно НЕ шлётся (строковая сигнатура `_lsSig`; `lsDel` её сбрасывает) — иначе перерисовки давали поток одинаковых `/api/rlm/store/set` (напр. лог чата слался ~37× за заход). **Синхронизация между устройствами (стандартная схема).** Данные общие на сервере, «где я сейчас» — своё у каждого устройства. Четыре правила: **(1) Гарантированная запись.** `lsSet` не «выстрелил и забыл»: неподтверждённое значение висит в очереди `_setPending[key]` и переотправляется с нарастающей паузой (0.5→1→2→…→30с) плюс добор раз в 15с, пока сервер не ответит `ok`; в очереди всегда самое свежее значение. Отдельная такая же очередь у лога чата (`_chatlogPending`, `chatlogFlush`/`chatlogRetry`) — она же ведёт `_chatDirty` (снимается только по подтверждению). Раньше сбой сети терял граф чата, лорбук, пресет и реплики МОЛЧА. **(2) Синхрон НИКОГДА не укорачивает историю.** `pullChatlogFresh` тянет лог прямо с сервера (`storeGetRetry`, минуя boot-зеркало) перед мутирующими командами (`MUTATES_LOG`), при открытии чата, при возврате к окну (`visibilitychange`/`focus` → `resyncOpenChat`, троттлинг 1.5с) и тихо раз в 20с, пока чат открыт. Сервер **короче** локального → он отстал: держим своё и дожимаем наверх; **равной длины, но другой текст** → принимаем только если своё уже сохранено; **длиннее** → принимаем. Перед заменой прежняя версия кладётся в резерв `rlm.chatlog.<id>.bak` (с меткой времени). Уход в фон — `flushDirtyChat` дожимает хвост через `fetch keepalive`, но только при `_chatDirty`. **(3) «Где я сейчас» — состояние УСТРОЙСТВА.** `rlm.current` (открытый чат/пресет) **читается** только своё, из `localStorage` (`loadCurrentLocal`/`saveCurrentLocal`) — устройства друг друга не перебрасывают; серверная копия при этом **продолжает обновляться** (`setCurrent` пишет в оба места) и служит СИДОМ для первого входа на новом устройстве. *(Когда серверную копию перестали писать вовсе, она застыла — и телефон при первом запуске открывал давний чат: отсюда была жалоба «нет соединения с API».)* Иначе телефон, открыв чат, перебрасывал туда и ПК. Это ЕДИНСТВЕННОЕ исключение из «localStorage не используется» — не данные, а позиция сессии. **(5) Пишет только ПОСЛЕДНИЙ подключившийся клиент.** Правила 1–4 спасают от обрывов связи, но не от клиента со СТАРЫМ состоянием в памяти: забытая вкладка или телефон отправляли своё вчерашнее и стирали свежую игру молча (так пропал чат 2026-09-02). Теперь сервер (`rlm-store.js`) держит одного владельца записи: `POST /claim {clientId}` объявляет клиента активным, `POST /owner` говорит, кто он. `set`/`setmany`/`del` идут с `clientId`; чужой получает `{ok:false, error:"not-owner"}`, файл не трогается. **Чтение (`get`/`keys`) не ограничено** — поэтому новый клиент подхватывает ровно то, что успел наиграть прежний. Клиент (`renderer.js`): `RLM_CLIENT_ID` рождается на каждую загрузку страницы, `storeClaim()` зовётся в начале `boot` (до чтения базы); ответ `not-owner` → `storeLostOwnership()`: флаг `RLM_VIEW_ONLY` глушит запись в `storeSetFlush`, очередь `_setPending` чистится, почтальоны Telegram останавливаются, снизу появляется плашка `#rlm-viewonly` с кнопкой «Играть здесь» (`storeClaim` + `location.reload()` — перечитать свежее, иначе положим поверх своё старое). Клиент без `clientId` (старая сборка) не отшивается. **(6) Копии перед перезаписью (сервер).** Клиентский .bak (пункт 2) делается только когда клиент ПРИНИМАЕТ серверную версию — от кривой ЗАПИСИ он не спасает. Поэтому копию кладёт сам сервер в rlm-store/_backups/ перед каждой перезаписью файла: логи чатов — при каждой записи, но не чаще раза в 10 с; любой ключ, если новое значение короче 60% старого («усушка») — всегда, с пометкой -shrink в имени; лишние копии подчищаются (50 на чат, 10 на прочие ключи). Подкаталог не попадает в /keys, клиенту копии не грузятся. Схема взята у ST (backups/ + троттлинг + numberOfBackups), но там она страхует чат, а у нас — любой ключ базы. **(7) У истории один хозяин.** История одиночного чата живёт ТОЛЬКО в `rlm.chatlog.<id>`; в снимок сборки
она больше не пишется (`nodeValues` типа `chat` отдаёт `chatId`/`scene`, но не `msgs`) — раньше копия в снимке
воскрешала удалённое, а пресет, сохранённый из чата, при загрузке затирал лог ДРУГОГО чата. История партии
Telegram живёт только в снимке (`convos` ноды) и дописывается единственной дверью `tgAddMsg`: положила реплику —
сразу сохранила (раньше дописывание шло из пяти мест, и в трёх сохранение забыли). Пометки Хроники
(`chrScene`/`chrHidden`), «докуда свёрнуто» (`_highest`), счётчики Цели и Души, имена тем/чатов, правка заявки
игрока и переименование участника теперь тоже сериализуются — раньше каждый перезаход их сбрасывал.

**(8) Выход не рвёт запись.** `main.js` держит `before-quit`: первый выход откладывается, окну уходит `app:flush`,
главный процесс ждёт `app:saved` (или 4 с) и только потом выходит — это покрывает крестик, Alt+F4, «Закрыть» и
меню. `app:restart` перед `relaunch` дожимает состояние и ГАСИТ свой сервер (иначе он переживал перезапуск и
работал на старом коде). В рендерере `flushBeforeExit` дожимает обе очереди (`_setPending` и `_chatlogPending`),
`charEditFlush` и открытый вижн комплитера (`flushVisionsBeforeSnapshot(true)`). `pagehide` и уход вкладки в фон
шлют снимок `fetch(keepalive)` напрямую, минуя мост. Файловый store главного процесса (`rlm-store.json`: ключ API,
`rlm.tts.dtype`) пишется атомарно и держит `.bak`, битый — поднимается из копии.

**(9) Сессия: право записи.** Берётся ПРИ ПОДКЛЮЧЕНИИ (`storeClaim` после успешной загрузки базы) и возвращается
при возврате фокуса к окну; молчащий владелец теряет право через 45 с (`mayWrite` продлевает `since` на каждой
записи). Прежний клиент уходит в просмотр с плашкой `#rlm-viewonly`. `?ro=1` открывает холст НАБЛЮДАТЕЛЕМ —
читает, но `claim` не делает: нужно, чтобы проверочная вкладка не глушила играющего.

**(10) Кто пишет: все.** Блокировки клиентов нет — любой клиент (ПК, телефон, вкладка) отправляет
изменения сразу. `mayWrite` (rlm-store.js) только отмечает активного, запись не режет. От затирания
защищает `mayShrink`: значение с МЕНЬШИМ числом сообщений, чем лежит на диске, не принимается —
ответ `{ok:true, skipped:"shorter"}`; намеренное укорачивание (удаление реплики, обрезка, очистка)
клиент помечает `shrinkOk:true` (см. `allowShrink` в renderer.js) и оно проходит. Счёт сообщений —
`msgCount`: у лога чата `msgs`, у снимка сборки — истории всех бесед ноды партии.

**(11) Ответ модели пишет сервер.** В `/api/rlm/generate` клиент передаёт `_saveTo: { key }` (ключ лога
этого чата). После успешного ответа `saveReplyToChatlog` (server/src/endpoints/rlm.js) сам дописывает
реплику в файл: заменяет последний плейсхолдер «…», не двоит уже записанный текст, пишет атомарно.
Это делает историю независимой от вкладки: телефон может уснуть или потерять сеть посреди генерации.

**(12) Чего в клиенте больше НЕТ** (снято, потому что ломало сохранение): мьютекса «идёт запись»
(залипал → снимок переставал сохраняться), гарда «не писать, пока `graphLoading`» (флаг залипал, если
восстановление связей не дошло до конца → не писалось ничего; сам флаг теперь снимается через 20 с),
проверок «снимок без проводов» и «пустая история поверх непустой» — их роль выполняет правило сервера.
Осталась одна клиентская проверка: снимок не пишется, пока `_chatId` ноды-хозяина не совпал с
`current.chatId` (иначе граф одного чата уезжает под ключ другого).

**(4) Свежесть на чтении.** Снимок графа чата **всегда перечитывается** при открытии (`ensureChatGraph` больше не отдаёт из кэша — иначе ПК показывал старую расстановку и затирал правки с телефона; сервер молчит → работаем с локальным). Лёгкие ключи (персонажи, списки чатов, пресеты, ворлд-буки) перечитываются при открытии стартового меню (`refreshLightKeys`, свои неотправленные правки не затираются). **`/api/rlm/store/*` в ноду «Консоль» НЕ логируется** (`rlmApi`/`CONSOLE_QUIET`) — персистенс это служебный шум, не вызов модели. **localStorage НЕ используется** — ни фолбэк, ни зеркало, ни миграция (сервер = источник истины; нет связи → экран `#server-down`, `boot` с ретраями). **Одна сессия:** персонажи/пресеты/чаты/логи/графы/настройки/ключ API/**оформление** (`rlm-style`/`rlm-preset`/`rlm-wire2`/`rlm-wire-op`/`rlm.shade`) — всё общее. НЕ в сессии: `rlm.tts.dtype` (PC-only, железная настройка TTS — остаётся в файловом `window.rlm.store`), мобильный режим (вид устройства — нигде не хранится, в браузере авто по экрану).
- **Как холст достаёт сервер:** в **Electron** страница на `file://` не может звать сервер напрямую (строгий CORS мотора, `origin:'null'`), поэтому запрос идёт **через главный процесс** (`window.rlm.api` → `main.js` → сервер). В **браузере/на телефоне** (холст открыт по HTTP с `/rlm/`) `rlmApi()` в `renderer.js` бьёт **прямым fetch на тот же origin** (относительный путь — проходит CSP `connect-src 'self'`, без CORS); `127.0.0.1:8100` остаётся только для dev через `file://`. Конфиг API (ключ) — обычный ключ серверной базы (`store = {get: lsGet, set: lsSet}`), один на все устройства (не отдельная синхронизация).
- **Ключ живёт на серверной стороне звонка** — из браузера к провайдеру не ходим, ключ не светится.

«Как не сломать»: наш маршрут монтируется **ДО** CSRF — не переносить его ниже, иначе холсту понадобится CSRF-токен. Порт **8100** держим отдельным от эталонного ST (8000). Холст (`/rlm/`) отдаём **с того же порта 8100** — из-за CSP холста (`connect-src 'self'`) раздача с другого порта/origin сломает `fetch` к `/api/rlm/*`. Маршрут `/api/rlm/net/*` — наоборот, **после** whitelist-middleware (только доверенные меняют список). `lsGet` читает **только** из зеркала `db` (сервер — источник истины), **без** фолбэка на `localStorage`; нет связи с сервером → экран «нет связи» (а не тихий показ старых данных). Холст `/rlm/` отдаём с `Cache-Control: no-store` — иначе телефон кэширует старый код и «застывает».

## OmniVoice TTS (озвучка чата, БЕЗ ComfyUI) — ПК/Electron-only

Клон голоса для чата на движке **OmniVoice** (k2-fsa, диффузионная TTS 600+ языков). Тяжёлый PyTorch/GPU → **только ПК/Electron** (в Termux/браузер не тянем; см. «Дуальный режим»). Отдельная подсистема, изолированная от мотора ST.

- **Папка `tts/`** (в корне проекта, НЕ в `server/`):
  - `venv/` — свой Python **3.12** + **torch 2.6.0+cu124** (cu124 под драйвер 560.94; cu128 требует ≥570) + `omnivoice` + `soundfile`. Ставится скриптом `setup_env.ps1` (через `uv`). Системный Python 3.14 не годится (нет колёс torch).
  - `model/` — веса OmniVoice (~3 ГБ: `model.safetensors` + `audio_tokenizer/` + токенайзеры), скопированы локально в проект.
  - `out/out.wav` — результат, **один файл с перезаписью** (новая озвучка затирает старую).
  - `service.py` — HTTP-сервис (порт **8123**), грузит модель ОДИН раз в фоне.
- **Сервис `service.py`:** `GET /health` (`{ready,cuda,error,dtype}`), `GET /progress` (`{phase:load|gen|idle, value:0..1}`), `POST /tts {text, ref_audio, ref_text, instruct, params, fmt}` → озвучка. **Два режима:** есть образец (`ref_audio`) → **клон**; задан `instruct` без образца → **voice-design** (генератор голоса по описанию, `model.generate(text, instruct=...)`; словарь черт в `omnivoice/utils/voice_design.py`). `fmt:'ogg'` пишет `out.ogg` (**OGG/OPUS** через `soundfile`, для голосового Telegram `sendVoice`), иначе `out.wav` (чат читает WAV-плеером). Параметры разложены по реальному API omnivoice: числовые → `OmniVoiceGenerationConfig`, `text/language/duration/speed/normalize_text` → прямые аргументы `generate()`. **Seed:** `-1`/пусто → сервис выбирает конкретный `random.randint`, применяет (`torch.manual_seed`) и **возвращает** `seed` в ответе (чтобы воспроизвести тот же голос). **Невербальные теги-эмоции** (`[laughter]` и т.п. — жёсткий список в `_NONVERBAL_PATTERN`) идут в `text` как есть. **Точность на GPU** — аргумент `--dtype fp16|bf16|fp32` (глобал `_dtype_name`, `_torch_dtype`); выбирается в ноде `Озвучка`, хранится в `store` (`rlm.tts.dtype`), `main.ensureTts` запускает сервис с ним, смена → `tts:restart` (kill+respawn — VRAM освобождает процесс). **Прогресс:** загрузка — по росту VRAM; генерация — **по времени с калибровкой** (`_gen_monitor` + EMA сек/символ; forward-hook считает шаги для первого прогона) — чтобы полоса не «застревала на 99%» на декоде/постобработке.
- **Как холст достаёт сервис:** через Electron, **целиком в `main.js`** (мотор ST не трогаем). `main.js` **лениво** поднимает сервис (по первому зову, чтобы модель не грузилась зря), проксирует и отдаёт звук рендереру **base64-ом** (CSP `file://`-страницы не пускает произвольный `file://` в `<audio>`; `media-src blob:`). IPC: `tts:generate`/`tts:health`/`tts:progress`/`tts:ensure`/`tts:restart`; **библиотека голосов** — `tts:saveVoice({b64,id})` (пишет WAV в `tts/voices/<id>.wav`), `tts:deleteVoice({file})` (только внутри `tts/voices`), `tts:readAudio({file})` (читает аудиофайл образца в base64 — для «прослушать пресет» без генерации). Мост `window.rlm.tts`. Гасит сервис при выходе; перезапускает, если модель не загрузилась.
- **Библиотека голосов** (нода `Озвучка`): список сохранённых голосов в серверном сторе `rlm.tts.voices` (`[{id,name,file,refText,seed,instruct,settings,_own}]`, общий на все чаты). Голос-«профиль» несёт seed + полный набор настроек (язык, тегетирование, все параметры). Файлы голосов — в `tts/voices/` (сгенерированные) либо путь к WAV-образцу пользователя.
- **Нода `Озвучка`** и кнопка 🔊 — см. список нод выше. Запуск озвучки САМ ждёт загрузку модели (без повторных кликов), показывает проценты в ноде и **лентой статуса над вводом** (подгрузка = бегущая полоса, генерация аудио = заливка по времени); ⏹ «Стоп» — теперь **крестик ленты** (или `stopTts`): и чтение, и генерацию (в UI мгновенно; сам torch-вызов домелется).
- **🔊 Авто-озвучивание** (галочка `.tts-autospeak`, поле снимка `autoSpeak`): на каждый готовый ответ ИИ — `maybeAutoSpeak(node, idx)` сперва **переводит** реплику (`trTranslate(text,'ru','preview')` → `_tr`/`_showTr`, как кнопка 🌐 в чате), затем сразу зовёт `speakFromChat` на переведённом тексте. Хуки: конец `generateReply` (для НЕ-pending реплик) и апрув `criticJudge` (для скрытых критиком — озвучиваем финал; заворот-перекат идёт через тот же `generateReply`). Перевод не удался → озвучиваем оригинал. Приветствие/pending не озвучиваем. ПК-only (гейт `window.rlm.tts`). **Плеер под сообщением** (`tts-audio`: стоп/переиграть/переген): при ручном 🔊 идёт в кадр-источник клика, при авто-озвучке (`source=null`) `speakFromChat` шлёт спиннер и плеер в **ОБА кадра чата** (нода `_frame` + разворот `#st-frame`) через `chatFrames()` — иначе аудио играло бы тихо в родителе (`playB64Wav`) без контрола в чате. **Звук привязан к ТЕКСТУ реплики** (`key=msg.text` в `tts-audio`; `chat.html` хранит `ttsAudioByIdx[i]={url,key}` и показывает плеер лишь при `key===currentMsgs[i].text`) — при перегенерации/правке старый плеер не «прилипает» к новому ответу, а поздно доехавший звук старой реплики отбрасывается. `regenerate` зовёт `stopTts()` (отмена уходящей озвучки + сброс `_ttsBusy`, чтобы авто-озвучка нового ответа не блокировалась).

«Как не сломать»: `tts/` — **отдельно от `server/`** (не смешивать Node-мотор и Python-TTS). Torch-версию подбирать под драйвер GPU. Первый запуск грузит модель минуты — это норма.

## План бэкенда (куда растём дальше)

RLM растёт на **моторе SillyTavern** (Node.js + Express, ESM) — своим кодом. UI — в браузере/Electron, сервер трогает файлы. Модель клиент-сервер:

```
[Браузер: телефон/ПК]  ←REST /api/…→  [Node-сервер (SillyTavern + плагины)]  ←files→  [data/]
```

Зависимости — **pure-JS/WASM, без нативной компиляции** (ради Termux). Правило «как не сломать»: **не тащить** `sharp`, `canvas`, `better-sqlite3`, `bcrypt` — только JS/WASM аналоги (Jimp, tiktoken, vectra).

## Дорожная карта (отложено)

**Порядок сэмплеров → влияние на генерацию (нативный koboldcpp).**
- *Что хотели:* чтобы перетаскивание в секции «порядок» ноды `Локал-сэмплеры` реально меняло результат (порядок обработки сэмплеров = `sampler_order`).
- *Почему отложено:* порядок применяется только на **нативном пути koboldcpp** (эндпоинт `/api/v1/generate`, тело в его формате). Наш текущий путь — OpenAI-совместимый `/chat/completions`, где порядка нет; облачные Aphrodite-хостинги (ArliAI/Infermatic/Featherless) им покрыты, а порядок нужен лишь чистому koboldcpp. Значит пока не нужен.
- *Что нужно, когда возьмёмся:* вторая «дверь» на сервере — маршрут-адаптер под koboldcpp: raw-текст промта вместо `messages`, `sampler_order` как массив **целочисленных индексов** (не имён), маппинг наших крутилок в koboldcpp-имена. Плюс ветка выбора двери по `apiEl.dataset.mode==='text'` + признаку «это koboldcpp».
- *Про инструкт-теги — вывод из изучения референсов (ST vs SW):* теги под модель **не обязаны** быть нашей заботой. **SW-подход** (и наш нынешний): всегда `messages` → **chat-эндпоинт**, теги ставит провайдер/движок. Даже koboldcpp имеет chat-эндпоинт (`/v1/chat/completions`), который применяет GGUF-шаблон модели, — значит и локаль можно вести через chat-дверь, не клея теги руками. **Своя raw-сборка строки нужна только ради `sampler_order`** (порядок отложен). Если всё же понадобится raw: не тянуть 37-шаблонную машинерию ST — хватит простого override как в SW (дропдаун Auto/ChatML/Llama-3/Mistral/Alpaca → шаблон движка). ST-way (полная библиотека + деривация из `chat_template` модели по хэшу/тегам) — только если захотим ту же глубину. Детали — в `backend-research.md`.
- *Что уже есть:* UI порядка (перетаскивание) и его сохранение; режим Text; чтение умных крутилок в `params` по OpenAI-пути.

**Два входа промта у `API · перевод` (свой Систем промт на каждое направление).**
- *Что хотели:* когда к ноде `API · перевод` подключён `Транслитер`, показывать на ней **два входа «Промт»** — «Текст→Перевод» (предпросмотр, `to='ru'`) и «Перевод→Текст» (замена, `to='en'`); каждое направление нейро-перевода берёт **свою** инструкцию из подключённого к этому входу `Систем промт`. Направление на не-LLM провайдере (Google/Yandex/Bing) свой промт просто игнорирует.
- *Почему отложено (важно):* сегодня нейро-перевод (`trNeuroTranslate`) **вообще не читает** подключённый `Систем промт` — шлёт встроенную команду «Переведи на такой-то язык». Значит фича = **две вещи сразу**: (1) научить перевод брать инструкцию из `Систем промт`; (2) динамический 2-й вход. А динамические порты «по проводам» чувствительны к сохранению/загрузке (легко потерять провод ко 2-му входу при восстановлении графа).
- *Что нужно, когда возьмёмся:* (а) в `trNeuroTranslate` по `to` выбирать вход (`in:prompt` / новый `in:prompt2`) и класть текст `Систем промта` системным сообщением (нет промта → нынешний встроенный фолбэк); (б) на ноде API рендерить 2-й вход, когда её выход идёт в `Транслитер.in:neuro`, с аккуратным порядком загрузки (сначала пересобрать порты, потом восстановить провода — иначе `findPort('in:prompt2')` вернёт null). Сериализация — по ключам портов, как у остальных входов.
- *Что уже есть:* один вход «Промт»; `trNeuroTranslate` находит API через `Транслитер.in:neuro`; направление известно (`to='ru'|'en'`); сэмплеры уже берутся из `Опции · перевод`.

## Дуальный режим (один бэкенд)

- **Телефон (Termux):** лёгкий режим — браузер, облачная модель, MD-память.
- **ПК (полный режим):** локальная модель (KoboldCpp/Ollama/…), тяжёлый TTS (XTTS/Coqui), зрение, картинки, аватар. Опциональная обёртка **Electron** (`start:electron`) для десктоп-ощущения.
- Персонажи/чаты/память **общие** — лежат в файлах на сервере, режим не важен.

## Наши плагины

- **soul-md** (`plugins/soul-md/index.js`) — серверный плагин: MD-память в стиле Soul of Waifu, кроссплатформенно (Windows + Termux). Дневник на чат, трекеры (`Status.md`/`World.md`), темы (`topics/*.md`) с семантическим RAG через родной эмбеддер ST. Маршруты `/api/plugins/soul-md/*` (за CSRF). Требует `enableServerPlugins: true` в `config.yaml`. Детали формата — в `formats.md`. *(Чтение памяти для холста идёт не через плагин, а через `src/endpoints/rlm-soul.js` — те же файлы, но маршруты `до CSRF`; там дневник отдаётся семантическим RAG, а не «последние N».)*
- **book-plugin / MemoryBooks** — фронт-расширение памяти (пока обзорно).
