# Механик машин — техническая документация

Полное описание плагина и всей проделанной работы. Для обзора — см. [index.md](index.md).

---

## 1. Что это

**«Механик машин»** — самостоятельный плагин SillyTavern, представляющий собой
**форк** расширения Memory Books. Весь движок Memory Books скопирован внутрь плагина,
поэтому он работает **без** отдельно установленной Memory Books.

Наше «лицо»:
- иконка-ключ **🔧** в панели ввода, рядом с волшебной палочкой (`#extensionsMenuButton`);
- по клику в ленту чата (`#chat`) добавляется **сообщение** (`.mes`), внутри которого
  рисуется **настоящий интерфейс приложения** (не модальное окно);
- интерфейс **всегда на русском**, независимо от языка SillyTavern.

Папка плагина (то, что грузит ST):
`C:\Tavern-1.14.0\data\default-user\extensions\SillyTavern-MachineMechanic\`

## 2. Структура файлов

| Файл | Роль |
|---|---|
| `manifest.json` | `display_name: "Механик машин"`, **`js: machineMechanic.js`**, `css: style.build.css`, `auto_update: false` |
| `machineMechanic.js` | **Точка входа** (наш код). Импортирует движок из сборки, ставит значок 🔧, рисует панель-сообщение |
| `index.js` | **Исходник движка** (форк Memory Books). Сюда вносим правки логики |
| `stmemory.js`, `addlore.js`, `chatcompile.js`, `sidePrompts.js`, `profileManager.js`, `templates.js`, `locales.js` и др. | Модули движка (исходники) |
| `soulDiary.js` | **🧠 Дневник души** (наш доп-модуль, не движок): `.md`-память на чат + смысловой поиск. Пара к серверному плагину `soul-md` |
| `locales/ru-ru.json` | Русский словарь перевода (≈170 КБ, полный) |
| `index.build.js` / `style.build.css` | **Сборка** — её реально грузит ST через `machineMechanic.js`. Руками не править, генерируется |
| `help.html` | **Справка** (копия `memorybooks-docs.html` + подсветка по `#хешу`). Открывается по клику на «?» |
| `index.build.js.orig` / `style.build.css.orig` | Резервная копия оригинального бандла Memory Books (аварийный откат) |
| `build.mjs` | Скрипт сборки (esbuild) |
| `package.json` / `node_modules/` | Зависимости сборки (`esbuild`, `dirty-json`). ST их игнорирует |

**Цепочка загрузки:** ST читает `manifest.json` → грузит `machineMechanic.js` →
он делает `import { mmOpenInline } from "./index.build.js"` (движок стартует) → ставит 🔧.

**Вне репозитория плагина** (лежат в установке ST, git не версионирует — при переустановке
класть заново): `plugins/soul-md/index.js` — серверный плагин Дневника души; `config.yaml`
→ `enableServerPlugins: true`.

## 3. Как это работает (архитектура)

### 3.1. Точка входа — `machineMechanic.js`
- `import { mmOpenInline } from "./index.build.js";` — подтягивает движок (он
  самоинициализируется: регистрирует команды, создаёт своё меню и т.д.).
- `createToolbarButton()` — вставляет `<div id="mm-wand-button" class="fa-solid fa-wrench interactable">`
  сразу после `#extensionsMenuButton`.
- Клик по 🔧 → `openPanel()`: создаёт сообщение `.mes` с телом `#mm-host` и вызывает
  `mmOpenInline(host, () => closePanel())`.
- Крестик × и «Закрыть» (класс `mm-close`) → `closePanel()` убирает сообщение.

### 3.2. Инлайн-интерфейс — доработка движка
Родной интерфейс движок рисует в **модальном окне** (`Popup`), а обработчики вешает
**делегированием на корневой элемент** `currentPopupInstance.dlg`, и всё ищет внутри
`currentPopupInstance.content`. Мы это переиспользовали, подсунув движку **наш
контейнер в чате** как «поддельное окно».

Механика: `showSettingsPopup()` строит `templateData` и HTML одинаково для обоих
режимов. Если задан `mmInlineTarget`, вместо создания модалки рисуем HTML в наш
контейнер и подменяем `currentPopupInstance` на объект-заглушку — дальше идут те же
родные функции навешивания обработчиков.

### 3.3. Принудительный русский
Перевод берётся из системы i18n SillyTavern **по языку интерфейса ST**. Раньше, если
ST был на английском, движок грузил пустой `en`-словарь → всё по-английски. Мы
заставляем движок при старте грузить **русский словарь первым**. Система ST
(`addLocaleData`) оставляет **первое** значение ключа, поэтому русский побеждает
английский fallback — интерфейс русский при любом языке ST.

## 4. Внесённые изменения в движок (`index.js`)

Всё помечено комментариями `Механик машин`. Полный список для будущей поддержки:

1. **Переменная режима инлайна** (рядом с `let currentPopupInstance`):
   ```js
   let mmInlineTarget = null; // { container, onClose }
   ```

2. **Экспорт `mmOpenInline` + `renderInlineActionButtons`** (перед `showSettingsPopup`):
   - `mmOpenInline(container, onClose)` — ставит `mmInlineTarget` и вызывает `showSettingsPopup()`;
   - `renderInlineActionButtons(container)` — рисует кнопки «Создать память / Объединить /
     Очистить сцену» (в модалке они были `customButtons` окна).

3. **Ветка инлайна в `showSettingsPopup()`** (перед `const content = DOMPurify...`):
   если задан `mmInlineTarget` — рисуем `settingsTemplate` в контейнер, ставим
   `currentPopupInstance = { dlg: container, content: container, completeCancelled }`,
   вызываем `setupSettingsEventListeners()`, `populateInlineButtons()`,
   `initializeSettingsPopupSelect2()`, `renderInlineActionButtons()` и `return`.
   Модальный путь ниже **не тронут**.

4. **Принудительный русский** (в блоке инициализации локали, ~`init`):
   перед загрузкой словаря текущего языка добавлена загрузка `loadLocaleJson("ru")`
   и `addLocaleData(current, ruData)` — русский регистрируется первым.

5. **Перевод строк-данных** (шли мимо i18n):
   - режим лорбука `"Manual"/"Automatic (Chat-bound)"` обёрнут в `translate(...)`
     (ключи `STMemoryBooks_Manual` / `STMemoryBooks_AutomaticChatBound`), 2 места;
   - названия ярусов — карта `MM_TIER_LABELS_RU` в `getSummaryTierOptions()`
     (Arc→Арка, Chapter→Глава, Book→Книга, Legend→Легенда, Series→Серия…).
     Меняется только отображаемый `label`, идентификатор `key` не трогаем.

6. **Перевод** — экспорт `mmTranslateText`, `mmOpenTranslateSettings` + дефолт
   `MM_DEFAULT_TRANSLATE_PROMPT` и ключи настроек (`mmTranslate*`). Детали — п. 8б.

7. **Кубик** — экспорт `mmOnGenerationStart`, `mmShowRollOnMessage`, `mmOpenDiceSettings`
   + ГПСЧ, `mmNextRoll`, `mmForcedRoll`, дефолты `MM_DEFAULT_DICE_PROMPT_*`,
   `renderInlineActionButtons` содержит кнопку «🎲 Кубик». Детали — п. 8в.

8. **Маркеры сцены** — `sceneManager.js`: контейнер `.mm-scene-markers` в `.ch_name`
   (п. 8г).

**Экспорты движка** (используются из `machineMechanic.js`): `mmOpenInline`,
`mmTranslateText`, `mmOpenTranslateSettings`, `mmOpenDiceSettings`,
`mmOnGenerationStart`, `mmShowRollOnMessage`.

Плюс в `machineMechanic.js` — наш UI (панель, 🌐-кнопки, «?», события кубика),
в `style.css` — стили (`#mm-panel`, `.mm-dice*`, `.mm-scene-markers`, `.mm-translation` и т.д.).

## 5. Сборка

`bun` (которым собирался оригинал MB) **не нужен** — заменён на **esbuild + node**.

```
cd C:\Tavern-1.14.0\data\default-user\extensions\SillyTavern-MachineMechanic
npm run build
```

`build.mjs` (esbuild): входы `index.js` + `style.css` → выходы `index.build.js` +
`style.build.css`. Импорты SillyTavern (`../...`) помечаются **external** (резолвятся
движком в рантайме), а модули `./*.js` и зависимость `dirty-json` **вшиваются** внутрь.
Не минифицируем — так удобнее отлаживать форк.

**Цикл доработки:**
- Правки **`index.js` / `style.css`** (движок) → нужен `npm run build` → **F5**.
- Правки **`machineMechanic.js` / `help.html`** → сборка НЕ нужна (ST грузит их
  напрямую) → просто **F5**.

`index.build.js` руками не редактируем — это артефакт сборки, перезатрётся.

## 5а. Контекстная справка (значки «?»)

У **каждой настройки** интерфейса стоит значок **«?»**. Клик открывает `help.html`
в **новой вкладке**, сразу на нужном месте, с **подсветкой именно этой настройки**.

Как устроено (всё в `machineMechanic.js` + `help.html`, без пересборки):
- `injectHelpIcons()` проходит по контролам `input/select/textarea[id^="stmb-"]`
  в панели и ставит рядом «?». Клик → `window.open(help.html#<id-контрола>)`.
  `MutationObserver` возвращает «?» после внутренних перерисовок интерфейса.
- `help.html` — копия `memorybooks-docs.html` (у неё каждая настройка описана
  строкой таблицы с её id в `<span class="code">`). Добавленный скрипт по
  `location.hash` (= id настройки) находит нужную строку и подсвечивает её
  (класс `.mm-hl`, жёлтая подсветка + прокрутка). Работает и `hashchange` —
  клик по другому «?» переводит подсветку в уже открытой вкладке.
- URL справки берётся относительно плагина: `new URL("help.html", import.meta.url)`
  — поэтому работает в любой сессии/на любой машине.

Если у настройки нет строки в справке — вкладка просто откроется сверху без
подсветки (не ошибка). Проверено: 26 «?», клик подсвечивает точную строку.

### Источник справки и её пересборка
Единый источник текста справки — **`book-plugin/memorybooks-docs.html`**. Файл в
плагине **`help.html` = этот источник + скрипт подсветки** (дописывается в конец).

**Правило:** правим текст в `memorybooks-docs.html`, затем пересобираем `help.html`:
```
cp book-plugin/memorybooks-docs.html  <плагин>/help.html
# и дописать в конец help.html блок <style>+<script> подсветки (см. историю/этот раздел)
```
Так текст и подсветка не расходятся. Внутренние ссылки-оглавление (`#c1…#cx`)
работают и заодно подсвечивают раздел (скрипт ловит любой `#хеш`).

### Содержание справки (обогащение объяснений)
Колонки «Зачем» переписаны так, чтобы объяснять **эффект**, а не просто
констатировать факт: что реально даёт настройка, зачем её включать/выключать и
какой компромисс. Важно: при правках **нельзя менять** `data-search` и
`<span class="code">stmb-…</span>` в строках — по ним работает подсветка по id.

## 6. Локализация

- Словари: `locales/*.json` (русский — `ru-ru.json`, полный) + встроенный английский
  словарь в `locales.js`.
- Строки в интерфейсе переводятся двумя способами:
  - `translate(текст, ключ)` в коде (баковится в момент рендера);
  - атрибуты `data-i18n` в HTML-шаблоне (`templates.js`, ~165 шт.) — их переводит
    `MutationObserver` самого ST при добавлении элементов в DOM.
- Мы форсим русский (см. п.4.4), поэтому интерфейс русский при любом языке ST.

**Что НЕ переводится (и не должно):**
- макросы в шаблонах: `{{title}}`, `{{scene}}`, `{{char}}`, `[000]` — движок
  подставляет их по имени, перевод их сломает;
- технические имена: провайдеры API (`openrouter`), модели (`z-ai/glm-5`).

Если где-то мелькнёт непереведённое — искать: либо нет ключа в `ru-ru.json`, либо это
строка-данные в коде (как режим лорбука/ярусы, п.4.5).

## 8. Диагностика проблем

- **Значка 🔧 нет / плагин не грузится.**
  Новый плагин ST видит только при перезагрузке страницы (F5); иногда нужен
  рестарт сервера ST. В консоли (F12) ищи `[Механик машин]` и красные ошибки.
- **Клик по 🔧 ничего не открывает.**
  Значит движок не отрисовал интерфейс — смотри ошибку в консоли; наш код обёрнут в
  try/catch и покажет текст ошибки прямо в панели.
- **Интерфейс на английском.**
  Проверь, что сборка свежая (`npm run build`) и сделан F5. Принудительный русский
  работает независимо от языка ST.
- **Сборка вдруг сломала движок.**
  Есть резервные `index.build.js.orig` / `style.build.css.orig` — можно временно
  вернуть оригинальный бандл.
- **Конфликт с оригинальной Memory Books.**
  Дубликат slash-команд SillyTavern только **предупреждает** в консоль (не ломает),
  так что форк работает даже при включённой оригинальной Memory Books. Для чистоты
  оригинал можно выключить в панели расширений.

## 8а. Стрелки у плавающих ножниц Clip

При выделении текста в чате всплывает кнопка-ножницы (`stmb_floating_clip_button`,
`fa-scissors`). Рядом добавлены **стрелки ◄ и ►**:
- **◄** — добавить к выделению **предыдущее** сообщение;
- **►** — добавить **следующее**;
- затем ножницы клипают уже расширенное выделение.

Реализация в `clipManager.js`: `createFloatingClipButton()` теперь строит контейнер
`.stmb_floating_clip_wrap` = `[◄] [✂] [►]` (позиционируется как единое целое штатной
логикой движка). `stmbExtendSelectionByMessage(dir)` двигает границу `Range` на
соседнее `.mes` и переставляет кнопку. Стили — `.stmb_floating_clip_wrap` /
`.stmb_floating_clip_arrow` в `style.css`. **Нужна пересборка** (`npm run build`).
Проверено: обе стрелки расширяют выделение и не выходят за пределы чата.

## 8б. Перевод сообщений (🌐)

- **Значок 🌐** у каждого сообщения (рядом с переводом ST) добавляет `machineMechanic.js`
  (наблюдатель за `#chat`). Клик → `mmTranslateText(текст)` → перевод рисуется блоком
  `.mm-translation` под сообщением; повторный клик убирает.
- **`mmTranslateText(text)`** (экспорт из движка): в ИИ уходит только текст + промпт
  перевода (в изоляции, без истории чата). Использует **профиль подключения ST**
  (`ConnectionManagerRequestService.sendRequest(id, messages, …, {includePreset:false})`
  — значит без чужих системных промптов и порядка). Если профиль не выбран — откат на
  профиль плагина через `sendRawCompletionRequest`.
- **Настройки** — `mmOpenTranslateSettings()` (кнопка «🌐 Перевод (промпт)» в панели):
  промпт, профиль подключения (`mmTranslateConnProfileId`), «Своя температура»
  (`mmTranslateTempOverride` + `mmTranslateTemp`) — галка вкл: своя, выкл: профиля.

## 8в. Кубик (🎲)

Свой ГПСЧ (**mulberry32**, `mmRandom`), НЕ инструменты рандома ST. Всё в `index.js`,
события вешает `machineMechanic.js`.

- **Кнопка «🎲 Кубик»** в панели: чекбокс = `mmDiceEnabled` (вкл/выкл), клик по тексту →
  `mmOpenDiceSettings()`.
- **Два раздельных режима** (`mmDiceMode`): `"dice"` (число d20, со шкалой критичности)
  и `"successfail"` (только Успех/Провал). **У каждого свой промпт**
  (`mmDicePromptNum` / `mmDicePromptSF`); в меню промпт меняется вместе с режимом.
- **Инъекция перед ответом:** событие `GENERATION_STARTED` → `mmOnGenerationStart()`:
  кидает кубик (`mmNextRoll`), собирает `[промпт + исход]` и шлёт скрыто через
  `setExtensionPrompt("MM_DICE_ROLL", …, IN_CHAT, depth 0, SYSTEM)` — ИИ учитывает,
  в чат не пишется. Число сразу рисуется **над будущим сообщением** (`.mm-dice-above`).
- **После ответа:** `CHARACTER_MESSAGE_RENDERED` → `mmShowRollOnMessage()` закрепляет
  блок над сообщением ИИ (и убирает прошлый при перегенерации).
- **Форс следующего броска** (`mmForcedRoll`, разово): Обычный/Успех/Провал/Число —
  применяется к следующему ответу и сбрасывается. Поле числа активно только при «Число».
- **Критичность (режим числа, в инъекции):** 1–3 = критический провал (вплоть до
  смерти `{{user}}` по контексту) … 20 = критический триумф. Тексты — константы
  `MM_DEFAULT_DICE_PROMPT_SF` / `MM_DEFAULT_DICE_PROMPT_NUM` + строка исхода в инъекции.

## 8д. Дневник души / Дневник персонажа (🧠)

**Два названия — одно и то же:** «Дневник души» = «Дневник персонажа».
«Soul-Memory-подобная» память поверх ST. Не трогает движок и лорбук — связка
«фронт-модуль + серверный плагин».

**Как достаётся в промт** (важно): дневник — **последние N записей по времени**
(файлы `Diary_дата` по имени + порядок дописывания, как в Soul of Waifu; не семантика).
Факты/темы — **по смыслу** (эмбеддер). Слой фактов: Router решает какие темы,
Archivist перезаписывает 1 файл на тему (resolve conflicts, prioritize new truths).

**Файлы**
- `soulDiary.js` (фронт, наш) — кнопка 🧠 у кнопки полосок, листалка, окно настроек, хуки.
- `plugins/soul-md/index.js` (сервер ST, **вне репо**) — пишет/читает `.md`, эмбеддинг, поиск.
- Нужен `enableServerPlugins: true`. Правка серверной части → **перезапуск сервера** (не F5).

**Три дока на чат** (`plugins/soul-md/data/<id чата>/`):
- `Diary_<дата>.md` — рефлексия от 1-го лица (append), стиль Soul of Waifu `_DIARY_SYSTEM`.
- `Psyche.md` (Эмоции), `Status.md` (Отношения) — трекеры, модель перезаписывает целиком.
  Промпты — облегчённая выжимка их `_ROUTER_SYSTEM` (эмоция+интенсивность, убеждения,
  диссонанс, затухание; доверие по той же шкале, динамика, привычки, обещания).

**Генерация** — `generateRaw` (чистый промт, без карточки/чата/джейла/пресета), единый
хелпер `genMem`. В систем-промте (`MEM_SYS`) — разрешающая fiction-рамка, чтобы модель
не цензурировала острое. Сырой ответ логируется в консоль (диагностика).

**Когда** — авто раз в N ответов (короткое окно) или «🔄 Обновить сейчас» (большое окно,
догнать историю). Всё настраивается.

**Инъекция в промт** (`GENERATION_STARTED`, `setExtensionPrompt`, IN_CHAT depth 4) — 4 блока:
`[Текущее состояние {char}]` = Psyche.md и `[Отношение к {user}]` = Status.md (всегда целиком),
`[Известные факты]` = темы top-3 по смыслу, `[Из дневника персонажа]` = последние N записей (`diaryCount`, деф. 3, k в `/query`).
Дневник — по времени (не эмбеддер), темы — по смыслу. Тег источника отражает, что реально вошло.

**Настройки** (окно ⚙, `extension_settings.STMemoryBooks.mm_soulDiary`): мастер-вкл,
тумблеры доков, интервал `trackerEvery`, окна `autoWindow`/`deepWindow`, редакторы промптов
(`prompts.{diary,psyche,status,router,archivist}` — все 5 редактируемые; плейсхолдеры
`{{char}}{{user}}{{recent}}{{prev}}`, для тем ещё `{{topics}}{{topic}}{{reason}}`; сброс к дефолту),
удаление файлов чата.

**Вьюер**: 3 страницы (Дневник/Эмоции/Отношения) + 4-я «Факты» = оглавление тем
(открыть / 🚫 исключить↔✅ вернуть через rename `.md`↔`.md.off` / 🗑 удалить). «✏ Править»
правит Эмоции/Отношения (`/save`); «🌐» — перевод Яндексом (свой у каждого дока и темы).
В ⚙ есть «Установка сервера» — готовая curl-команда для Termux + копировать.
Серверные маршруты тем: `/topics`, `/topic-save`, `/topics-query`, `/topic-delete`, `/topic-exclude`.

**Тег источника** под ответом (`showSource`): 📔 дневник / 📚 факт:имя / 📕 запись лорбука
(лорбук — через `WORLD_INFO_ACTIVATED`, только записи с `comment`, лимит 5; `/topics-query` отдаёт `used`).
**Индикатор** «Формирование души» над `#send_form` (`progInit/progSet/progDone`) — статус ⏳→🔄→✅ по каждому доку.
**Свои лимиты:** `maxTokens` (responseLength для памяти, НЕ основной max_tokens ответа) + `maxWords`
(уходит в `MEM_SYS`: «уложись в N слов, допиши до конца» — против обрыва).

**Привязка к чату** — ключ `getCurrentChatId()`; на `CHAT_CHANGED` инъекция чистится;
удаление чата (`CHAT_DELETED`/`GROUP_CHAT_DELETED`) → `/purge` стирает папку чата.

**Серверные маршруты** (`/api/plugins/soul-md/…`): `append`, `query`, `docs`, `tracker`,
`get`, `save`, `purge`.

Подключается в `machineMechanic.js`: `import { initSoulDiary }` + `initSoulDiary(ctx)`.
