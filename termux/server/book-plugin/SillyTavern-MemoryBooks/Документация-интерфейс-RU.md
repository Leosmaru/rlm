# 📕 Memory Books — документация по интерфейсу

Плагин для SillyTavern, который создаёт из переписки «воспоминания» (memories) и записывает их в лорбук (World Info) с ключевыми словами и нумерованными заголовками. Ниже — описание **каждой кнопки, настройки и меню**, что она делает и зачем нужна.

> Весь интерфейс генерируется в коде (`templates.js` + `index.js`), а не лежит в готовых `.html`-файлах. Отдельные `.html` в папке `resources/` — это самостоятельные утилиты-конвертеры (см. последний раздел).

---

## 1. Как открыть плагин

- **Меню расширений → «Memory Books»** (иконка книги `📖`). Пункт добавляется в выпадающее меню «волшебной палочки»/расширений внизу чата.
- Клик по этому пункту открывает **главное окно настроек** (описано ниже).

---

## 2. Разметка сцены прямо в чате

Прежде чем создать воспоминание, нужно отметить в чате **начало и конец сцены**:

| Элемент | Что делает | Зачем |
|---|---|---|
| **Кнопка-шеврон «►»** на сообщении | Отмечает **начало** сцены (start) | Задаёт нижнюю границу диапазона сообщений, из которых сделается память |
| **Кнопка-шеврон «◄»** на сообщении | Отмечает **конец** сцены (end) | Задаёт верхнюю границу диапазона |
| **Плавающая кнопка «Clip»** | Появляется при выделении текста в чате (если включена в настройках) | Быстро «вырезать» выделенный фрагмент для тематической памяти |

Если маркеры не выставлены, в окне настроек будет предупреждение: *«No scene markers set…»*.

## ▶ Ролеплей-пример: от сцены до памяти

Разберём на живом примере, **что вы делаете, что получается и как это влияет на модель**. Фэнтези-ролеплей: спутница `{{user}}` — эльфийка-следопыт **Лира**. В чате ~160 сообщений, модель начинает путать детали ранних сцен.

**Шаг 1. Проблема — модель забывает.** К 160-му сообщению ранняя сцена ушла из контекста:
> `#158` **{{user}}:** Лира, напомни — сколько я должен Молчуну?
> `#159` **Лира:** Прости… я не припомню такого имени. *(← деталь потеряна)*

**Шаг 2. Действие — размечаем сцену и создаём память.** Ставим `►` на #71 и `◄` на #96 (вся сцена у моста, 26 сообщений), жмём **🧠 Create Memory**. Плагин делает компактную запись в лорбук:

```
007 — Сделка у Серого моста
Ключи: Серый мост, Молчун, кинжал «Ветерок», долг, 200 монет
Текст: {{user}} и Лира встретили у Серого моста торговца Молчуна.
{{user}} купил кинжал «Ветерок», но заплатил половину — Молчун дал
в долг под обещание вернуть 100 монет к полнолунию. Лира не доверяет
торговцу и советует держаться настороже.
```

**Шаг 3. Эффект — экономия токенов.** Включённый Auto-hide прячет сообщения 71–96:

| В контексте | Токенов |
|---|---|
| Сырые 26 сообщений | ≈ 8 200 |
| Запись памяти | ≈ 620 |

*Как это влияет:* экономия ≈ 93%, освобождается место под новые сцены, разговор не «глупеет» от переполненного контекста.

**Шаг 4. Отдача — модель снова «помнит».** Через ~90 сообщений появляется слово «Ветерок» → срабатывает ключ → запись подставляется в контекст:
> `#251` **{{user}}:** Достаю кинжал «Ветерок».
> *(🔑 ключ «Ветерок» → добавлена запись «007 — Сделка у Серого моста»)*
> `#252` **Лира:** Тот самый клинок от Молчуна. Не забывай — ты всё ещё должен ему сотню монет к полнолунию. *(✓ деталь восстановлена)*

*Как это влияет:* модель «вспомнила» долг и недоверие Лиры, хотя исходные сообщения давно скрыты. Память живёт в лорбуке и срабатывает по ключам ровно тогда, когда нужна.

**Шаг 5. Масштаб — авто-память и консолидация.** Auto-Summary (интервал 50) сам делает записи каждые 50 сообщений; **🌈 Consolidate Memories** сшивает связанные записи (007–012 про Северный лес) в одну «арку» с общим ключом. *Как это влияет:* контекст остаётся лёгким даже на дистанции в сотни сообщений.

> **Мини-пример формата заголовка:** `[000] - {{title}}` → `007 - Сделка у Серого моста`; `[00] · {{char}}: {{title}}` → `07 · Лира: Сделка у Серого моста`.
>
> **Мини-пример трекера:** сайд-промпт «Инвентарь» с интервалом 10 каждые 10 сообщений обновляет `кинжал «Ветерок», 3 зелья, 87 монет` — модель всегда видит актуальное состояние, не пересказывая историю покупок.

## ◆ Для каких целей это использовать

Коротко: плагин нужен там, где **переписка длиннее, чем помещается в контекст модели**. Он переносит суть старых сцен в лорбук, а модель подтягивает её по мере надобности.

| Задача | Как помогает | Что включить |
|---|---|---|
| Длинный ролеплей / кампания (сотни–тысячи сообщений) | Модель не забывает ранние события | Auto-Summary + Create Memory |
| Многосессионная история | Вернуться к сюжету через недели без потерь | Лорбук, привязанный к чату |
| Держать «состояние мира» (инвентарь, отношения, квесты) | Актуальные факты всегда перед глазами модели | Трекеры / сайд-промпты (🔵 Constant) |
| Экономия токенов и денег | Короткие сводки в контексте вместо сырого лога | Auto-hide + память |
| Оживить старую сюжетную нить | Всплыл ключ → нужная деталь вернулась в ответ | Ключевые слова записи |
| Обзор истории кампании | Лорбук как «дневник» событий | Просмотр записей / Compaction |

> **Когда не нужно:** для коротких чатов, которые целиком помещаются в контекст, память избыточна — она полезна на длинной дистанции.

## ⚖ Порядок, позиция и приоритет

Куда запись попадёт в промпте и насколько она «весома», решают три параметра. Они задаются в редакторе профиля: **✏️ Edit Profile → Lorebook Entry Settings**.

**Как это ложится в поток промпта** (собирается сверху вниз; чем выше — тем весомее как фон):

```
System / инструкции
🧠 Записи памяти (и трекеры)   ← ↑Char, позиция по умолчанию
Карточка персонажа
Примеры сообщений              ↑EM / ↓EM
Авторская заметка              ↑AN / ↓AN
История чата (свежие сообщения) ← «сейчас»
```

**1. Activation Mode — когда запись попадает в промпт**

| Режим | Когда активируется | Для чего |
|---|---|---|
| 🔗 Vectorized *(по умолч.)* | По смысловому (векторному) поиску — даже без точного ключа | Рекомендуется для памяти; нужна включённая векторизация в ST |
| 🔵 Constant | Всегда в промпте, независимо от ключей | Для постоянного фона (инвентарь, ключевые факты) |
| 🟢 Normal | По совпадению ключевых слов (scan depth) | Классический режим лорбука |

**2. Insertion Position — куда вставляется:** `↑Char` (реком.), `↓Char`, `↑EM/↓EM`, `↑AN/↓AN`, `Outlet` (+ имя). Ниже ↑AN память опускать не стоит — потеряется среди свежих сообщений.

**3. Insertion Order — приоритет при равной позиции:**
- **Auto (по №)** — order = номер воспоминания; свежие получают больший order.
- **Reverse** — order = reverseStart − (№−1); только с Outlet.
- **Manual** — фиксированный order 1–9999 для всех.

> **Что такое приоритет:** записи с бóльшим `order` вставляются раньше и первыми проходят в лимит токенов; при переполнении контекста записи с меньшим order отбрасываются раньше. Позиция важнее order (сначала группировка по позиции, потом сортировка по order внутри неё).

**4. Recursion Settings:** *Prevent Recursion* — запись не активирует другие; *Delay Until Recursion* — запись включается только на этапе рекурсии (её могут «подтянуть» другие записи, но не прямое сканирование чата).

**Пример — почему «Инвентарь» приоритетнее эпизода:**

| Запись | Настройки | Поведение |
|---|---|---|
| 🎒 Инвентарь (трекер) | 🔵 Constant · ↑Char · order 9999 | Всегда вверху, не отбрасывается при нехватке бюджета |
| 007 — Серый мост (эпизод) | 🔗 Vectorized · ↑Char · order 7 | Появляется по смыслу, уступает при переполнении |

*Как это влияет:* инвентарь модель держит в голове постоянно и с наивысшим приоритетом, эпизоды — ситуативно. Режимом, позицией и order вы решаете, **что фон всегда, а что по запросу**.

## ∑ Консолидация: уровни, опции и промпты

### Зачем это нужно
Со временем воспоминаний становятся **десятки и сотни**. Даже по 600 токенов — если в сцене сработает 15 ключей, это снова ~9 000 токенов и переполнение. Плюс сюжет дробится на обрывки.

| Проблема без консолидации | Что даёт консолидация |
|---|---|
| Много мелких записей → много активаций → снова переполнение | Одна сводка вместо группы — меньше активаций и токенов |
| Модель видит обрывки сцен, теряет общую линию | Целостная сводка сюжетной дуги |
| Повторы и дубли деталей | Сшивает и убирает избыточность |

### Лестница уровней (tiers)
Каждый уровень собирается **из уровня на ступень ниже** (по умолчанию минимум 5 записей). Одни и те же сцены постепенно сжимаются во всё более крупные сводки.

| Уровень | Собирается из | Что это по смыслу | Заголовок по умолч. |
|---|---|---|---|
| **Memory** (tier 0) | — (из сцены чата) | Одна сцена / эпизод | `[000] - {{title}}` |
| **Arc** (tier 1) | Memory | Сюжетная дуга | `[ARC 000] - …` |
| **Chapter** (tier 2) | Arc | Глава | `[CHAPTER 000] - …` |
| **Book** (tier 3) | Chapter | Том / книга | `[BOOK 000] - …` |
| **Legend** (tier 4) | Book | Крупный свод | `[LEGEND 000] - …` |
| **Series** (tier 5) | Legend | Цикл историй | `[SERIES 000] - …` |
| **Epic** (tier 6) | Series | Максимальная свёртка | `[EPIC 000] - …` |

> **Проще говоря:** большинству хватает **Memory → Arc → Chapter**. Book/Legend/Series/Epic нужны только для гигантских кампаний. В окне выбираете **целевой** уровень, источник берётся на ступень ниже.

### Окно «🌈 Consolidate Memories» — все опции

| Опция | Что делает | По умолч. |
|---|---|---|
| **Summary Tier** | Какой уровень строим (Arc…Epic); источник — уровень ниже | Arc |
| **Preset** | Пресет промпта консолидации (+ «Rebuild from built-ins») | по умолч. |
| **Max entries per pass** | Сколько исходных записей за один проход | 15 |
| **Token Budget** | Лимит токенов на проход | 30 000 |
| **Automatic summary attempts** | Сколько проходов запускать автоматически подряд | 10 |
| **Minimum eligible … before tier is ready** | Минимум исходных записей, чтобы уровень «созрел» (и для авто-запроса) | 5 |
| **Lorebook Entry Settings** | Как сохранить сводку: активация, позиция, порядок, рекурсия (см. ⚖) | 🔗·↑Char·Auto |
| **Disable source entries after creating summaries** | Отключить исходники после сборки, чтобы не срабатывали вместе со сводкой | вкл |
| **Select All / Deselect All + чеклист** | Какие записи войдут в сводку | все |

### Промпты консолидации — что и как писать
Правятся в **🧱 Consolidation Prompt Manager**. Один промпт работает на любом уровне благодаря макросам:
- `{{stmbtier}}` — целевой уровень (напр. «arc»)
- `{{stmbchildtier}}` — исходный уровень (напр. «memory»)

Ответ модели **обязан быть строго JSON**:
```json
{
  "summaries": [
    { "title": "3–6 слов", "summary": "сводка одной строкой", "keywords": ["ключ1"], "member_ids": ["<ID>"] }
  ],
  "unassigned_items": [ { "id": "item-id", "reason": "почему не вошло" } ]
}
```
- **member_ids** — какие исходные записи вошли (обязательно при нескольких сводках, иначе нельзя править их по отдельности).
- **unassigned_items** — что не подошло и почему.

Три встроенных пресета: **Default** (подробная структура: Premise · Major Beats · Character Dynamics · Key Exchanges · Outcome & Continuity — для важных дуг), **Alternate** (компактная сводка — баланс), **Tiny** (агрессивное сжатие — когда записей очень много).

**Правила хорошего промпта:**
- Не убирайте «return only JSON» — по ней плагин парсит ответ.
- Хронология + наименьшее связное число сводок.
- Не переписывать блок PREVIOUS (это канон вышестоящего уровня).
- **keywords** — конкретные существительные, объекты, места, имена, действия; НЕ абстрактные эмоции/темы.
- Игнорировать OOC и декор, если не влияет на continuity.
- Проще всего — скопировать встроенный пресет и подправить.

> Промпты уровня **Memory** (отдельные воспоминания) — в **🧩 Summary Prompt Manager**: та же дисциплина «строго JSON», но сцена сжимается в одно воспоминание (без member_ids и уровней).

*Как это влияет:* правильные уровни и промпты держат контекст лёгким на дистанции в тысячи сообщений, ранние нити не теряются. Запуск — **🌈 Consolidate Memories** или авто-запрос, когда уровень «созрел».

## 3. Главное окно настроек

### 3.1. Верхний информационный блок

| Элемент | Что показывает |
|---|---|
| **Current Scene** (Текущая сцена) | Предпросмотр выбранной сцены: сообщение начала/конца, спикеры, отрывки текста, число сообщений и примерная оценка токенов. Если сцена не размечена — жёлтое предупреждение с подсказкой про шевроны. |
| **Memory Status** (Статус памяти) 📊 | До какого сообщения уже обработана память в этом чате (или «ещё не обрабатывалась»). Нужно, чтобы понимать, откуда продолжится авто-суммаризация. |

### 3.2. Preferences (Предпочтения)

Чекбоксы, управляющие поведением плагина:

| Настройка (id) | Что делает | Зачем |
|---|---|---|
| **Always use default profile** (`stmb-always-use-default`) | Всегда использовать профиль по умолчанию без окна подтверждения | Ускоряет создание памяти — сразу генерирует, не спрашивая |
| **Show memory previews** (`stmb-show-memory-previews`) | Показывать предпросмотр воспоминаний и сайд-промптов, возвращённых ИИ | Даёт отредактировать/проверить результат перед сохранением |
| **Show consolidation previews** (`stmb-show-consolidation-previews`) | Показывать предпросмотр сводных сводок (консолидации) | Контроль качества при объединении нескольких воспоминаний |
| **Show notifications** (`stmb-show-notifications`) | Показывать всплывающие уведомления (toastr) | Обратная связь об успехе/ошибках |
| **Show floating Clip button** (`stmb-show-floating-clip-button`) | Показывать плавающую кнопку «Clip» при выделении текста | Быстрый доступ к тематической вырезке |
| **Allow scene overlap** (`stmb-allow-scene-overlap`) | Разрешить пересечение диапазонов сообщений между воспоминаниями (пропустить проверку) | По умолчанию плагин не даёт дублировать сообщения; галка отключает эту защиту |
| **Refresh lorebook editor** (`stmb-refresh-editor`) | Обновлять редактор лорбука после добавления памяти | Чтобы новые записи сразу были видны в открытом редакторе World Info |

### 3.3. Лимиты и контекст

| Настройка | Что задаёт | Зачем |
|---|---|---|
| **Max Response Tokens** (`stmb-max-tokens`) | Максимум токенов на сводку-воспоминание (плейсхолдер 4000) | Ограничивает длину/стоимость генерации |
| **Token Warning Threshold** (`stmb-token-warning-threshold`) | Порог, при превышении которого показывается предупреждение о больших входных токенах (по умолчанию 30 000) | Защита от случайной дорогой/долгой генерации на огромной сцене |
| **Default Previous Memories Count** (`stmb-default-memory-count`) | Сколько предыдущих воспоминаний подмешивать как контекст (0–7) | Улучшает связность: ИИ помнит, что было в прошлых сводках |

### 3.4. Regex (advanced) — продвинутый режим

| Элемент | Что делает |
|---|---|
| **Use regex (advanced)** (`stmb-use-regex`) | Включает применение регулярного выражения к тексту перед генерацией |
| **📐 Configure regex…** (`stmb-configure-regex`) | Открывает выбор/настройку regex (кнопка видна только при включённой галке). Внимание: выбранный здесь regex запустится независимо от того, включён он или выключен в основном списке ST |

### 3.5. Current Lorebook Configuration (Конфигурация лорбука)

| Элемент | Что показывает / делает | Зачем |
|---|---|---|
| **Mode** (`stmb-mode-badge`) | Текущий режим: *Manual* или *Automatic (Chat-bound)* | Куда пишутся воспоминания |
| **Active Lorebook** (`stmb-active-lorebook`) | Имя активного лорбука или «None selected» | Понимать целевой файл записей |
| **Enable Manual Lorebook Mode** (`stmb-manual-mode-enabled`) | Ручной режим: вы сами выбираете лорбук, а не привязанный к чату | Когда нужно писать в конкретный/общий лорбук |
| **Auto-create lorebook if none exists** (`stmb-auto-create-lorebook`) | Автоматически создавать и привязывать лорбук к чату, если его нет | Чтобы не настраивать вручную для каждого нового чата |
| **Lorebook Name Template** (`stmb-lorebook-name-template`) | Шаблон имени авто-создаваемого лорбука. Поддерживает `{{char}}`, `{{user}}`, `{{chat}}` | Единообразные, узнаваемые имена лорбуков |

> «Manual mode» и «Auto-create» **взаимоисключающие** — включение одного блокирует другой. Поле шаблона активно только при включённом Auto-create.

**Кнопки ручного режима** (появляются, когда включён Manual Mode):

| Кнопка | Действие |
|---|---|
| **📕 Select / Change Manual Lorebook** | Выбрать (или сменить) лорбук вручную |
| **❌ Clear Manual Lorebook** | Сбросить выбранный вручную лорбук (появляется, только если он задан) |

### 3.6. Token Saving — экономия токенов (скрытие сообщений)

| Настройка | Что делает | Зачем |
|---|---|---|
| **Auto-hide messages after adding memory** (`stmb-auto-hide-mode`) | Выпадающий список: `Do not auto-hide` / `Auto-hide all up to last memory` / `Auto-hide only messages in the last memory` | После создания памяти прячет старые сообщения из контекста, экономя токены — их «помнит» уже сама память |
| **Messages to leave unhidden** (`stmb-unhidden-entries-count`) | Сколько последних сообщений оставить видимыми (0 = скрыть всё до конца сцены) | Оставить «хвост» контекста для плавности |
| **Unhide hidden messages for memory generation** (`stmb-unhide-before-memory`) | Перед генерацией временно раскрывает скрытые сообщения (`/unhide X-Y`) | Чтобы память строилась по полному тексту, даже если он был скрыт |

### 3.7. Automatic Memories — автоматические воспоминания

| Настройка | Что делает | Зачем |
|---|---|---|
| **Auto-create memory summaries** (`stmb-auto-summary-enabled`) | Автоматически запускает `/nextmemory` каждые N сообщений | Память создаётся сама, без ручных действий. ⚠️ Требует «прайминга»: хотя бы одно ручное воспоминание в чате |
| **Auto-Summary Interval** (`stmb-auto-summary-interval`) | Через сколько сообщений создавать авто-сводку (10–200, дефолт 50) | Частота автоматической памяти |
| **Auto-Summary Buffer** (`stmb-auto-summary-buffer`) | Задержка авто-сводки на X сообщений (отложенная генерация, 0–50) | Чтобы захватывать чуть больше контекста / не резать сцену на середине |
| **Prompt for consolidation when a tier is ready** (`stmb-auto-consolidation-prompt-enabled`) | Показывает вопрос «да/нет», когда выбранный «tier» набрал достаточно исходных записей для консолидации | Напоминание объединить накопившиеся воспоминания |
| **Auto-Consolidation Tiers** (`stmb-auto-consolidation-target-tier`) | Мультивыбор уровней (tiers), которые будут вызывать запрос на консолидацию | Тонкая настройка, какие уровни сводок автоматизировать |

### 3.8. Memory Profiles — профили памяти

| Элемент | Что делает | Зачем |
|---|---|---|
| **Memory Title Format** (`stmb-title-format-select`) | Формат заголовка воспоминания. `[0]`, `[00]`, `[000]` — авто-нумерация; поддерживает `{{title}}`, `{{scene}}`, `{{char}}`, `{{user}}`, `{{messages}}`, `{{profile}}`, `{{date}}`, `{{time}}` | Единообразные, сортируемые заголовки записей |
| **Custom Title Format…** (`stmb-custom-title-format`) | Поле для своего формата (появляется при выборе «Custom») | Полностью произвольный шаблон заголовка |
| **Профиль** (`stmb-profile-select`) | Выбор активного профиля (провайдер+модель+температура+промпт) | Разные наборы настроек генерации под разные задачи |

## 4. Всплывающие окна (попапы)

### 4.1. Create Memory — подтверждение создания
Появляется перед генерацией (если не включён «Always use default profile»):
- **Scene Preview** — тот же предпросмотр сцены (сообщения, спикеры, токены).
- **Using Profile** — какой профиль используется, его Model/Temperature, раскрывашка **View Prompt**.
- **Предупреждение** ⚠️ о большой сцене (если токенов много).
- Подсказка: нажмите **Advanced Options**, чтобы поменять промпт/контекст/API.

### 4.2. Advanced Memory Options — расширенные опции
- **Scene Information** — диапазон сообщений и оценка токенов (обновляется динамически).
- **Profile** — сменить профиль для этой генерации.
- **Memory Creation Prompt** — редактировать промпт разово (есть кнопка «развернуть редактор» `⤢`).
- **Include Previous Memories as Context** — сколько прошлых воспоминаний подмешать (0–7); показывает, сколько уже есть в лорбуке.
- **API Override Settings** — блок сравнения: настройки профиля vs текущие настройки SillyTavern; чекбокс **«Use current SillyTavern settings instead of profile settings»** заменяет модель/температуру профиля на текущие ST.
- **Save as New Profile** — если настройки отличаются от профиля, предлагает сохранить их как новый профиль.

### 4.3. Memory Preview — предпросмотр воспоминания
Показывается после генерации (если включён «Show memory previews»):
- **Memory Title** — заголовок (можно править; иногда только для чтения).
- **Memory Content** — текст воспоминания (редактируемый, есть «развернуть»).
- **Keywords** — ключевые слова через запятую (по ним лорбук будет срабатывать в чате).
- **Scene Information** — диапазон сообщений и имя профиля.

### 4.4. Consolidation Preview — предпросмотр консолидации
Для каждой сводки — карточка:
- радио **Accept this summary** / **Regenerate consolidation** — принять или перегенерировать;
- **Summary Title**, **Summary Content**, **Keywords** — редактируемые поля;
- раскрывашка **Assigned source memories** — какие исходные воспоминания вошли в сводку;
- счётчики уже принятых и оставшихся записей.

### 4.5. Summary / Consolidation Prompt Manager — менеджеры промптов
Общие элементы:
- **Search presets…** — поиск по пресетам;
- список пресетов (таблица);
- **➕ New Preset / New Consolidation Preset** — создать пресет;
- **📤 Export JSON** — экспорт;
- **📥 Import JSON** — импорт;
- **♻️ Recreate Built-in Prompts** — восстановить встроенные промпты;
- **✅ Apply to Selected Profile** — применить выбранный пресет к активному профилю.
- Подсказка: не меняйте инструкции «respond with JSON» — плагин по ним разбирает ответ ИИ.

## 5. Слэш-команды (для чата/скриптов)

| Команда | Что делает |
|---|---|
| `/creatememory` | Создать память из размеченной сцены |

| `/nextmemory` | Создать память от конца последней памяти до текущего сообщения |

## 6. Отдельные HTML-утилиты (папка `resources/`)

Это **самостоятельные страницы-конвертеры**, не часть основного окна плагина — их можно открыть в браузере отдельно.

### `lorebookconverter.html` — конвертер лорбуков
- **Sample Title Format** — поле образца заголовка; по нему строится regex (показывается в `regexDisplay`). Пусто → шаблон по умолчанию «01 - title».
- **Upload Lorebook File** — загрузка JSON-лорбука (клик или drag-and-drop).
- **Convert File** — помечает записи, чей заголовок подходит под regex, флагом `stmemorybooks: true`, и отдаёт скачать `*_converted.json`.
- Зачем: пометить существующие записи лорбука как «воспоминания STMB», чтобы плагин их распознавал.

### `stmb-toggle.html` — утилита переключения флагов
- **Process** — в загруженном JSON у записей с `stmemorybooks === true` меняет `delayUntilRecursion: false → true` и `preventRecursion: true → false`. Остальные записи не трогает.
- **Download Modified JSON** — скачать изменённый файл.
- Зачем: массово починить настройки рекурсии у записей-воспоминаний.
