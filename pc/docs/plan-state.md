## Что это

Пользовательские **счётчики состояния** (доверие / золото / инвентарь / здоровье / настроение), которые **ИИ ведёт сам по ходу чата**. Число меняется от событий сцены («подрался → доверие −10», «продал меч → золото +50») и тянется из реплики в реплику, показываясь рядом с чатом.

Это **новая способность** РЛМ: ни `Режиссёр` (односторонние события), ни `Душа` (проза-память), ни `Хроника` (архив сцен) дискретные числовые счётчики не ведут. По направлению данных похоже на `Душу` (ИИ пишет обратно), по месту вставки — на `Режиссёра` (маленький блок in-chat у ответа), но связки «дискретное состояние + двусторонний круг» нет ни у кого.

## Референсы (кратко; детальный разбор механизма — в `backend-research.md`)

- **MachineMechanic** — «Полоски-статы» (`statBar.js`): до 4 числовых счётчиков; ИИ дописывает **абсолют** inline-меткой `[[Имя:N|причина]]` в конце ответа; значение **живёт прямо в тексте сообщения**; рисуется HP-полоской в бабле. Считает сама модель.
- **SW** — «SOW Variables» (тег `<state_update>`): типы `int/bool/list/str`; ИИ выдаёт **дельту** `<state_update>{"trust":+5}</state_update>`; арифметику и клампинг делает **код**; значения в **реестре** (`characters.json`); богатая библиотека **пресетов**; в промте — блок `[CURRENT STATE CHARACTERISTICS]` с **пороговыми описаниями** (число переключает поведение).
- **Анти-референс — RPG Companion** (лежит в дереве): тот же смысл, но комбайн (полосы+инвентарь-по-локациям+квесты+кубики+погода+`<lie>`/`<filter>`/CYOA). Это **гранулярность ST**, от которой мы уходим.

## Место в философии

- **Отдельная нода `Состояние`** — по правилу «одна нода = один видимый механизм». Тип механизма другой: двусторонний дискретный счётчик, а не события Режиссёра и не проза Души — впихивать в них нельзя, размоет.
- **Опциональный слой** (правило нод №3 `node-logic`): нет ноды → чистый ST. Как `Душа`/`Режиссёр` — усиление сверх ST.
- **Автосохранение:** значения — контент, сохраняются сами (💾 только для нод/сборок).

## Предложенная раскладка (рекомендация, ещё не «Решено»)

- **Нода `Состояние`** — мини-приложение как `Лорбук`/`Душа`: слева список переменных, справа редактор (имя/тип/min/max/дефолт/иконка/пороговое-описание), глазок на весь экран.
- **Обновление — дельта-тег в стиле SW** (`<state_update>{…}`): математику (сложение, клампинг, типы, инвентарь `+/−`) делает **сервер** → надёжно даже на слабой локалке Termux (модель не считает сама, только сообщает «+5»).
- **Хранение — снапшот значений в `extra` сообщения JSONL**, не оторванный реестр. Синтез двух референсов: **честная математика SW (реестр) + локальность MachineMechanic (значение привязано к реплике/свайпу)** → свайп / ветка / правка **не рассинхронятся** (текущее состояние = снапшот последней видимой реплики). Наш чат уже JSONL с `extra{}`/`swipes[]` — ложится штатно.
- **Инъекция — In-chat плашка «Состояние» @0** (самый конец, ближе к ответу): в промт идут **пороговые описания** (идея SW: «доверие 63 → делится секретами, но не тайнами»), а не голые числа. Поведение по диапазонам живёт в **описании каждого значения** (как пресеты SW «BELOW 30… ABOVE 70»); общий заголовок-инструкция — **редактируемое поле в ноде** с переключателем **Мягкая/Жёсткая** (не зашит в код; правится + сброс). У чисел авто-метки близости к границе (`почти предел`/`ПРЕДЕЛ`/`минимум`). Перевод RU/EN — на имени/описании переменной и на инструкции.
- **Типы — минимум:** число + список-инвентарь + флаг (строку отложить).
- **Причина изменения** — опцией из MachineMechanic (`|причина`: видно, *почему* доверие упало).
- **Пресеты** — библиотека в один клик (RU), как «Загрузить пресет» на референсе и у SW (дёшево — просто данные).
- **UI в чате** — блок (полоска/число + причина) **под каждым ответом ИИ** в ленте (не плавающей панелью поверх чата — перекрывала текст). В самой ноде значения НЕ дублируем (секцию «Текущие значения» убрали — показывала стартовые нули и путала). Блок укрупнён/читаемее; в шапке — кнопка **RU** (перевод всех **причин** изменений EN→RU, тумблер оригинал/перевод, кэш в сообщении).
- **Минимализм:** берём только пользовательские типизированные переменные + пороги + инъекция + HUD. Комбайн RPG Companion не тащим.

Черновой набросок переменной (концепт, не код):

```jsonc
{
  "id": "trust",              // ключ для тега <state_update>
  "name": "Доверие",          // имя в UI
  "type": "int",              // int | list | bool  (str — отложено)
  "min": 0, "max": 100,       // для int: рамки клампинга
  "default": 15,              // старт
  "icon": "shield",           // иконка HUD
  "prompt_template": "[Доверие: {value}/100. Ниже 30 — закрыт; 30–60 — вежлив; выше 70 — делится секретами.]"
}
```

## Открытые развилки (обсуждаем, не торопимся)

1. **Обновление:** дельта-тег (рекомендация) vs абсолют-в-тексте (стиль MachineMechanic).
2. **Схема переменных где живёт:** только в ноде `Состояние` (+ сохранять пресетом) — или ещё цеплять к карточке персонажа (у SW — на персонаже; на референсе есть Импорт/Экспорт карточки).
3. **Пороговые описания** — сразу или потом.
4. **Типы:** минимум (число + список + флаг) — или сразу и строку.
