# RLM — Ошибки и уведомления (пользовательские затыки)

> **Устав документа**
> - **Зачем:** копилка пользовательских «затыков» — ситуаций, где юзер жмёт и получает ошибку/пустоту, и как мы его об этом уведомляем. Основа под будущую отдельную работу по системе ошибок и уведомлений.
> - **Что сюда пишем:** каждый предвидимый затык = {когда возникает → что сейчас показываем и в каком канале → что бы улучшить}. Плюс общий уговор про каналы.
> - **Чего НЕ пишем:** внутренние баги кода (это `bugs.md`), историю (это `changelog.md`), детали реализации функций (это `architecture.md`).
> - **Правило ведения:** дописываем строку, когда находим новый пользовательский затык; помечаем «улучшено», когда сделали нормальное уведомление.

## Каналы уведомлений (СТРОГО — не путать)

Три РАЗНЫХ канала, у каждого своё место и вид. Одно в другое НЕ сваливаем.

1. **ПРОЦЕСС / состояние** — идёт долгая операция. → **лента статуса** над вводом: `chatProc(node,'pulse'|'load'|'fill'|'done'|'idle', текст)`, с цитатой загрузки. Отмена — ✕ на ленте. Сюда НЕ пишем итог (успех/ошибку).
2. **УСПЕХ** — операция удалась. → тот же квадратный тост **СВЕРХУ**, но `'ok'` = **зелёный край** (успех/ошибку различаем ЦВЕТОМ края, а не местом; текст **переносится**, не обрезается). Текст **короткий** (сам контент виден в своём месте: запись в списке, карточка в лорбуке — в тост его НЕ дублируем).
3. **ОШИБКА** — операция не удалась / не для чего. → тот же тост сверху, `'err'` = **красный край**, **внутри чата**. `alertOnce` (модалка) — ТОЛЬКО если тостить некуда (совсем нет ноды «Чат»).

**Источник тоста = заголовок.** `chatToast(node, text, kind, {title, icon})`. По умолчанию — `🗒 ХРОНИКА`. КАЖДАЯ подсистема шлёт **свой** заголовок, чтобы её сообщение не выглядело чужим/ошибочным:
- Режиссёр — `🎬 РЕЖИССЁР` (хелпер `directorToast(node, text, kind)`).
- (Критик, Душа и др. — свои; пока часть шлёт дефолт «ХРОНИКА» — это к будущей унификации.)

**Правила, которые уже нарушали (не повторять):**
- ❌ успех («персонаж добавлен») под красным/чужим заголовком → ✅ `directorToast(..., 'ok')` (зелёный край, «РЕЖИССЁР»).
- ❌ отмена пользователем как ошибка (`'err'`) → ✅ это `'ok'` (нейтральный итог, не красный).
- ❌ длинный сгенерённый текст в тост → ✅ короткий тост, контент — в своём месте.

## Затыки — Режиссёр / генерация (по состоянию 2026-08-22)

| Когда | Сейчас показываем | Канал | Улучшить (бэклог) |
| --- | --- | --- | --- |
| Нет «Лорбук чата» (лорбук со scope = *Чат*) → NPC некуда класть, список пуст | err-тост «нет ноды Лорбук чата»; список «— пока нет —» | ошибка / пусто | подсказка «поставь лорбуку область Чат» или предложить создать |
| Режиссёр не подключён к чату (его выход не идёт в комплитер этого чата) | err-тост «Режиссёр не подключён к чату…» | ошибка | подсветить нужный провод/порт |
| У чата нет ноды API | err-тост «у чата нет ноды API» | ошибка | — |
| В ноде API не вписаны Base URL / модель | err-тост «впиши Base URL и модель в ноду API» | ошибка | — |
| Модель вернула ошибку сети / не-JSON | err-тост «ошибка модели» / «модель вернула не-JSON» | ошибка | показать сырой ответ в консоли (>_), кнопка «повторить» |
| Затишье (event_type = none) при ручной генерации | ok-тост «Затишье — события нет» | успех | — |
| Совсем нет ноды «Чат» в сборке | `alertOnce` «В сборке нет ноды Чат» | модалка (тостить некуда) | — |

## Общий бэклог «ошибки и уведомления» (будущая работа)

- Единый слой уведомлений: типы (процесс/успех/ошибка/предупреждение), единый вид, история.
- «Повторить» на ошибках генерации; показ сырого ответа модели.
- Валидация сборки перед действием (чат/API/модель/лорбук на месте) с точечной подсветкой недостающего.
